# Frontend residency benchmark

This fixture measures a built Web app and its matching Server on one device. It creates three temporary Scopes, twelve Sessions with 1,056 historical messages, including one 550-message history, a turn with 2,001 tool Parts, two child Sessions, Notes, a large Markdown file and two simultaneous synthetic text streams. It never invokes a model provider. Bun 1.4.2 and the repository's installed Playwright Chromium are required.

`run.mjs <repository> <fresh temporary output directory> [panels]` starts one isolated Runtime serving that repository's `apps/web/dist`, exercises thirty warm switches across three Scopes, then streams the fixed workload. It reads both complete streams through their rendered Markdown windows and verifies all 300 ordered chunks. The optional `panels` check exercises real Notes editing, forced WebSocket reconnection while hidden, file reader DOM/scroll continuity, execution records and filter continuity, three rounds of cache churn and forced garbage collection. The runner stops its Runtime before returning. Run baseline and candidate sequentially with the same runner and independent fresh directories.

`compare.mjs <baseline output directory> <candidate output directory> [--timing]` checks an 80% reduction in stable streaming WebSocket bytes, zero warm Part content requests, zero warm timeline reads, zero full-body reads during the contiguous stream and no browser errors. `--timing` additionally enforces P95 at most 200 ms on a fixed device; shared CI uses deterministic protocol and lifecycle tests instead of this hardware-dependent limit. The request/traffic phase counters exclude warm-up and separate navigation from stable generation.

Each run writes `report.json`, screenshots and fixture logs. The panel check adds `panel-report.json`; comparison adds `comparison.json`. Keep those outputs outside the repository because Runtime logs can contain local paths. Reports include only fixture data, normalized request routes, event names/bytes, timing, browser/runtime/device metadata and residency counts. A run directory is never reused. Preserve failed outputs when diagnosing a regression; do not count incomplete fixtures as baseline samples.

The browser follows actual rendered text after each router navigation. It does not infer readiness from completed HTTP requests. This benchmark does not reproduce an existing user's complete database or Electron/native Browser behavior; native attachment ordering is covered separately by the Browser lifecycle suites. See the [frontend sync architecture](../../../../docs/architecture/frontend-data-sync.md) for the production invariants.
