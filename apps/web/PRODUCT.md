# Product

## Register

product

## Users

Synergy Web is used by developers and agent operators who are switching between sessions, scopes, notes, blueprints, and automation state while actively working.

## Product Purpose

The app gives users a calm command surface for running agents, preserving context, turning rough notes into executable plans, and returning to prior work without losing orientation.

## Brand Personality

Quiet, capable, precise. The interface should feel like a focused workbench.

## Anti-references

Avoid nested-card chrome, border-within-border form shells, decorative gradients, unclear icon-only mode switches, mismatched note and blueprint actions, and blueprint lists that look like generic note cards.

## Design Principles

Confirming directory recovery completes the current task’s directory selection and preserves its draft. The next send uses that confirmed binding without another selection step. Background directory changes cannot silently redirect an explicit task selection.

Use one visual source of truth for shared document editing.
Make reciprocal actions visibly reciprocal.
Reserve emphasis for workflow state and current selection.
Let blueprints read as plans with status, activity, and next action, not as passive notes.
When an agent successfully creates a Blueprint through `note_write`, the session should focus the Notes side panel on that Blueprint; replacing an existing Blueprint and ordinary note writes should stay in the message flow without opening the side panel.
When that Blueprint is created or replaced from an active Plan workflow, wait until the current turn is idle, then show a compact one-time composer control to equip the Blueprint in the current session. The control should not auto-start the BlueprintLoop, and dismissing or muting it must not close Plan by itself.
Dragging a Blueprint into the composer stages its title above the editor as “Ready to run”. Dropping replaces an idle Plan or Light Loop before staging, but never creates or starts a run. Removing the pending row is local. A running Plan or Light Loop must stop before replacement; an ordinary running task can retain a staged Blueprint for later submission. Sending from an idle Session starts the staged Blueprint; ordinary notes remain reference attachments.
Starting a Blueprint run should keep the user on the Blueprint detail surface; the run status owns the feedback there, and session output is opened through an explicit session link.
Blueprint run configuration is user-owned: the run menu requires an explicit execution-agent choice before model selection, persists that agent on the Blueprint, and must not expose the choice through model-facing tools. The agent picker has one heading, compact insets and localized built-in descriptions; search and selection remain usable in a narrow panel.
Note and Blueprint detail document surfaces should stay stable while the user reads or edits: metadata refreshes, autosave responses, and BlueprintLoop state changes must not reset scroll position, selection, or the editor instance.
Light Loop and BlueprintLoop occupy the bottom layer of the pending-message stack outside the composer editor. One compact row shows the workflow icon, a short stage and a truncated goal; direct icon buttons edit the Light Loop goal, open the Blueprint or cancel the current loop. Queue guide, edit and delete actions use labeled icon buttons, with a trash icon for deletion. Pending queue actions show progress within the existing icon space without moving the row, Composer or transcript. Tooltips and accessible names preserve meaning at narrow widths. Review feedback and failure details stay behind the information action. Successful completion removes the row without replacing the editor or draft, and remains hidden after reload, reconnect and session switching. Historical result lookups stay silent while loading; active completion lookups and failed reads retain their status feedback. Failed, cancelled and timed-out results remain available in the row. Completion records stay in the conversation; Blueprint Notes retain the latest result and execution-session link.

Sidebar session icons should preserve Blueprint identity while a BlueprintLoop is active: running and auditing Blueprint sessions should remain visually distinct from ordinary running sessions and return to normal session treatment when the loop is terminal. BlueprintLoop no longer owns a `waiting` phase, so a session stopped by its workflow shows the paused state instead of a third loop phase.
Note and Blueprint detail headers should use flat toolbar controls with compact rectangular hit targets; keep workflow metadata as text rows, and use divider-row popovers instead of bordered option cards inside bordered shells.
Keep dense surfaces quiet enough for repeated daily use.
The default workbench uses a neutral canvas, a distinct navigation surface, and raised input and floating surfaces. Necessary secondary text remains readable on every surface, including selected rows. The default Sidebar is 260px wide; explicitly resized widths remain user-owned within the existing 230–420px range. Navigation rows use the shared 14px/20px text role, reserved trailing action space, visible keyboard focus and touch-accessible actions. Newly created expanded projects load their session list automatically. Project loading indicators represent an active request, settle for empty results, and give way to Retry on initial failure.
The session toolbar starts at the workbench's top edge without an extra pane inset on desktop or mobile. Its controls and the side workspace header share one vertical center; conversation content owns its clearance below that row.
Use the shared 120/180/240ms motion roles for feedback, floating surfaces and structural transitions. Ordinary controls respond through color rather than scale or bounce. Menus animate from their anchor, tooltips wait 400ms, and reduced motion removes spatial transitions. A rapid reverse action must settle at the user's final requested state without a lingering portal or focus trap.

Returning to a conversation restores its reading position during the current app run; sending a validated new request returns to latest. Session switching exposes the target shell immediately without an outgoing snapshot. An admitted retained transcript is visible directly; cold history waits locally for its initial reading window and appears at full opacity without an entrance animation. Only one transcript is visible at any frame. Pending questions and permissions remain with their session: switching hides their controls without answering or discarding them, and returning restores the pending decision. Transient menus and dialogs close when their owning view is hidden; hidden file and Note panels do not consume another view's keyboard input or reclaim focus. Reading, destination errors and reduced motion retain their own clear states.

Message-flow counts retain stable text fragments and animate only the changing locale-formatted number over 180 ms. Routine activity labels settle for 120 ms before changing; actionable waiting, stopped and failed states appear immediately. Following content growth uses a 240 ms visual offset over already committed layout. Reading input interrupts that offset without moving the painted paragraph; bounded batch disclosures own their space transition, while the parent process fades naturally sized rows without compressing its paragraphs. If a tool enters during following motion, its height transition preserves the current painted position and the existing following deadline. Initial history, virtual remounts and reduced-motion views remain static. Loading an earlier page within a long turn keeps its already-readable answer mounted; waiting for summary metadata only affects the history control, not the displayed transcript.

Expanded live process groups follow their newest action independently of the outer conversation. Opening a group preserves the outer reading position without disabling that local follow. Reading upward, selecting text or inspecting a row pauses the group's follow until the reader reaches its bottom or presses End. The conversation owns the single floating return-to-latest button; returning there also resumes its active process group. Completed process history retains its local reading position.

The floating return-to-latest button appears when the outer conversation has content below its current viewport or its history window omits the latest messages. It is the only return-to-latest control; the transcript header contains only the available load-earlier action. Pausing follow while reading a process group does not show it on an already bottom-aligned conversation. On desktop it sits 12px above the Composer's right edge, alongside task progress; pending decisions and navigation links remain below it. On mobile it stays above the stacked dock. Activity appearing or disappearing does not move the desktop button away from the input.

Loading earlier history preserves the content and expansion state already being read, including when the page fills an earlier part of the same task. Existing disclosure preferences also apply to newly loaded history; paging does not force it open. Manual expansion keeps adjacent content separate. The reader can scroll into the added process immediately; position preservation must not pull them back.

Computer and project menus show known choices immediately. Connection checks and directory metadata update inside the menu without replacing the Composer setup row, resizing the input or welcome playfield, or losing trigger focus. Directory failures stay local to the affected project and do not prevent project selection. Cold conversation navigation, returning after view eviction, and new task handoff retain the toolbar, Composer and available message content while directory metadata is pending; folder reads never replace the entire conversation with an empty page.
The conversation and Composer share one 50rem outer column with 24px gutters, reduced to 16px in narrow panes. New-task introductions use the whole chat pane: a low-contrast field of drifting pixel motifs extends behind the composer, and a borderless playfield occupies the space above it. A headline, one short sentence and a single game status control replace decorative branding and redundant calls to action. The status control starts, pauses, resumes or retries the current game; Escape explicitly pauses it. Clicking outside, writing and moving keyboard focus leave visible gameplay and ending feedback running. Focus loss releases held keys and captured gestures without firing or dropping a piece. Obscuring dialogs, expanded editing, hidden pages and offscreen artwork suspend the game clock without clearing state. The ambient field keeps drifting independently of game state, input, dialogs, expanded editing and artwork visibility. Hidden pages and reduced motion freeze ambient motion in place; deliberate game actions remain available. Returning focus never needs a click just to resume the simulation. Mouse focus adds no enclosing frame, while keyboard focus is indicated beside the game status and never fills the transparent playfield.

Explicit New actions select one of four independent games: timed stacking, pixel slingshot, falling blocks and aircraft combat. Stacking has contiguous floors, timed landings and continuous height milestones with bounded history; its speed keeps rising with height toward a bounded ceiling instead of plateauing after the first milestone. Aircraft combat has timed firepower, one-hit shields and repair pickups, three enemy routes, and progressive bounded difficulty. Ammunition, a protective bubble and a heart supply box identify pickups by shape; nearby labels and brief received-effect feedback explain their benefit. Active effects use named countdowns. Missed enemies break combos without costing health. Timers advance only while playing; immunity uses a steady outline. Falling blocks start at 420 ms per row and accelerate every five cleared lines. Held movement uses a local repeat clock, grounded pieces allow a bounded adjustment window, and completed rows remain in place during the clear feedback before compaction. Touch dragging moves continuously and cancelled gestures cannot trigger a drop. Captured game gestures stay with their initiating pointer; secondary touches cannot take over or cancel them. Idle stacking already moves; aiming, falling-block placement and aircraft previews respond to the pointer before starting. Original pixel sprites and bounded local simulations use canonical theme tokens, including same-mode theme switches. Slingshot uses an independently loaded rigid-body solver for seeded, three-shot challenges assembled from supported towers, paired bays and bridges. New challenges vary position, span, height and stone ballast; retries keep the same layout. Broken supports wake the remaining bodies so upper structures fall naturally. Pull cancellation never spends ammunition; scoring waits for structures to settle. Only ordinary position/velocity snapshots survive remounts, and controllers are disposed on teardown. No audio, model request or user-file read is involved. Selection excludes the preceding game and stays stable while editing, switching projects, resizing, reconnecting and changing themes. There is no scene selector or timer rotation. Only the selected module loads. The ordinary composer and its project/file entries, plus the single empty extension outlet, remain available during loading or failure. Short windows scroll the welcome content independently. Games never read or replace a draft and create no Session. Existing Session loading never starts an introduction because messages are temporarily absent.
A user preference (`welcomeGames`, Settings → General) can disable the new-task games entirely: the introduction keeps its headline, short sentence and composer entries as a plain greeting in the same position, loads no scene module, and mounts no ambient field or game status control. Scene selection continues underneath so re-enabling resumes the existing rotation.
Game results lock rules and scores immediately, then finish a bounded local ending: aircraft debris and coasting objects fade into a ready silhouette, a missed floor falls away while the tower remains, topped-out blocks settle row by row, and slingshot wins reveal earned stars. Endings pause with the game and never delay retry. Restart and next-challenge transitions blend from the current frame over 240 ms, including interrupted transitions; reduced motion shows static results and switches immediately.
The Composer keeps the same bottom anchor before and after the first send. Its normal body starts at 64px and grows upward to the smaller of 240px and 40% of the available conversation height, then scrolls internally; attachments and context have their own bounded region. Bottom space is 24px on desktop, 16px in desktop windows at most 640px tall, and 12px plus the safe-area inset below 768px width. The input area presents working location, editor and necessary actions. The location strip presents computer, project and the applicable main-folder/Worktree choice only before a Session ID exists. Once a Session ID is accepted, remove the entire strip, including quick actions and scheduled-wake summaries, without a spacer. Task details in the upper toolbar owns actual workspace identity, branch, environment, scheduled activity and Inbox. Its workspace and Inbox remain available when execution statistics fail or are unsupported. Worktree identity has an independent Sidebar badge alongside execution state. Quick actions remain registered but hidden; slash commands remain available. Running, paused, completed, switching and reconnecting Sessions never restore it; creation failure retains setup and the draft. Composer extensions, attachments, permission and error feedback keep their existing surfaces. The subagent avatar strip and expandable Todo/DAG progress sit immediately above the Composer. They share its column, remain independent of task details, and reserve no empty status footer. Permission requests, questions, workflow offers and execution errors remain explicit and reachable in the conversation. Request-card actions share the header's trailing inset at every pane width; they reserve no Composer space for Inbox. Header icons, titles and controls share a vertical center in both expanded and collapsed cards. Observed Dock border-box height, including bottom space, determines conversation clearance; available editor height deducts that same space. Preserve the single editor service, draft revisions, submission lock, IME handling and Dock height observer. Submitted user bubbles enter once over the base motion duration with a six-pixel rise; history, canonical handoff and virtual remounts do not replay that entrance. Streamed text is available immediately, with an opacity-only fade on new suffixes over the slow duration; existing prose stays opaque and stable. Fast tool receipts use the same current-step entry as running tools. Reduced motion settles all arrival effects immediately, and reading earlier messages must not force a return to the bottom.
Model and thinking selectors save one session-owned choice and remain usable during generation. Show saving, failed-save retry and the boundary at which a saved change will apply; keep the current request intact. Offer Default, supported Off and concrete levels through the same menu in Settings and the session toolbar. Default always means the provider default. Settings configures new-session defaults, while switching back to a model restores that session's saved level.
Use one neutral surface system: light mode reads as a near-white canvas with white or transparent rows, hairline borders, and very light hover/selected fills; dark mode reads inward by getting brighter than its shell.
Treat that surface model as a hierarchy invariant, not a per-page decoration choice; if a page drifts blue-gray or slab-heavy, audit the token source first, then the component consumer.
Treat the semantic color palette as one complete theme contract. Every Synergy-owned visible color must resolve through that contract in light and dark mode; alternate themes change seeds or declared semantic overrides without bypassing the token graph. Generated Web/Desktop boot fallbacks, runtime colors, utility mappings, Note Shiki/Mermaid, Chart.js, terminals, editors, and embedded documents stay synchronized from the same selected theme. Common text/background and status foreground/surface pairs meet WCAG AA contrast in every supported theme.
Paginated result sets are identified by their owning resource plus the normalized query. Same-query refresh or retry may preserve visible rows while pending. A different query is a different result set: old rows, pagination cursors, and interaction state must become invalid immediately and must never be combined with the new query.

## Interaction & Visual Principles

Focus never adds or recolors a control border, outline, ring, inset stroke or glow, regardless of theme or input method. Shared controls and native elements suppress browser outlines. Text inputs and their containers keep exactly the same appearance on hover, pointer press and focus; editing is indicated only by the caret. Action controls show keyboard focus with a neutral surface or text treatment; focusable dialogs, scroll viewports, resource containers and Canvas retain their resting background in ordinary and forced-color modes; composite choices apply that cue to their visible control or label. Existing resting borders, error states and selection semantics remain distinct. The same rule applies to Web boot controls, Desktop startup/recovery controls and Synergy-owned controls inside embedded documents. [Focus presentation](../../docs/decisions/implemented/simplification/2026-10-12-focus-without-perimeters.md) records the decision and verification.

User-authored messages support Markdown reading and a source view. Copy, retry and model input preserve the original source. File-reference controls use authoritative source ranges and resource bindings; ordinary paths do not become workspace links. User HTML displays literally and Markdown images require an explicit open action. Code and wide tables scroll locally, while long user messages retain an expand/collapse control.

Message references use a source icon and meaningful text without a resting underline or background. Hover and keyboard focus add a quiet underline; a 400ms intent opens one interactive preview with source, location, relevant excerpt and explicit open/copy actions. Authored labels remain unchanged, while compact bare URLs preserve their full targets for copy and browser semantics. Preview never opens a resource or borrows a website login. Notes and Files use their existing draft owners; unresolved historical Workspaces stay unresolved. Ordinary webpages open a peer Workspace Browser tab on managed-local Desktop; Web and unsupported hosts retain external opening. Selected native failures offer retry and an explicit system-browser action.

Already-rendered message images open the image viewer directly without a hover card or native title tooltip. Image text references show a bounded thumbnail, file references show numbered excerpts, and Notes and webpages show relevant content. Cards use a compact source/name/content/actions hierarchy; internal Asset and Note addresses remain available through Copy without appearing as duplicate body text. Passive previews disappear when useful content is unavailable, including failed thumbnails; an explicit touch information action can retain a compact status and opening action. Keep the card open while the pointer or keyboard focus is inside it. Interaction rules belong in implementation and documentation, not explanatory product copy. See [content previews](../../docs/decisions/implemented/feature/2026-10-18-resource-content-previews.md).

All editor, panel and fullscreen-content expansion controls use the shared pair of two diagonal outward arrows to expand and two diagonal inward arrows to contract, resolved through the [public sizing action tokens](../../docs/plugins/ui-contributions.md#public-components).

Composer sizing uses a thin top grip and a floating corner control, without a size menu or separate header row. Pointer hover near the corner and keyboard focus reveal the control; touch keeps a 44-pixel action visible. The separator supports arrow-key resizing, Home for automatic height, End for maximum manual height and Enter to expand. Its accessible range follows the measured editor chrome. Dragging beyond the manual height limit keeps the editor bounded while the grip and an instruction show continued progress. An additional 32 pixels arms expansion on release; returning to the limit disarms it, and cancellation restores the previous height. Reduced motion retains the instructions without pull transforms.

The composer keeps one editor and draft when expanded for long Markdown instructions. Source editing, revision-checked formatting and preview preserve native editing state. Expanded Enter inserts a line break; Control/Command+Enter submits. A successful server acceptance collapses only an unchanged cleared draft, while failure and subsequent edits preserve it. Preview waits 150 milliseconds between updates and pauses during composition. Wide composers provide a second preview column; narrow composers switch views.

Composer expansion grows upward from its bottom anchor over 340 milliseconds; contraction returns over 240 milliseconds with a controlled ease-out and no bounce or text scaling. Width, preview columns and formatting tools follow the same transition. Reversing the action starts from the currently visible geometry. Keep the live editor, native selection, undo and scroll state intact, and keep Send anchored and reachable. Manual dragging remains immediate. Typing, viewport changes or a new sizing choice settle stale transitions; reduced motion settles immediately, including preference changes during a transition.

Draft attachment cards preserve addition order in one horizontally scrolling row, with no wrapping or expansion toggle; keyboard focus brings offscreen controls into view. Sent user attachment cards fold after two measured rows. Draft images use 96×72-pixel cover previews with the same geometry during upload, failure and completion. The automatic editor minimum is 48 pixels with attachments and 64 pixels without; resizing and expanded editing preserve the user’s choice. Attachments and text share a 16-pixel inset and 8-pixel spacing. Single sent images preserve their aspect ratio within 240×180 pixels; multiple or mixed attachments use 120×96-pixel image tiles. Document cards preserve filename extensions and full identity. One user message owns one timestamp and action row, with 8 pixels between attachments and body, 4 pixels before metadata, and 28 pixels after the whole message. Preparation, optimistic and canonical messages share the same content renderer; preparation captures submission time, ordered assets and the server origin. Keep this view through storage preparation, initial Scope recovery and current-version canonical body hydration; release it on completion, cancellation or a changed target. Parallel uploads preserve the order in which attachments were selected. Uploading and failed counts remain visible. Failed uploads retain a temporary File and their original identity for retry or removal; they block sending until resolved and are not persisted. Removed or invalidated uploads cannot reappear through a late result. Draft attachments open a temporary shared reader and never allocate a persisted workbench resource. Closing, invalidating the draft or changing connections cancels reading and restores focus. Sent user attachments reopen the original session/message/attachment resource, including images, and repeated clicks reuse its tab. Panel opening failures provide feedback and retry; obsolete targets cannot complete a late opening. Thumbnail failures try the original image before retaining an actionable file representation, and reading failures remain retryable. Read-only source content is isolated from workspace file drafts. Office attachment readers load locally on demand and preserve original downloads. DOCX displays primary content, existing pagination, images, tables, headers and footers with page navigation, zoom and search. XLSX preserves worksheet navigation, virtualized cells, merged regions, row and column sizes, cached formatted values, formula inspection, range copying and find. PPTX provides static slide navigation, fitting, zoom and text find across shapes and table cells, including embedded images and common shapes. Formulas, external data, macros and animation are not executed. Preview layout may differ from the original. Compressed input is checked in a disposable Worker against 50 MiB input, 200 MiB actual expansion and 4096 entries; external resources and active content are excluded, and rendered markup stays in an opaque frame. Closing invalidates late work.

Treat the Holos agent as the Synergy account identity. Model subscriptions, API keys, quota windows, and provider logins belong to Providers and Usage, not Account.

User-visible high-risk operations that archive, delete, cancel, overwrite, or uninstall product data must use the shared confirmation dialog. Browser page dialogs, permission review surfaces, and runtime controls with dedicated gesture semantics may keep specialized interfaces when the domain requires it.

Holos agent profile is remote-owned identity data. Synergy may collect the initial name, description, and avatar URL when creating an agent, and may edit those fields from Account settings, but local storage should only retain the agent ID, agent secret, and timestamps. Importing an existing agent must fetch the remote profile instead of asking users to recreate or overwrite it.

Holos create and import agent dialogs should be compact identity forms: title, short prompt, fields, and actions. Do not use decorative icon blocks, alert-style cards, or local storage and verification details for ordinary explanatory text in these flows.

The Holos login callback page should behave as a transient bridge, not a destination page. On success it should confirm the agent connection, notify the opener with a strict target origin, attempt to close itself, and leave a calm fallback with a close action and Synergy return link. Desktop-originated login should open the external Holos page through the desktop shell and return through the `synergy://` app protocol instead of browser popup semantics. Failure states may include a short expandable detail, but must not show a client secret or offer dangerous fallback actions.

Account settings should present the remote Holos profile as identity first and expose identifiers as supporting metadata. Profile fields should not sit permanently on the page as an empty edit form; use an explicit edit state for name, description, and avatar URL. Log out belongs with the identity card because it acts on the current identity. Switching saved agents belongs in a focused chooser, not as a debug-style table inside the Account page. The lower-left account menu should echo the same hierarchy: profile as identity first, then switching agents.

Saved Holos agent lists should display each account's remote profile name, description, and avatar when available, including non-active accounts. Short agent IDs are supporting fallback metadata, not the primary label for agents with a reachable profile.

Optional features are visible only after the current server confirms their public capability. Missing or unconfirmed features leave no navigation, settings search result, workflow control, dedicated resource tab, or historical resource entry point, including on mobile. Direct links return to the ordinary Session surface when absence is confirmed. A reconnect invalidates the previous selection even at the same URL; stop optional requests, autosave and plugin/theme ownership, and discard replies from the previous selection. Preserve local drafts and stored resource references for reinstall without removal notices, reinstall instructions, disabled placeholders or unavailable-feature cards. Ordinary conversation text and sent attachments remain; missing features cannot expose specialized historical tool cards or control metadata as replacement content. Cross-server actions verify the target server's capability.

Ordinary interface copy describes the work and available actions. Page and section descriptions must add information beyond their titles and fields. Keep field consequences, input validation and recovery guidance that affect the next action; omit internal registration, retention and restoration explanations. A rejected task action receives one brief actionable response. Startup failures keep recovery controls visible and put the complete raw diagnostic behind an explicit disclosure, without repeating a diagnostic excerpt above it.

Keep navigation surfaces mentally aligned with where they live. Sidebar destinations such as Agenda, Library, Performance, and Plugins open in the main session-side canvas. Settings may be modal, and it should dim the whole app because it interrupts the current task.
Session chrome keeps model and thinking effort in the top bar. Before a Session ID exists, computer, project and the main-folder/Worktree choice belong to the location strip above the Composer, sharing one sans typeface, regular weight, size, line height and supporting text color; a selector's nested label must not reintroduce stronger typography. The model uses `base`/`semibold`, while thinking uses `small`/`medium` and displays only its current value. Tooltip and accessible names retain the thinking control's purpose.
Channel accounts are Sidebar navigation owners, not parallel workspaces. Account rows should present one compact status badge for disabled, waiting, disconnected, syncing, connected, failed-sync, or degraded state and expose keyboard-accessible **Refresh Projects** and **Download Diagnostics** actions only when the provider capability supports them. Managed Project rows distinguish active, paused, stale, and archived remote state. Remote-archived Projects remain visible until the user uses the normal local archive workflow, while active or remotely paused managed Projects clearly explain why local archive is unavailable.

Settings should be a human-facing preference surface, not a raw config editor. Keep common settings in a left-aligned readable measure, use switches for binary choices, guided scales for ordered multi-step values, and direct option controls for unordered choices. Do not expose inline restore-to-default options for ordinary preference controls; defaults should be reachable through the same control when needed. Reserve raw domain-file syntax for import/export or advanced configuration views. Default primary agent model should live in Models, not General.
Settings select fields keep their value at the leading edge and their chevron at the trailing edge, including full-width fields. Resting triggers use a borderless inset fill; keyboard focus retains a visible ring. Menus use a raised surface with a quiet boundary and shadow, a trailing check for selection, and a light fill for pointer or keyboard focus rather than a persistent selected-row fill. Configuration-file disclosures use one inset detail surface with readable monospace paths, natural wrapping and separately reachable copy/open actions. Interactive and non-interactive permission choices share the same profile names.
