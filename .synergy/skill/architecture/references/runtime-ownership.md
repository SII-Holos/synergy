# Runtime ownership

For a standalone service that must not execute Agents, verify the startup lifecycle itself rather than disabling routes. Use explicit context and storage ownership without starting Session recovery or model discovery; register its owning migrations through the central runner. Exercise independent Homes, failed-open cleanup, restart identity, real HTTP and absence of outbound requests. See [organization service](../../../../docs/architecture/organization.md).

Drain storage telemetry and its timers before disposing a standalone service context, including startup failures. Verify a closed service remains quiet beyond the aggregate flush interval; short startup/shutdown tests can finish before a leaked producer fires.

For Homes owned by an optional domain, retain ownership independently of component availability. Test absent and mismatched owner selection, unsupported metadata, same-identity restart and unchanged legacy personal data before execution storage opens. Initial provisioning and versioned adoption belong to the owning domain; a normal startup must not relabel personal data. See `HomeOwnership` in [Runtime and Scope](../../../../docs/architecture/runtime-and-scope.md).

When a native Node host provisions a Home before launching Bun, exercise the public metadata entry in a real Node child and typecheck its consumer under Node module resolution without Bun ambient types. Reuse the context-free Harness ownership file entry; keep bounded reads, atomic writes and positive test-home detection identical, including rejection before creating a provisioning lock. Provision ownership before the installed launcher creates module state. Do not infer that portable metadata also makes Agent execution portable.

When adding dependencies to Scope or Workspace binding modules, trace back through session and rollout schemas. Load execution-only orchestration inside the owning asynchronous operation when eager loading would create a schema cycle. Verify affected public entries in separate processes; a product bootstrap can hide import-order failures.

Trace each mutable registry, cache, environment read, callback, child process and timer to its owning Runtime before changing lifecycle code. Imports define capabilities; composition registers them before opening. Native listeners must capture the owner explicitly. Trace all AsyncLocalStorage-based domain contexts too: experiment overrides, per-session migration targets, rollout identities, transport sinks and tool execution callbacks must reject inherited values after a Runtime switch and disappear inside RuntimeContext.exit. A scoped context from another Runtime cannot supply a workspace, credentials or storage. Test interleaved instances and closing one while the other continues, plus failed startup and resource drainage. Scope identity and nullable local metadata are distinct from a session’s explicit nullable workspace; see [Runtime and Scope](../../../../docs/architecture/runtime-and-scope.md).

Attach resident outbound connections to component services. Verify local readiness while the remote handshake is blocked, automatic recovery of transient loss, terminal replacement/revocation, and shutdown while checkpoint admission is held by another owner. Keep one-shot imports and discovery inert; a successful transport handshake never substitutes for command authorization.

Separate bounded business callbacks from heartbeat and frame validation. Reserve bounded capacity for receipt queries and skip reconciliation while controls drain; saturation must refuse before receiver admission without retiring a healthy connection. Track every callback through shutdown and reject duplicate active exchange identities. Test a held command beyond the negotiated offline interval, independent queries, count/byte saturation, slot reuse, and close before callback release. Durable admission, not callback completion order, owns command sequencing.
