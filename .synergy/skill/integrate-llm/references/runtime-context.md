# Runtime context and request stability

Keep hosting Runtime identity in the fixed `synergy-runtime` advisory slot, ahead of recall/environment, with frozen policy (tool intent, attachment guidance) in the cached system prefix instead of the advisory tail. Do not insert it into the stable system prefix or derive it from the Session Workspace. Capture launch provenance once and use the actual Runtime listener. Verify unchanged system messages, Codex's full previous-request prefix, no duplicate unchanged identity, and a fresh observation after restart; deterministic request equality proves layout stability, not provider-reported cache hits.

Key loop-stable context collection to the current task root's first model preparation, including an empty result; numerical steps also count pre-model jobs. Reuse context across root and child continuations, replace it for a new Inbox root, and preserve collection cancellation and loop-exit eviction. Distinguish explicitly absent contributions from unavailable collection. Keep persisted advisory observations out of contributor input history; verify memory and visual-state queries still select the real user input during continuations and resumed preparation. Verify that Library experience extraction retains the complete assistant trajectory across hidden observations without treating them as user intent or new turn boundaries. For durable advisory events, reserve message order before the associated assistant, retain the original permission role, commit after prompt admission, and compare source revisions through retry, reopen, fork and compaction. Verify actual SDK inputs through tool continuations, compaction before and after the first request, empty contributions and cancellation during collection; count commitment separately from model requests. Cache experiments preserve source text and measure uncached input alongside the provider-reported weighted hit rate; identical text alone does not establish a cache hit.

For durable context changes, separate knowledge content versions, applicable selection, confirmed state and occurrence events before choosing a revision. Deduplicate knowledge only against verified definitions in the effective model projection; test deselection/reselection, content rollback, partial projection changes and compaction. Keep pending cache refresh internal and distinguish failed observation from confirmed empty state. Exercise exact request-prefix preservation through real continuations, plus provider-reported cache reads and uncached input in authorized live evaluation; do not infer savings from character counts or cache-hit percentage alone. Preserve existing historical text when introducing finer source granularity.

For live session model controls, capture model and thinking together before prompt budgeting and tool preparation. Carry that snapshot through serialization and request accounting; do not read mutable UI or session choices midway through preparation. Verify actual next-request wire parameters with a delayed local provider fixture, per-model restoration, restricted tool-turn changes and no tool replay. Apply explicit thinking normalization after ordinary parameter hooks and preserve unrelated options.

Keep the runtime-context protocol once in the stable system instructions of every request whose layout emits `<context-source>` observations, before budgeting and worker transfer; a raw-text `<runtime-context>` envelope gets no protocol, since its state vocabulary would describe absent markup. New observations state facts and retain source/version metadata; never rewrite historical text to adopt a new presentation. Sort final model tool definitions and discovery catalogs after authorization and source overrides, before bounded presentation; do not sort execution sequences, schema arrays or ranked search results. Built-in MCP description overrides belong to MCP, require builtin ownership, endpoint and a reviewed full-definition fingerprint, and fall back to raw remote prose on contract changes. Keep schemas and raw remote definitions intact.

Verify permuted source arrival, access changes, group expansion, pending/unavailable/cleared states, knowledge deselection/reselection, source hashes, retry/reopen/fork, compaction and provider switches. Measure actual input/cache usage separately from character counts.

Keep old-tool pruning inside the existing prompt-pressure decision, not a per-step background maintenance job. Protect canonical task roots rather than counting transport-role user messages; Cortex completions and steer inputs remain part of their owning task. Isolate mutable message containers before hooks while sharing immutable output strings; test both replacement and in-place nested transforms against canonical storage. After pruning, preserve the canonical evidence and ephemeral transforms, rebuild the current provider-bound plan and remeasure without an older usage baseline. Verify no-pressure continuations retain their exact prefix, pruning disabled and summaries disabled remain independent, insufficient pruning and single long tasks still reach existing compaction, and cancellation prevents later model dispatch. A changed prompt must establish its own provider usage before calibration resumes. Keep calibration in `PromptBudgeter`: compare the fully prepared envelope and exact message prefix, including active tools and the agent preamble, and measure any delta with the same opaque-aware meter. Do not recover a baseline from historical usage alone.

## Preserve Native Local Compaction

Follow [LLM loop and compaction](../../../../docs/architecture/llm-loop.md#compaction) for the canonical request and lifecycle invariants. When changing native compaction:

Measure admission against the complete prepared request, including agent instructions, contributions, user system overrides, final transformations and active model schemas. Keep soft pressure separate from a hard response-space failure. Test a root-only request above soft but below hard, a truly overflowing fixed input, and an explicit empty-history compaction. A no-op must settle pending work without a summary boundary or a repeated continuation. Use real system assembly with a deterministic meter or local provider; a fixed mocked budget result cannot detect instructions omitted before preparation. Verify prepared reuse does not duplicate instructions or hooks.

1. Defer pending compaction until normal `SessionInvoke` preparation resolves context, tool availability, projected history and the complete prepared request. Pass that snapshot to the summary owner without rerunning preparation. Only callers without prepared data require the owner to call `AgentTurn.prepare()` for final hooks, provider data and materialized attachments; do not send a preliminary conversation call on cold manual or automatic budget paths.
2. Capture the original agent, model, user settings including variant/thinking, model selection, final prepared data, ordered native tool definitions, active IDs, system cache breakpoint, late-system context, and materialized history. Do not reconstruct this request with a dedicated model or rerun final preparation for the summary.
3. Append summary instructions through `promptSuffix` after the complete `LLM.promptMessages()` layout, including late-user runtime context. Keep schemas in `tools`, set `toolChoice: "none"`, and supply no execution callbacks. Reject both incremental tool starts and final-only calls in the processor before deferred expansion, permission checks, or scheduling.
4. For provider overflow, copy the request arrays before processor cleanup and summarize the captured request directly. Release snapshots on successful or non-context model-stream settlement before tool authorization and execution. Rebind cancellation to the session abort signal rather than the completed turn signal. Carry canonical message sources alongside the prepared message array. Budget the complete envelope with the shared `PromptBudgeter`, summarize an atomic prefix, and retain its untouched suffix. On summary context overflow halve the prefix without rerunning preparation. Commit explicit coverage only after complete output reduces the resulting context and source validation succeeds; an irreducible range must not create a mechanical boundary. Test coverage conservation rather than estimator precision, including opaque reasoning whose encoded length changes.
5. Keep assistant failure settlement with the compaction owner after handoff. Use a fresh native invoke deadline combined with session cancellation; do not inherit a disposed ordinary turn signal. Check storage finalization transactionally rather than racing it, preserve an already-committed summary on optional remote failure, and restore late processor terminal fields without losing usage. Verify shrinking overflow attempts and one committed boundary per request, `running`/`failed`/`empty`/`committed` states, commit-only boundaries, continuation, and `usageRole: "compaction"`. Cover prepared hooks/provider options, original settings, schemas/order, suffix layouts, cold and overflow paths, hook failures, cancellation, timeout/late completion, disabled deadline, and rogue tool attempts without effects.
6. Keep the registered dedicated `compaction` agent for external adapters that cannot expose native prompt snapshots. Keep optional Codex remote compaction default off and bind its artifacts to the same selected coverage. Cancel and drain obsolete candidates; preserve the root and untouched tail during replay, including an assistant item immediately after the summary. Verify cold reads, cache eviction, runtime restart, fork, rollback, migration and import against the same coverage, and keep canonical loop chronology separate from provider prompt order. Assert prompt continuity, not provider cache hits or performance savings; those require independent provider evidence. For live replay acceptance, inspect the recorded transport request for the opaque artifact and exactly one copy of the root and uncovered tail; a saved artifact and successful response alone do not prove replay occurred.
