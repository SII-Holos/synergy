## Replaceable plugin presentation

Read [frontend plugin ownership](../../../../docs/architecture/frontend-plugin-platform.md) before changing Shell, conversation, composer, resource or overlay composition. Keep domain owners above replaceable presentation and test their public services with native and external views. Capture draft identity before asynchronous work and restore only at an unchanged owning revision. Dispose DOM references, pending UI work and portals by surface identity; accepted server work keeps its domain lifetime.

For UI API changes, build the production App and run bun run plugin-ui:test. Its public preview helper installs extracted archives into an isolated real host. Also run the owning App/UI tests, private HTTP smoke, typecheck, localization and package gates. Browser fixtures must pre-discover their actual module entry so dependency optimization cannot reload the page during interaction assertions. Verify styles on ordinary inherited text and protected portals, not only elements that explicitly restate font variables.

Keep question and permission ownership below SDK/Sync and above replaceable Session pages. Read [request interaction state](../../../../docs/architecture/frontend-data-sync.md#request-interaction-state) before changing submission or draft cleanup. Verify refresh, server/Scope isolation, explicit terminal events, failed reads, stale generations and uncertain-result checks through the real Persist path. Native presentation registers an inline outlet; a missing outlet must retain an accessible host surface. Route DataProvider permission replies through the same coordinator and test a cached permission identity during a temporary empty-index interval. Capture the client before awaiting, and never persist submission locks or infer terminal state from empty loading buckets.

For task progress, distinguish execution completion from task counts and test initial hydration, failures, waiting, paused work, disconnect and activity during the ending timer. Exercise fixed summary dimensions, complete read-only task-list text, current-view counts, cancellation semantics and retained DAG instance identity. Hidden views must be inert and freeze graph updates while preserving manual pan/zoom. Use node ID rather than fresh layout-object identity to retain native controls and focus anchors. Verify nested Escape before opening autofocus and after closing autofocus, drag versus click and the selection-only graph consumer. Exercise the real short-window dock with requests present: floating content must stay inside viewport bounds and hit-test above the Composer. Wait for both conditions together within a bounded deadline when floating positioning is asynchronous. Use shared floating positioning as the single anchor-width source. Run relevant App/UI suites through SYNERGY_TEST_FILES, then static checks and production build sequentially; include private HTTP smoke and native/custom Session composition.

Verify pending-list route ownership in the current server before treating a snapshot as global. Scope-local request reads replace only their own index slice; keep source-Scope metadata and sequencing trackers with the existing global carrier. Snapshot-confirmation and read-revision signals must also be Scope-specific, so loading Home or another project cannot clean a pending draft or erase terminal-event evidence from another runtime epoch. Exercise initial connection and reconnect with an already pending request and an empty replay journal: clearing an index requires a confirming pending snapshot before recovery completes. Verify inline outlet sizing with the Composer present; a shrinking parent must propagate its height constraint through portal wrappers to keep request actions clear of the editor.

For navigation performance, test leaving the last Scope view for a global panel and returning, not only overlapping Session views. Retain recently viewed stores within the bounded inactive LRU, isolate panel data suspension below navigation controls, and verify canonical handoff convergence after a displayed timeout. A deadline sample must not replace the eventual completed navigation duration.

When a mutation replaces a collection (such as session tags), serialize pending edits and use the accepted response as the next edit baseline. Do not wait for an asynchronous event to update that baseline. Preserve failed input, expose retryable errors, and test a second edit before the first event arrives. Query filters must reach canonical pagination; filtering only the loaded navigation window cannot represent all matching history.

When changing file consumers, capture Workspace ID and binding generation before asynchronous work. Exercise the same relative filename in two Workspaces, switch while one read is pending, deliver stale-generation watcher events, and reopen a tab after a binding change. Preview URLs and editor models must retain the same owner as the file request.

For editable file consumers, capture the complete-read content version when editing starts. Keep that baseline independent from watcher refresh, and preserve drafts through model remounts. Test a remote write during editing and new local input during a pending save; only the submitted revision may become clean.

Workspace selection changes require catalog snapshot/event race coverage: deliver rebinding before an older bootstrap or Session response, retain the new Session generation without changing activity, and keep pinned file tabs on their captured generation. Conditional sharing/rebinding forms retain the revision observed when editing starts; incoming events must not silently authorize overwriting concurrent changes.

For filesystem actions, capture the Workspace, binding generation and observed entry version when opening the form. Retain input on conflicts and keep dirty source and destination drafts independent across rename events. Native create/delete notifications alone cannot prove a rename; verify the editor behavior against unrelated sibling changes.

For file-draft changes, verify reload as well as component remount, original content-version conflicts, Workspace generation separation, missing source files and local-storage quota failure. Preserve in-memory edits when durable backup fails and expose the recovery state in the existing editor.

Bottom session activity must remain independent of Task details and Workbench capability. Mount running/queued Cortex avatars and the retained 待办/DAG summary through the Composer priority outlet. Anchor expanded progress above the entire activity group, preserve workflow-offer priority, and verify real Question/Permission cards together with editor resizing. Reserve measured activity and request action height before permitting upward Composer growth, including wrapped permission actions. Full editor expansion hides retained bottom controls and inline requests, aborts holds and freezes progress; verify that Send remains reachable and collapse restores requests, drafts and graph identity. Exercise short activation versus a two-second hold, gesture interruption, authoritative completion and removal of a focused avatar without stealing another control's focus, cancellation failure/retry, child waits, unknown/reconnecting status, focus return and narrow/short viewports. Hidden retained graphs must stay inert and frozen without resetting manual viewport choices. When the anchor leaves too little reading space, use the shared modal focus boundary while retaining the graph; activate that boundary only while expanded so collapsed content cannot suspend other dialogs. Verify initial visible focus, nested Escape and focus return without losing pending requests or drafts.

For mobile drawers, use the shared modal stack instead of a document-wide keyboard listener. Test nested Settings and Escape, returning focus to each opener, releasing background isolation when the viewport widens, and keeping fixed actions reachable when collection content scrolls. A working-location summary must read the canonical session binding or explicit new-session choice; include null, missing binding, rebinding and pending creation cases rather than substituting the project directory.

For collection motion, compare ordered stable IDs before scheduling animation. Capture current rendered positions before keyed children update and measure the committed layout relative to the list container; cached viewport coordinates confuse scrolling with reordering and retain obsolete disclosure heights. Coalesce updates within a frame, preserve visible interruption positions, cancel only owned animations and dispose frame/media listeners. Verify normal motion after scrolling, delayed loads, same-ID refreshes, rapid disclosure reversal and live reduced-motion changes in the real collection fixture; reduced-motion-only tests cannot detect this class of jump.

For collection navigation changes, verify every existing category against its own projection and preserve nested ownership and pagination. Check actual category controls and list bounds at the minimum sidebar width in both supported locales; full-width controls plus outer margins must not exceed their container. Keep intentional resize hit areas separate from content-overflow assertions, and verify fixed controls while the collection scrolls. For independent disclosures, verify simultaneous expansion, preserved nested state and keyboard exclusion while hidden. Exercise keyboard activation with the real session typing-autofocus handler mounted; it must not redirect a focused control’s Space or typeahead keys into the Composer.

For Environment selection, test zero allocation when browsing profiles, conditional Session updates, stable creation request IDs after a lost reply, and draft restoration after startup failure. Activity recovery must address the original operation; never submit its command again.

For interactive introductions, verify explicit New separately from same-route rendering, project selection and reconnect. Pin scenes and seeds only in test fixtures. Keep the local demonstration state independent from the draft and protect focused scene controls from Composer typing autofocus. Gate the game with its interaction and visibility state; gate the ambient field independently with document visibility and reduced motion. Compare actual Canvas frames after game pause, input, modal presentation, expanded editing and offscreen artwork: the game freezes while the background keeps drifting. Verify hidden tabs and reduced motion freeze the ambient field in place, restoring motion does not resume a manually paused game, and unmount releases both clocks.

For Canvas caching changes, compare occupied pixels, alpha and composited color against the original drawing path with real browser `deviceScaleFactor` values, including fractional scales and both themes. CSS zoom is not device-scale evidence. Restrict cache reuse to raster grids where it preserves coverage; count offscreen preparation as well as destination drawing, and verify theme invalidation, resize and disposal without changing motion cadence.

To add an introduction, create a directory under `components/session/welcome`, export its component through one lazy `registry.ts` entry with a stable ID and explicit localized descriptor, and keep its pure state model independently testable. The container must not switch on scene IDs. Use `memory.read` / `memory.write` for plain local snapshots; do not retain Solid owners, DOM nodes, Workers or timers there. Mark the artwork with `data-welcome-visual` so visibility excludes its surrounding actions. Gate recurring work with `active`, honor `reducedMotion`, reject old generations and dispose resources. Pin scene and seed in test fixtures, never a product selector. Verify the new module through the shared host, keyboard/touch paths and independent draft ownership; run assignment tests with an extra registry entry. Game objects use canonical ordinal visualization tokens; imperative drawing resolves them reactively. Verify actual success and failure routes, bounded simulation state, and consistency between trajectory previews and play. For generated physics challenges, derive layout from the experience seed and challenge index, preserve it on retry, and test initial stability plus reproducible solutions across seeds and progression. Deleting a support must wake dependent sleeping bodies before settlement is evaluated. Advance simulations with the shared bounded 120 Hz accumulator and publish once per render frame; do not discard fractional time or accumulate paused wall-clock time. Keep physics engines inside their scene controller, serialize only plain body state, and dispose collision listeners and engine worlds on teardown. Keep pointer cancellation, keyboard actions and a discoverable pause/resume action available. A captured game gesture belongs to its initiating pointer: ignore secondary contact and scope release/cancel events by pointer ID. Verify with a two-touch browser regression. Pixel Canvas rendering uses a logical-resolution buffer with nearest-neighbor scaling; redraw on canonical theme-token changes, including same-mode switches. The background belongs to the chat pane and cannot intercept input or extend into the sidebar. Use the single game status control and contextual keyboard feedback instead of a permanent toolbar or an enclosing mouse-focus frame. Test idle pointer feedback and actual input/click-outside pausing separately from initial editor autofocus. Remove retired modules, tests and catalog entries together when changing the registered experiences.

For game endings, lock the outcome before advancing a bounded presentation clock; visual completion must never delay retry or continue scoring. Advance ending and replay feedback through the existing active clock, preserve only plain terminal age in experience memory, and release local transition snapshots on completion or theme change. Capture the currently displayed frame when interrupting a replay, ignore held restart keys, and test immediate retry, input-driven pause, remount and reduced motion separately from gameplay.

## Complete workbench acceptance

Verify the complete built workbench from global and project new tasks through first send and an existing conversation. Follow [the product rules](../../../../apps/web/PRODUCT.md) for welcome presentation, working location and status. Keep their real controllers and status/detail components mounted in acceptance; a layout fixture with empty or substitute status is only a focused layout check. Verify that playing, pausing, retrying and remounting a welcome scene never change draft text, attachments or working location; follow any remaining revision-based editor actions through their actual owner. Select a valid fixture start mode and wait for the streamed reply and idle state; a new session URL alone does not prove successful submission. Exercise project and file entry buttons through their real dialogs and chooser.

For native chrome, inspect actual macOS traffic lights, dragging, minimize, fullscreen and exit, including collapsed sidebar and narrow split panes. Keep host control protection outside replaceable Shells and test a non-built-in Shell reserve. Measure button and icon bounds across default, hover, focus and opened menus within 1 CSS px. Capture both themes and real menus, checking popup collision, Escape/focus return, 375px width, short windows and 200% zoom. Under reduced motion, inspect computed styles while the menu carries its open state: the media rule must override the state selector's specificity. Overall visible coherence is an acceptance requirement alongside automated results.

For built-in navigation changes, verify the registered Shell in the production page, not only a manually constructed DefaultShell fixture. Registries may copy entries, so object equality cannot identify a built-in entry. Test full collapse, zero actual occupancy, retained width/scroll/disclosures, inert descendants and focused-control recovery on session and non-session routes. An ancestor’s `visibility: hidden` alone is insufficient when a disclosure explicitly restores visibility: inspect the rendered closed page. Keep restore/Search/New in the top row and preserve the mobile drawer and third-party Shell contract.

Configuration density is role-based: only the primary model selector retains its chevron; toolbar thinking uses its optional presentation while form controls remain unchanged. Verify real Agent, permission and working-location menus after removing the entire arrow wrapper. Add comes first as a circular control, and existing section metadata must produce real groups with one keyboard-navigation owner. Exercise model search with no, few and many results, long names, bounded scrolling and footer reachability.

Give closed-session entry and open-resource controls one visible owner each. Keep creation/menu/overflow controls outside the tab scroller. Test the composed Shell, Session, Sidebar and Composer: fullscreen must hide and inert conversation/navigation chrome, preserve unsent drafts, and restore preferred dimensions; sample transition bounds and actual hit targets while reversing actions. An empty resource slot converts in place and delayed actions validate its captured identity. For working-location typography, compare computed styles on the nested visible labels across new and existing sessions. Model selection markers need their own reserved trailing column; test badge alignment and long-name truncation before and after selecting a different row. Keyed lists compare selection by the supplied key rather than object identity; rebuilt catalog or search results must retain the selection marker.

Native titlebar acceptance must include OS-level coordinate clicks on restore, Search, New and the workspace toggle, plus a window drag from the empty header. Renderer-injected clicks and accessibility activation can bypass native drag hit testing. Check actual drag rectangles against controls in sibling or portaled subtrees; `no-drag` on a button alone does not prove that an overlapping drag owner releases it. Repeat after sidebar collapse and with the side workspace open. See the [escaped native hit-test failure](../../../../docs/postmortem/0035-native-titlebar-swallowed-controls.md).

For project-folder recovery, retain structured binding failures instead of treating unavailable folders as non-Git. Verify confirmed main/shared recovery, partial success, uncertain mutation replies, revision conflicts and navigation cancellation through the generated SDK. Preserve explicit draft intent separately from refreshed binding generations and retain trigger/editor nodes; selection creates no Worktree until sending. Keep setup Tooltips inactive without removing accessible names or shared wrapper geometry. Check path-edit hit targets and keyboard focus beside long breadcrumbs in both themes at narrow widths; avoid extra borders or persistent hover fills.

For project-entry changes, test the real Prompt provider and project picker together: destination-first merging, both revision checks, cancel, upload blocking, same-connection ownership and file-reference provenance. Verify independent section saves and unsaved dismissal in project settings. Inspect real computer/project/main-folder and Worktree controls at narrow and short viewports, 200% zoom, both themes and keyboard focus return. Folder selection must retain the underlying dialog state and distinguish the connected service from Desktop's machine.

Use the shared Dialog footer for actions that must remain reachable while project forms or directory results scroll. Cover short windows and keyboard focus return. During directory loading, edit the path before the response arrives and verify that the response preserves the newer input.

For Composer setup density, use its named container width rather than viewport breakpoints. Verify long computer/project names in a narrow pane inside a wide window, 320/375px windows, 200% zoom, main and deferred/existing Worktrees, and simultaneous repair/custom-location actions with touch targets. Compact labels must retain full identity, paths and pending state through Tooltips and accessibility.

For initialization-only Composer controls, gate presentation on the route Session ID rather than activity, message count or snapshot availability. Verify failed creation, accepted identity, running/paused/completed states, switching and reconnects while preserving the editor, extensions, attachments and decision/error surfaces.

For service folder navigation, verify separated breadcrumbs, explicit path editing, successful-submit focus return, failed-path retention and Escape cancelling the edit before the picker. Shrink an already-open picker and verify that its current folder stays visible while ancestors remain reachable. Multi-selection must survive browsing into another directory and return exact paths while preserving the originating project form.

When asynchronous picking disables its opener before mounting a nested dialog, capture the focus target before disabling and retain the same control through the first selection. Restore focus after the pending state clears only if the originating dialog is still active. Test the real picker flow with the opener disabled, both confirmation and cancellation, instead of only mounting the nested dialog synchronously.

Project creation must remain a real two-field flow with a small computer selector. Verify per-connection directory staging, default-main creation, existing-project detection without renaming, failure retention and Composer focus after the modal closes. At least two actual repositories must participate in multi-folder acceptance: create from A with B shared, change main to B, and verify old tasks and A Worktrees still open, search, modify and clean up through their original bindings. Compare primary and additional roots in file tree, context picker, search and command tools rather than accepting a visual folder list as proof of access. New Worktree selection must allocate nothing until send. Exercise historical Worktrees with a non-Git or unavailable current main.

Inspect the shared controls in the real project Popover, create form, settings and service directory browser. Required sizes and timing live in PRODUCT.md. Check single-border input focus, separate menu/dialog shadows, fixed trailing checks, stable loading widths, nested Escape and focus restoration. Capture complete screens in both themes, narrow/short viewports, 200% zoom and reduced motion; isolated component snapshots cannot establish the combined page's density.

For Browser results, use the existing draft capture/retention API before asynchronous upload and reject a changed conversation. Screenshots and feedback remain editable until the person sends. Use Dialog size presets rather than competing max-width utilities; verify the footer and body scroll in a small Desktop window. Native overlay covers are bounded still images only, scoped to the selected page and cleared when native content resumes.

Build shared UI DOM fixtures in a separate process with the test environment. Vite can set `NODE_ENV=production` in its caller; do not propagate that mutation to test batches, whose Lingui fixtures require runtime message compilation.

## Large-history verification

Trace the native transcript owner separately from the route, Composer and workbench owners. Switch server, Scope and Session while retaining pending reads and virtual exit rows, then verify the predecessor cannot write into or release the successor. Reconnect must preserve accepted DOM and reading anchors while refreshing every already loaded Part interval; include more than 100 Parts, disjoint target intervals, deleted interval endpoints and live changes during refresh. Do not treat a missing page as a substitute for stale accepted data.

Capture virtual layout at ref release before the handle disappears. Cache only bounded plain measurements keyed by immutable resource and presentation identity; reject a changed width or row sequence. Verify the first layout on revisit, active following after same-version body growth and detached reading after native wheel or keyboard input. A script-assigned scroll offset alone does not establish reading intent. Test large streaming-to-terminal Markdown through paint frames and keep selection and paragraph position assertions.

For a demonstrated heap retention defect, churn more Scopes than the warm-cache limit, force collection in the browser test and count uniquely identified store payloads still reachable. Preserve the shortest retained reference path privately, assert the documented resident allowance and verify provider disposal releases all payloads. Record heap size, DOM and listener counts as supporting observations. Every store-owning cache callback must leave with its Scope even when its byte budget has spare capacity.

Measure response completion using the browser's [Resource Timing](https://www.w3.org/TR/resource-timing/#dom-performanceresourcetiming-responseend) timestamp and capture the ready paint timestamp before serializing or saving benchmark output. Keep Node coordination, screenshot and evidence I/O outside that interval. Check both count and byte budgets; smaller history prepend batches can bound reconciliation independently of the API maximum. Traverse the entire history after changing a batch size, including window-cap crossings and return to latest.

Attribute server query counts alongside browser latency. Trace request context and adjacent recovery owners: resolving an existing Workspace must not acquire the writer, and display reads should reuse their resolved Session within the request rather than repeat migration and binding hydration. Verify a held-writer lookup and the current rollback, deletion and content-version contracts; persisted status batches must preserve live precedence without hydrating each Session again. Keep this reuse inside the request unless a separately tested invalidation contract owns longer-lived state.

Test presentation summaries and canonical bodies independently. Cover a single turn with thousands of Parts and more messages than the entire window cap, a giant Markdown paragraph, list item and table cell, dynamic height, prepend anchoring, focused controls, selected text, full copy and search location. Traverse past the cap and verify the conversation remains readable. Read count bounds alone do not establish DOM or byte bounds. Verify subscription cancellation with two consumers, deletion during a body request, stale subscription generations and checkpoint recovery after hidden-page return or reconnect. Invalidate hydrated bodies while their first summary page is still pending, finish that page, and verify mounted rows renew invalidated leases without requiring a version change. Check bodies several seconds after navigation and recovery rather than only at their first paint. Delay the first Part announcement across subscription renewal, then deliver an obsolete checkpoint after a current summary or body; verify discovery survives, accepted content never regresses, and queue coalescing cannot discard the current update. Use one immutable data snapshot, a production Web build and matching viewport for performance comparisons; retain sample counts and distinguish application admission, resource preparation, model wait and paint latency.

For file-entry performance, measure the first Workspace access separately from hot directory-cache reads. Hold Scope recovery in a real Runtime fixture and verify that browsing initializes its Workspace resources and returns while recovery is pending; mutations must retain their recovery barrier. Scope recovery moved off the response path must remain owned, drained and isolated at background storage priority.
