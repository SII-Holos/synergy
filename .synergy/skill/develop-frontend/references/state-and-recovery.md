## Settings recovery

When a setting changes the configuration contract, regenerate the shipped core and full config schemas with `generateSchema()` from `script/release/shared/build-runtime.ts` and run `bun test --config /dev/null test/script/release/runtime-schema.test.ts`. SDK/OpenAPI and configuration-reference generation do not update those artifacts.

After saving a shared display preference, verify both global consumers such as Kanban and Scope-owned session views without navigation or reload. Exercise the targeted configuration refresh with and without a retained Home Scope; refreshing a Scope snapshot alone cannot update consumers of the global store.

Existing Project settings must preserve optional metadata that the creation flow requires. Test discovered Projects without a stored name, folder-only and task-default-only edits, and explicit invalid renames; a display-label fallback is not a stored name. Preserve that absence when seeding production acceptance from real catalog state instead of creating a named replacement Project.

For directory recovery, place the failed/current location and recovery controls before historical lists. Collapse unrelated Worktrees and affected-task lists, keep search complete, and bound expanded lists. Long confirmation descriptions must scroll independently of their actions; test hundreds of titles and long paths in narrow, short windows. Catalog refresh and registration of an existing location never authorize an unverified or replaced directory. Route those results to explicit revision-checked rebinding, retain failed drafts, and test cancellation and owner changes before mutation. Pair rendered tests with real directory replacement and missing-then-created directory fixtures; a mocked successful registration does not establish filesystem recovery.

Theme and color-scheme selections apply immediately, while fonts, locale and other staged preferences use the footer Save/Cancel flow. Verify both boundaries rather than assuming every appearance setting shares one commit policy. Test same-mode theme changes on already-mounted content and portals. Exercise concurrent Desktop skin persistence with real temporary files: all accepted writes must settle in order, the final stored skin must match the latest request, and a failed replacement must clean up without blocking the next save.

For Settings, keep draft controllers in the panel owner so page and subview transitions cannot dispose staged values. Include preferences stored outside configuration, such as the Boss self-memory name, in the same explicit save sources; blur and disposal must not publish a preference draft. Validate numeric and structured-text inputs before patch normalization can omit invalid values, and bind errors to the visible field and owning page. Rebase successful writes against the submitted snapshot, validate all sources before commands run, and retain domain receipts across read failures so retry never repeats a completed write. Audio tests use saved configuration only; test permissions, silence, structured failures, stopping and disposal with isolated media fixtures. Use the owning UI library Portal for a popover: a permanently mounted generic Portal can hide content without unmounting its focus scope. Verify close-animation completion and focus return with rendered keyboard tests.

Keep section resource dependencies explicit and lazy. Verify that a failing model or agent request cannot block unrelated sections, refresh failures preserve readable snapshots and staged fields, and retries only reload affected resources. Search indexes should reuse field descriptors; test real scrolling, focus and highlight cleanup after late mount or selection replacement. For asynchronous dismissal, use a controlled close button: a library close primitive may close unconditionally after its click handler despite preventDefault. Route every dismissal through one guard, close the parent only after its discard confirmation has closed, and test server error responses through generated SDK calls with error propagation enabled.

For Settings controls, measure the available content width rather than the viewport alone. Verify field/state separation, effective font text, narrow footer allocation, selected-option keyboard behavior and actual computed accessible names. Use the public inset surface locally, keep errors readable, and associate descriptions and errors with their controls. Configuration intent or missing telemetry must never imply a healthy running service. Cover first-use configuration guidance, target-only advanced expansion and successful writes whose readback fails.

For full-width selectors, measure the actual value and chevron bounds; an expanded trigger must retain leading text and a trailing indicator. Keep selection marks independent of hover and keyboard highlighting, preserve visible focus when removing a resting border, and mount Settings menus in their owning layer. Render real resolved themes before comparing computed colors or borders: unresolved custom properties can make unrelated styles appear equally transparent. Inspect expanded file details with long paths at desktop and narrow widths. Test Escape from a focused option, including multiple selection, because a listbox can consume the event or clear selection before its enclosing popover handles dismissal.

For resource configuration flows, test list search across all visible resource groups, field errors that reveal an entry excluded by search, and focus return after a rename or page switch. Keep editing inside the shared Settings save boundary. Verify transport-specific drafts and key/value rows with spaces, colons and equals signs; duplicate or unnamed entries must fail validation before record normalization can discard them. Confirm that creating and editing a server does not execute its command.

Pass reactive local collections to the shared `List` as arrays, such as `items={models()}`. Function-valued `items` are filter-driven loaders; passing a memo as a loader does not subscribe the list to later catalog updates. Hold catalog publication until the initial rows are visible, then verify new models appear and their quick-switch preferences can change without search input or remounting.

For credential recovery, remount the connection form through a Settings section change after a successful write and failed refresh. Automatic method selection must honor the retained receipt, preserve the refresh action and avoid replaying API-key writes or credential imports.

## Library and statistics recovery

Verify experience states through the persisted reward status and generated DTO, including a failed stub with no intent and an evaluated zero reward. Test detail failure, duplicate reads, local retry and disposal independently of encoding. Unified search keeps result ownership by query and content group. Test a pending group under the real Suspense owner: independent fetches alone do not prevent the parent fallback from hiding ready results. Do not infer timestamps absent from a public summary. For sparse daily statistics, cover skipped dates, month/year and leap-day boundaries, snapshot-relative ranges and local date labels; a successful refresh must publish one response without a second compute request.

## Preserve State and API Ownership

Bind global navigation actions to their shell owner instead of a task-owned command override. Test the rendered action beside the real task control and command registry with disabled and uploading states, retaining task-specific draft transfer in the Composer. See [sidebar project creation ownership](../../../../docs/decisions/implemented/bug-fix/2026-10-14-sidebar-project-creation-ownership.md).

For projected conversation streams, send regression frames through the real WebSocket handler as well as the reducer. Exercise a first Part arriving under an obsolete subscription after navigation, visibility renewal and reconnect, plus a large reference read cancelled during that transition. Verify discovery without accepting the obsolete body, unchanged current summaries, ordered sequenced events, no reads for discarded references and no publication after disposal. A helper-only test cannot detect an earlier transport branch bypassing recovery.

For content recovery, exhaust the HTTP conflict budget before delivering a matching live body at both the same and a newer version. Verify that the retry surface clears without a click, additional request or row remount; mismatched retained text and summary-only advances must not count as recovery. Publish body and version together, and exercise late reads, shared consumers, inactive views and memory release. Measure the body paragraph's reading offset across error removal: transient error text must not own a reading anchor or alter saved body-block indices. Cover a row resize before the virtual content extent changes, and inspect painted frames rather than accepting only the final restored offset.

A Part can produce several timeline presentations, such as a visual card and its promoted attachments. Visibility maps must distinguish those presentations while retaining identity across legitimate transitions such as reasoning promotion. Test the complete projection with both faces present, asserting that the card survives and final row keys stay unique; mounting the card alone cannot establish conversation acceptance.

Ordinary uploaded attachments leave model preparation policy to the server. Do not manufacture an explicit summary or exclusion policy from MIME type: that can suppress text and document extraction. Verify the actual composer payload through preparation and a provider request, including a random identifier present only inside the uploaded bytes; upload success and a file card alone do not prove delivery.

For optional features, use `useGlobalSDK().capabilities.has` against public `features`, never package IDs in diagnostic `components`. Apply the same requirements to desktop/mobile navigation, settings search, both composers, restored resource tabs, historical tool cards and cross-server actions. Unknown selections remain hidden. On reconnect, including the same URL, suspend autosave and retry timers, clear plugin/theme ownership and reject stale replies while retaining local drafts and saved tabs. Verify a core server, an independent feature and removal/reinstallation through rendered components and request counts. Pass the service selection through `DataProvider.hasFeature` to shared UI; preserve transcript text and attachments without exposing missing features' control metadata. Keep plugin-owned surfaces independent of the built-in map; configuration field ownership still comes from `/config/domains`.

Hold discovery, resource-load and save replies across a reconnect epoch and a reinstall. Verify that those old replies cannot republish the previous selection, restore optional UI or overwrite the retained draft. A startup `503` from capability discovery stays unknown and retries until readiness; abort that wait on an epoch change or provider cleanup. Exercise the generated client against the selected target when an action can switch servers; the current server's capabilities cannot authorize a different target.

With a sole optional resource open, unknown discovery must dispose its presentation without persisting a fallback selection. Confirming the same owner restores the selected resource; confirming absence selects an available surface. Reproduce capability confirmation before the same update's panel registration: default-page restoration must wait for registration to settle and recheck the active panel. Also verify an empty Core surface can open its generic home and a user's explicit choice during discovery remains selected.

Special message wrappers must forward reactive message and Part getters through deferred content hydration. Render the header first, deliver attachment Parts later, then remove and restore the source feature; verify that the ordinary attachments remain visible without remounting the message.

Distinguish capability retirement from ordinary Scope pause. A plugin workbench entry accepted under the same confirmed capability selection may keep its `retention: "pause"` instance while another Scope replaces the active registry. Preserve its original owner and public lifetime; plugins pause their own work through `onActivity`. Unknown or absent capability, selection replacement, and owner disposal must destroy the presentation and abort its lifetime, including hidden views. Test real provider/registry transitions and delayed discovery, preserving domain drafts without using saved tabs as an availability fallback.

When several owners share an API, gate each record by its persisted source before loading bindings or exposing controls. Blueprint loops require Blueprint plus Lattice for `lattice`, or Plugin Host and the `plugin-blueprint` bridge for `plugin`; keeping the API owner installed does not retain an absent source. Use Session and Note source projections before the first loop GET, then recheck returned lists, events and mutations. Historical special messages and tools add every `metadata.requiredFeatures` entry to their existing presentation requirements; absent metadata preserves the older host contract. Test removing only the source or bridge, keeping Blueprint and ordinary notes/conversations, and restoring the source without losing drafts or sent attachments.

After building Web, run `bun apps/web/test/fixtures/verify-runtime-capabilities.ts` for real same-address removal/reinstallation coverage. It starts one isolated source runtime at a time, reuses its temporary home and port, drives the built Web through Chromium, and verifies that each stopped runtime releases its port before the next starts. Coordinate that runtime window with other agents; the fixture retains local logs, screenshots and request counts and shuts down its server on success or failure.

Run `bun apps/web/test/fixtures/verify-blueprint-source-capabilities.ts` for source-only removal: it keeps Note and Blueprint installed while cycling Lattice, exercises retained history and the composer before and after cold deep-link navigation, and verifies that no absent-source loop GET occurs. Its seeded armed loop never submits model work.

Observer targets delivered by asynchronous mount callbacks must be reactive element signals, with cleanup on unmount. Verify late mount and replacement against rendered layout or computed CSS properties instead of asserting implementation strings.

For Composer layout, measure the Dock's border box, including bottom padding and safe-area space. Observe border-box changes without content-box deduplication; padding-only changes must update conversation clearance. Deduct the actual bottom padding from expanded editor space. Verify compact defaults, viewport breakpoint changes, short windows, narrow panes, first-send anchoring, upward growth, internal scrolling and reachable actions with the real Composer and production styles; retain font size, touch targets and the single editor.

For fixed component refs assigned after setup, initialize layout snapshots and observers after mount. Test the first layout change and a live reduced-motion preference change; later reorders alone can conceal an absent initial measurement. Remote artwork must retain an identifiable placeholder while its request is pending as well as after failure.

Treat resource and operation keys as opaque strings. Escape them with `CSS.escape()` before placing them in selectors in both current-selection and keyboard-navigation paths. Cancel deferred scrolling on selection replacement and unmount. Test actual rendered scrolling and selection with composite JSON keys, quotes, backslashes, Unicode and empty strings. Follow the same identity through upstream controls and repeat the original installed interaction after a local fix. For patched dependencies, test every shipped module form and preserve canonical values; selector escaping must not become a second persisted identity.

Solid JSX may evaluate to a function. Never distinguish a rendered trigger from a component with `typeof`; use an explicit component prop such as Popover `triggerAs`, and forward its event, ref, and accessibility props to the native button. Test click, keyboard activation, Escape, and focus return with the real Tooltip composition. For animated overlays, wait for content removal before asserting restored focus; a still-focused opener during dismissal does not prove the closing focus scope has settled. Retained hidden workbench surfaces must be inert without losing drafts. Route Escape through the active overlay first and only collapse the surface containing focus; verify two simultaneously open surfaces, a nested menu, a dialog, and an editable target in a real browser. When a responsive modal presentation unmounts, release its overlay without closing the underlying workspace domain.

1. Use stores for coherent keyed collections and signals for independent scalar state. Read project-overridable configuration from the current Scope through `useSync`; `useGlobalSync().data.config` contains global settings only. Test differing global and project values plus a Scope config refresh.
2. Apply same-identity entity updates with targeted setters and `reconcile`; do not replace a whole stored object for a one-field event. A single-entity projection may alias a transcript or another store bucket: when its entity ID changes, replace the pointer through `produce()` instead of reconciling at the object root. Verify that advancing the projection preserves the previous entity's ID, contents and visibility before a reload can repair the view.
3. Keep derived values one-way. Preserve composer resolution as explicit draft → session default → fallback; only explicit user choices persist upward.
4. Use generated SDK methods for ordinary internal HTTP routes. Keep raw browser transports only for WebSocket/EventSource/WebRTC, external URLs, platform fetch injection, and browser file/blob/download flows that the SDK should not represent.
5. Preserve Scope/directory parameters, authentication, error semantics, asset URLs, event `seq`/`epoch`, replay, and loading/error states. Directory ownership matching must preserve POSIX path case; case folding belongs only to Windows drive/UNC paths.
6. For append-only LLM streams, keep the full snapshot as recovery state while imperative renderers track an offset and consume only the appended suffix through the dependency's typed live-update API. Do not rescan the accumulated prefix or insert an independent character-rate playback backlog; reset from a checkpoint only when the append invariant breaks. Derive terminal presentation from explicit part or message lifecycle markers, not coarse session status or the presence of a later timeline part. Key imperative terminal transitions and enhancements by content identity so unrelated sibling updates cannot restart them.
7. Do not key the whole turn or message-role boundary by object identity: `message.updated` events land as fresh objects on every update, so a keyed `Show`/`Match` destroys and rebuilds the entire turn (tool-card expansion, scroll, and Markdown state included) several times per reply. Keep those boundaries non-keyed responsive updates, and instead isolate failures inside `Part` with an identity snapshot: capture session/message/part/type before child evaluation, render the ErrorBoundary fallback from that snapshot only, and never re-read the failed child's live props. Log the original error with stable IDs only; exclude message content, tool payloads, and workspace paths. Cover this with a real Solid lifecycle test that proves a secondary stale read cannot escape the local boundary.
8. Read session-shaped store fields through the session data view only: ui components use `useData().view` (`partsFor`/`messagesFor`/`permissionsFor`/`statusFor`/`inboxFor`/`hasInboxBucket`/`todosFor`/`dagNodesFor`/`questionsFor`/`cortexTasks`/`sessions`/`sessionFor`), app components use `useSessionDataView()`. Do not read `data.store.part/permission/...` or `sync.data.<field>[sessionID]` directly in render code — session switches race store intermediate states (missing buckets, released scope stores) and `createMemo` defaults stop applying after first compute, so a direct read can surface `undefined` and crash with a rotating set of TypeErrors. The view accessors apply their empty fallback inside the function body. Missing array buckets must resolve to the shared constants in `packages/ui/src/context/session-data-view.ts` (`EMPTY_PARTS`, `EMPTY_MESSAGES`, …) — never a fresh array literal, because the render chain's `same()` equality guards short-circuit on reference identity and a fresh literal would invalidate every downstream memo on each store tick. `hasInboxBucket` is the only accessor that reports bucket presence: use it to preserve an "not loaded yet" gate when `undefined` semantics matter (e.g. inbox loading state).
9. Callback parameters are accessors or raw values depending on the control: non-keyed `<Show>` and `<Index>` pass an accessor — call it (`param()`) before rendering or passing it into i18n values, formatters, or attributes — while `<Show keyed>` and `<For>` pass the raw value itself. Passing an accessor uncalled renders its minified source (the crash-page footer once displayed `Version: () => { if (!untrack(condition)) … }`), and calling a keyed `<Show>` or `For` parameter fails typechecking. Prefer the non-callback form reading the source signal directly when no narrowing is needed.

10. Publish page-owned entries in global reactive registries from `onMount`, after transition commit; synchronous setup writes can stage old entries and overwrite their cleanup during commit. Register all cleanup before returning, and use leases for state shared by overlapping owners. Test nested navigation and a suspended transition, asserting that old registry entries disappear, the visible page keeps its commands until commit, disposed loaders abort, and stale replies cannot mutate reopened state. See the [transition lifecycle decision](../../../../docs/decisions/implemented/bug-fix/2026-09-07-transition-lifecycle-retention.md).

Global command-palette navigation must work while an editor or terminal owns focus. Test a native key-consuming target, verify that the palette opens without sending the shortcut into the control, and confirm provider disposal removes the capture listener. Keep ordinary local bindings at their existing propagation boundary.

For user decisions and recoverable queue operations, retain state by request identity, keep structured errors, and reconcile uncertain transport results before retrying. A public preview is not a restoration payload: restore through the domain's original input and idempotent receipt. Verify delayed replies after a request switch, lost replies after server success, failed restoration, and stopped progress motion separately from pending state.

For immediate Settings connection commands, keep setup inputs under the dialog owner without registering them as preference changes. Reuse a stable creation ID, recover a lost response through the canonical connection snapshot, and retry reads after a known write without repeating it. Abort disposed authentication waits and prevent late responses from completing a different view. Present catalog source and verification time independently of authentication health; inspect structured failure fields even when the transport succeeds. Cover these boundaries with the actual connection components.

Account metadata editing must not be gated by delete capability. Verify both canonical and named connections through the same update route, including blank display-label fallback and unchanged account identity. Separate account editing from new-account setup; capture explicit sibling-creation intent instead of inferring it from connectivity. Service pickers represent service types rather than sibling instances. Keep metadata baselines and pending writes with the dialog-owned drafts so section remounts cannot unlock an in-flight update. Include resource drafts in every dismissal guard without registering them as preference-save sources, and retain credential confirmation after a connection ID has been allocated. Exercise update success followed by failed refresh and section remount, then edit and save again to prove cached receipts do not suppress the next legitimate write.

Logical conversation disclosures must be independent of message boundaries and virtual render chunks. A turn's process entrance reveals public prose and independently expandable contiguous batches. Keep parent and child choices independent, retain batch identity through historical prepend and parent closure, and let locators reveal both ancestors. Balanced defaults may collect finished earlier batches, but cannot collect pending parallel calls, focus, selection or protected reading. Summaries use successful operation evidence without hydrating offscreen bodies; total calls include unsuccessful attempts. Secondary reasoning arrows appear on hover or keyboard focus on fine pointers, and remain visible on touch. Verify cross-message reasoning/tools, public-prose separators, terminal marker ordering, final Markdown identity, focused/selected content and bounded mounted bodies with real virtual-list components. Exit animations may retain only mounted rows and must release their content leases after settling. Interrupt a manual entrance by actual virtual eviction before settlement, then verify its later mount stays static. Keep compact pending-space estimates scoped to process bodies; ordinary user attachments and final answers retain their own geometry.

## Preserve Loading Boundaries

Hold Task details summary and context reads pending while navigating to a cold conversation and returning to a retained one. Verify that settled transcript content becomes readable and interactive without closing the panel; failure, retry and cancellation retain its rows and reading position. Keep accounting readiness separate from canonical root execution and mounted-body readiness, and count requests to reject a compensating eager fetch.

Optional menu metadata must not suspend an already-visible selector or Composer. Supply a typed initial snapshot and read `resource.latest`; without an initial value, the first `latest` read can still suspend. Bind snapshots to their current connection and query owner, and settle failures inside the affected menu item. Hold initial and refreshed requests pending with the real menus and production layout; verify retained trigger/editor/Canvas nodes, unchanged geometry, partial failure, late connection responses and Escape focus return. For Session metadata, exercise cold navigation and a return after resident-view eviction as well as a warm return; hold folder, history-preparation and message requests separately and check shell/editor presence before releasing them. The directory resource regressions live in `apps/web/test/components/session/project-directory-resource.dom.test.ts`.

Navigation summaries must not evaluate deferred execution data. Keep command templates lazy until their Workspace-bound execution, and cover Home command reads with a template that would fail if evaluated. For virtualized history, preserve the visible display row and offset rather than only its message ID; one message can contain many Parts. Test a prepend while a later Part of the same message intersects the viewport. Use one geometry owner for prepend anchors: move cached measurements with an exact retained row suffix, keep one outer reading row through internal Part backfill, and do not schedule a second Page DOM correction. A virtualizer's programmatic measurement retries must not overwrite later wheel input. Exercise recovery that completes after historical navigation; keep the retained window and summary row identities while refreshing bodies, and fetch latest Context independently. When assembling bounded snapshot pages, retain the first response watermarks rather than stamping earlier content with the last page's newer version.

1. Register optional built-in workbench panels with `WorkbenchPanelEntry.loader`; do not statically import Notes, Files, Browser, Terminal, or Review implementations into the route shell. Browser pages are resource tabs in that same strip; follow [change-browser-runtime](../../change-browser-runtime/SKILL.md) for page reconciliation and settings. Do not nest another Browser tab strip or expose backend profile terminology in the everyday toolbar.
2. Keep heavyweight feature engines behind the interaction that needs them: Tiptap and Mermaid behind Notes, Monaco behind file Source view, and Ghostty behind Terminal.
3. Do not evaluate JSX child getters to detect detail presence: use an explicit availability value or property presence, then instantiate children only inside the mounted disclosure. Test closed → open → closed imperative-renderer counts. Bound tool previews and retained expanded-render caches by capacity; use resource identity to open full content on demand. See [bounded tool rendering](../../../../docs/decisions/implemented/bug-fix/2026-09-07-bound-tool-rendering-memory.md).
4. Import only fonts used by the active product typography contract. A dormant family must not be emitted by the default App build.
5. Preserve `apps/web/test/app-build-css-contract.test.ts` as the production build regression gate for initial module preloads, emitted product fonts, and core compiled CSS. CI consumes the verified full-distribution Web build via `SYNERGY_WEB_BUILD_DIR`; standalone execution builds an isolated fixture. Reusing a local build through that variable requires `--manifest` and a readable `.vite/manifest.json`. Share compiled UI test modules only with complete input/output validation and fresh processes and DOMs; settings regressions assert actual interaction and saved values rather than source strings.
6. Keep the Web HTML entry in Tailwind's explicit source inputs when moving package roots. Validate the built HTML and CSS together in a browser with overflowing sidebar content and composer focus: the root must stay within the viewport and the list must scroll without moving the document or navigation header.

When a retained view replaces an input service, key the presentation binding by the service identity. A truthy-to-truthy replacement must not retain an editor mounted against a disposed controller; ordinary readiness updates within one service must retain its editing state.
