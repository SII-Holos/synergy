# Public product screenshots

Use this procedure when refreshing README or documentation screenshots. Product implementation and runtime verification remain governed by the parent [development workflow](../SKILL.md).

1. Inventory existing image files and their Markdown or HTML references. Distinguish UI captures from benchmark figures, logos and generated brand assets. Keep existing asset paths when replacing the same product view.
2. Start a dedicated Home and Electron profile with explicit free ports. Verify the server's reported Home before seeding through the generated SDK. Never populate a real user's Library, Notes or Agenda for a screenshot.
3. Use clearly synthetic project names and content. Genuine demo turns may supply experience records; retain their real evaluation state. Do not fabricate successful runs, rewards, permissions, installed plugins or remote devices to fill a view.
4. Make scheduled examples future-dated, record their IDs privately, and pause them after capture. Verify their final state before handoff. Do not leave screenshot preparation scheduling later model work.
5. Capture the actual rendered product through the native or browser controller. Inspect the image for readable headings, clipped controls, dialogs, private paths, credentials, runtime identifiers and personal content. Use an ordinary UI action to dismiss temporary menus and tooltips before capture. Do not reconstruct the product UI or replace screenshots with generated mockups.
6. Inspect the captured bytes' actual format; an output filename does not select encoding. Native capture can return JPEG bytes even when saved with a `.png` suffix. Convert only the encoding when the repository asset requires PNG, using a temporary output and preserving the original capture outside the repository. On macOS, `sips -s format png <capture> --out <asset.png>` performs this conversion. Check the resulting format and dimensions before replacing the asset.
7. Update captions to match the displayed version and real data. Keep public demo inputs separate from private manifests, credentials, logs and resource IDs. Finish captures and file writes before running documentation, decision and formatting checks.

The handoff names refreshed assets, relevant checks, retained demo processes and the final state of any screenshot-only schedules.
