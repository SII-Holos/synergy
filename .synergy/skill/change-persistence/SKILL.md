# Change Persistence

## Classify the State

1. Decide whether the data is canonical durable state, a derived index/snapshot, cache, auth secret, runtime lock, temporary artifact, or project-local configuration.
2. Read [Storage and paths](../../../docs/reference/storage-and-paths.md) and the owning architecture document.
3. Trace every writer, reader, index, event, export/import path, recovery path, deletion path, and startup migration before changing the shape.

## Implement the Current Model

For incremental native restoration on an already held Target, bind the actual original import receipt and authenticated archive namespace through `RuntimeMaintenance.withRestorationArtifacts`. Prepare binaries outside SQL/checkpoint gates, then publish through the original restoration transaction. Require exact streamed native-location witnesses, mandatory alias completion and a final guard over the full staging namespace; caught failures must still reject COMMIT. Verify unknown outcomes with garbage collection and cold reuse. Native evidence does not grant domain append policy or recovery readiness.

For whole-aggregate replacement, trace derived state stored outside the canonical prefix. Invalidate or rebuild it through its owning API inside the publication transaction. Warm the previous destination before importing changed membership, then verify canonical, ordinary, paged and cold reads plus rollback. Invalidating one unrelated cache does not establish complete read consistency.

When hydrating references from a batch of records, deduplicate referenced identities and use the owning domain's batch reader instead of one concurrent read per record. Keep ownership checks and missing-record positions, and verify more distinct references than storage admission capacity, shared references, malformed records and subsequent rebinding with real storage.

For composed domain reads, use `Storage.snapshot()` and make every paginated projection query join its parent transaction; a direct `TransactionalStore` query inside it can reenter the non-reentrant reader queue or lose writer-local visibility. Release a reader snapshot before a cold derived-index write and recheck after writer admission. Verify with a real held writer, committed external reads, transaction-local writes and a concurrent publication; use physical barriers with bounded rescue and cleanup rather than latency targets.

For child/task metadata pages, update thin projections with canonical lifecycle and import writers in the same transaction. Keep private prompts and outputs out of rows, counts and cursors. Register the old-state upgrade with its owner and invoke catalog preparation only from the explicit reading domain; do not attach a complete sibling scan to ordinary Session metadata access. Verify child-record read counts after preparation, restart, hidden and ambiguous identities, rollback, parent moves, removal and deleted cursor anchors.

For execution-status observations, keep current record reads separate from historical replay and execution recovery. Match descendant Run parents and record identities, bound candidate discovery as well as body reads, and report truncation. Direct-record pagination omits branch-only nodes; use branch-inclusive addresses and validate their records before counting them. Verify real process liveness and exit alongside interrupted records with unknown physical completion, nested unrelated roots, large fan-out, corrupt metadata and an unsettled journal. A cancelled Run or empty live registry cannot prove physical exit.

For auxiliary SQLite migrations that inspect schemas or rows before writing, acquire write ownership before the first read. A deferred WAL snapshot cannot become a writer after another connection commits, even with a busy timeout. Use a second real database connection to attempt publication between inspection and migration commit, then verify that both migration metadata and subsequent writes remain usable.

When reducing authority-read work, batch only the current operation through its owning storage reader. Listing projections must re-read durable state on the next call; mutation admission must re-read every owner's fences inside the current transaction on every write, including after an earlier write installs a fence. Measure fixture preparation, rebuild, listing and cleanup separately with real SQL/worker counts against an identical baseline fixture, and gate work bounds rather than host latency. Verify mixed missing records, malformed state, same-transaction fence installation and rollback; never reuse presentation projections or transaction-wide absence caches as authority.

Do not join store-wide in-flight preparation from a transaction that the preparation may need. Complete preparation before business admission; inside the transaction validate durable receipts with its own snapshot. Test a cold concurrent reader and writer behind explicit barriers, including already-current owners, missing receipts, rollback and retry. A prewarmed load can hide this cycle.

For physical directory retirement, enumerate host-qualified canonical Workspace authority across the Storage namespace, not only one Scope or registry. Repeat subtree and physical-alias exclusion inside the serialized catalog write transaction, and reject overlapping authority publication through registration, rebinding, relocation and identity upgrades while deleting. Keep filesystem identity checks outside SQL callbacks. Cover both writer commit orders with barriers, descendant and foreign-Scope references, active ancestors, unbound imports and blockers beyond a page boundary; a native claim does not prove the absence of dormant logical references.

### Authoritative Agent records

1. Build logical keys through `StoragePath`; use an explicit `Storage.Handle`. Normal Agent record code must never read or write legacy JSON files.
2. Keep independently updated or streamed records independently addressable. Wrap the complete business mutation, indexes, receipts and outbox notifications in `Storage.transaction()`.
   Keep growing ownership sets out of directory rows. Use independently addressable records and a transactional occupancy count when readers only need to know whether a selection is retained. A storage or transport window must not become a new product quota; task budgets come from the existing execution contract. Test beyond former fixed limits, rollback, repeated rejection and restart. Version retained metadata through registered record migrations, preserve unknown or damaged ownership as an error, and verify cold startup does not enumerate historical owners.

   Separate retained resource use from durable execution identity when a task can continue. Fence issued capabilities by a retained-use generation, publish immutable release receipts with occupancy, and recheck physical transport drainage at commit. An older release retry must not decrement a reacquired generation. Verify a request admitted during publication, release/reacquisition rollback, response loss, reconnect and historical capability migration. Bounded activity observations alone cannot establish native drainage.

3. Nested writes join the caller's transaction. Defer cache and event effects until commit. Never run tools, network calls, plugin reloads, filesystem writes or buffer drains inside a retryable SQL transaction. Keep transaction-owned part writes out of streaming retry buffers; verify rollback followed by a delivery retry cannot resurrect the abandoned parts.

When a record-access migration fills a default, make the current writer materialize the same supported value before caching and publishing new records. Compare warmed history with a detached read and cache eviction using standalone and nested records; compaction must accept unchanged history while still rejecting real source edits. Seed historical migration fixtures with their original stored shape instead of assuming a current writer still emits it. Upgrade imported records before applying current write defaults, and test the real import entry point. See [attachment default consistency](../../../docs/decisions/implemented/bug-fix/2026-10-27-attachment-default-consistency.md).

Preserve missing-original and truncation provenance before migrations, imports or current writers create replacement artifacts. A complete artifact made from a preview proves only that preview, not the lost original. Recover inline content only against the original descriptor's hash and byte count; test direct reads, real owner preparation, current writes and repeated imports, with a valid retained-original control.

Authority-sensitive mutations must carry a synchronous `commitGuard` to the actual SQL driver commit decision, after all awaited ownership checks and before COMMIT. A callback-end assertion cannot fence PostgreSQL's post-body ownership query. Preserve nested guards until the outer write settles, reset them on retries, reject guarded writes inside read snapshots, and test rollback of real staged records plus a valid-current-authority control. Keep guards I/O-free; after the commit decision, failures belong to commit uncertainty/reconciliation rather than compensating deletes. If the documented test PostgreSQL URL is unavailable, report the real-engine gap separately from a narrow driver-transport fixture.

4. Treat commit uncertainty as an unresolved result; reconcile the operation receipt before retrying. Preserve storage, ownership and integrity errors instead of treating them as missing records. Mark an optional read with `silentNotFound: true` at its caller and recover only from `Storage.NotFoundError`; never suppress all missing reads globally. Test cold initialization through the real caller, including its `missing` telemetry outcome and propagation of a genuine storage failure.

For high-frequency owner updates, define the deduplication evidence's lifetime before choosing a receipt mechanism. When serialized retries need only the latest committed update, keep that evidence in the authoritative owner checkpoint rather than retaining one permanent global command receipt per flush. Verify uncertain commit and unavailable reconciliation, input-hash conflicts, superseding writes, owner deletion and portable export; bounded payloads alone do not bound cumulative receipt growth.

For externally admitted commands, separate the logical accepted effect from terminal transmission attempts. Creation must reserve one stable identity with authorization, commit native object and receipt together, and permit skip before the object exists. Verify rollback removes newly created indexes and Scope metadata, restart retains the receipt, and replay never adopts or recreates an unrelated or deleted object. A rejected or skipped attempt cannot consume a future authorized retry of the same unchanged request. Bind the complete target and payload digest, serialize skip with late input, and retain ordering checkpoints across restart. Commit receipt, Inbox/control mutation, sequence and notification together; avoid taking a delivery lock below the SQL writer when another caller takes those locks in the reverse order. Test actual staged writes followed by connection loss, deadline crossing and rollback before returning acceptance. Native continuation must drain execution before opening the receipt transaction. Release its control lock while waiting, reacquire and revalidate the observed pause, then join the native transaction through its admission hooks. Use the native final commit guard for transient authority so a deadline or connection refusal preserves its admission error through Rollout publication. Test a newer pause during the wait, cancelled admission, original hook and guard errors, and rollback of receipt, Inbox, pause release and Rollout reopening together.

Service admission must recheck current authorization and a captured live connection in its writer; persisted last-seen data is not online authority. A new request held behind an unresolved predecessor is definitely unsent, while the predecessor may have an unknown outcome. Retain each issued reconciliation proof until its attempt lifecycle ends, and test a late receipt from an older proof after issuing a replacement. Older receipts must not clear a newer pending sequence or erase already retained terminal evidence.

Compose task-cancellation receipts through the native Rollout admission hooks. Commit the cancel intent, matching Inbox removal and host receipt before physical signals, and keep drainage outside SQL. Fence connection/deadline failure at commit without withdrawing accepted cancellation on disconnect. Test unchanged terminal runs, unopened queued work, a run appearing during preparation, original hook errors including NotFound, and recovery after drainage fails. Keep control serialization through drainage so a delayed cancel cannot stop a newly continued root.

5. Call `Storage.writeBinary()` before entering `Storage.transaction()`; it rejects in-transaction calls because filesystem bytes must become durable before the business reference commits. Stage unpublished large imports and register resumable post-deletion cleanup. Rollout evidence commits its sequence allocation, event evidence, projection and head in one transaction.
6. Physical writes retain the atomic-file transient-retry contract for Windows sharing violations. Extend the real-file retry tests when changing that helper.
7. Keep the SQLite subprocess alive through owner process-group cancellation so terminal evidence can drain. Verify real `SIGINT`/`SIGTERM` delivery to an isolated owner group and forced owner loss; explicit shutdown, request deadlines and parent-disconnection cleanup must still terminate the worker.
8. Run the shared SQLite/PostgreSQL contract tests for engine changes; CI requires real PostgreSQL 16–18. macOS source development needs the verified SQLite engine from `bun packages/harness/script/build-sqlite.ts`. For engine packaging changes, run `bun test --config /dev/null test/script/release/workspace-sqlite.test.ts` on macOS to open the actual unpacked archive with host libraries masked.
9. Inspect real query plans for early and late cursor pages when changing large imports, verification or export. Verify index range seeks, tied ordering, descending pages, deleted cursors and namespace isolation. Prefix traversals must probe records from their descendant frontier; include an absent recovery root against a populated namespace so an empty result cannot hide a full scan. Child enumeration must short-circuit after live evidence in each immediate child rather than walk every historical descendant; verify deleted-only and foreign-namespace branches remain hidden. Full maintenance walks use the existing key index; measure the space cost before adding another per-record index. Keep physical integrity checks complete and size their finite maintenance budget from the current database snapshot, including WAL growth; never relax ordinary query deadlines to cover offline verification.
10. Route every long SQLite operation through typed driver maintenance (`vacuum`, `reclaim`, `integrity-check`, `create-index`, `drop-index`), including schema DDL during first open. Do not add caller-specific startup timers or budget callbacks. Verify the real operation emits begin and exactly one terminal event; preserve finite snapshot budgets, bounded worker probes, failure propagation and PostgreSQL behavior. Read the [startup maintenance contract](../../../docs/decisions/implemented/bug-fix/2026-09-20-startup-maintenance-contract.md) when adding an operation.
11. Audit direct SQL observers and cross-language test probes when changing record encoding. Prefer the canonical storage reader; isolated probes that must inspect a running container's private database must decode both plain and compressed bodies and retain a real-container regression.

Background maintenance may update session metadata without representing conversation activity. Carry the owning session mutation's activity-preservation option through cleanup helpers, retaining canonical activity timestamps as well as navigation `lastActivityAt` while publishing changed metadata. Test normal reclamation, missing-resource reconciliation and navigation index reconstruction with real session records, and verify new conversation activity still advances recency. For pause recovery, cover the first latch write during lazy Scope startup as well as repeated reconciliation; an already-paused fixture alone cannot detect a recency change on initial discovery.

When changing worker liveness or shutdown, close a real worker while a blocking query has entered its busy state. Verify probing exits within the teardown budget and deliberate shutdown emits no terminal-unavailability notification. Recheck driver and request ownership after awaited probes; a closed driver can make retries resolve immediately and starve shutdown timers.

Keep queue admission wait caps separate from explicit request deadlines and SQL execution budgets. A local wait cap ends when its callback begins; only caller deadlines and cancellation propagate into later admissions. Test a real multi-step storage operation across that cap, plus expired waiters and nested explicit deadlines. Delaying a recovery entry point outside its storage gate does not exercise this boundary.

For PostgreSQL deletion plans, include a new namespace created after statistics were collected for unrelated history. Inspect actual row visits and loop counts for the emitted statement; indexed predicates alone do not prevent the planner from repeating an inlined candidate query. Keep the same transaction and deletion semantics when bounding repeated work.

### SQLite and other domain stores

1. Keep fresh-install schema creation in the owning database initialization.
2. Put upgrades, backfills, and rewrites in versioned domain migrations registered through the central migration runner.
3. Preserve transaction, WAL, vector-extension fail-soft, and backup assumptions of the owning store.
4. For model-assisted read-transform-write work, carry the observed revision through asynchronous preparation and compare it inside the final database mutation. Use a monotonic revision, including same-millisecond writes. A conflict must leave canonical data and derived indexes untouched; test a held preparation step with an intervening writer and deletion. A preflight read alone does not protect the write.

For namespace backups, capture an MVCC metadata snapshot and stream its fixed immutable artifact locations while holding the native artifact pin/gate. Do not re-read current keys or stream object pages from inside an already-held SQL export snapshot. Reuse the portable parser and native binary preparation across content backends. Verify missing bytes/keys, callback cancellation, unfinished readers, failed final fencing and a real independent-Home restore. A namespace archive does not prove complete deployment recovery or unique execution ownership; private archives require trusted operator authority rather than ordinary project/admin access.

Consume caller-controlled binary producers outside the destination artifact gate through bounded temporary spooling. Preserve inherited cancellation, the original key and the native prepared pin; verify final bytes with the canonical backend. Bound active spools and total pending requests across the whole Runtime, including other Stores, and fail saturated nested dependencies instead of queuing behind their parents. Track the full preparation before its first await through file cleanup; close producer admission and drain it before backend closure after accepted caller tails finish. Raw Store owners must await their calls before closing. Test real same-Store reads/cache writes, queued cancellation, cross-Store capacity, nested saturation, closure, collection and commit-unknown evidence.

Capture consumers read protected logical entries through the canonical checkpoint owner, with the actual exporter's returned manifest as the expected identity. Consume and validate the complete footer, recovery keys and reference inventory before sealing a derived capture index. Test a replacement by another valid archive, incomplete iteration and cancellation; reading a later current manifest or adding an independent decryption/parser path cannot prove the captured checkpoint.

For SQL-external Home/config facets, consume the active checkpoint owner's opaque archive evidence inside the existing frozen capture. Keep exact validated file bytes and normalized settings separate from immutable effective startup options; use one owning descriptor/parser and reject replaced paths or parent aliases. Test original cancellation and closed-callback/foreign-Store evidence, then encrypt, reopen and cold-read an independent target with original capture files unavailable. Explicit reconstruction requirements block completeness; a staged segment must not activate source endpoints or replace deployment/ACL/old-writer reconciliation.

For knowledge cache facets, index exact cache and manifest references from the fixed namespace instead of scanning an entire cache or resolving latest versions. Reuse canonical Skill-name and file/manifest validators, check cancellation after reads before yielding, and preserve project-specific identities. Prepare target bytes before SQL. In the target Store's original live write callback, page every canonical cache/manifest address and verify exact inventory coverage before relocating only those directories; recheck transaction ownership after awaits. Test a valid segment with a whole cache partition omitted and self-consistent counts, a foreign transaction argument, an escaping wire name, more than one metadata page, retained old selections, empty files, source removal, corrupt or edited bytes, original cancellation and expired callbacks. Namespace completion does not grant execution or replace deployment recovery.

Do not append target recovery actions at a copied source journal head before reconciling the actual source's final suffix: the source may have continued at those same sequence numbers. Prepare fresh signing material as inactive authenticated ciphertext bound to the original native installation, full request, fixed native/namespace manifests and historical head. Consume native metadata from its owner's private verified snapshot, not mutable presentation fields. Reuse the signing owner’s key codec and retain one durable material across unknown acknowledgements and cold retries. Test a genuine post-backup source authority change while the target keeps its old head and active records unchanged, plus wrong keys, foreign Homes, cancellation and expired callbacks. Before full recovery, the active transition must reconcile the real suffix/current policy and writer evidence, and its backup owner must cover or retire unpublished key material.

Native Runtime maintenance needs one explicit purpose/cohort operation and real suspension/drainage/inspection owners. Verify a trailing canonical writer, rollback, a changed post-drain revision, commit-unknown retry, failed release and cold-cohort refusal with actual storage. Fence new external allocation/execution intents before dispatch and in their publishing transaction; preserve original receipt reconciliation and accepted final saves. Require native process-tree, stream and save completion, and test an in-flight provider request without resubmission. Do not substitute bridge shutdown, Runtime cancellation, unattended pause flags or invented transfer IDs for a writer proof. Wiring the primitive and registering an empty inspector do not establish production maintenance or physical-writer reconciliation.

For native delegated work, retain its current task/root admission, pending repair input, budget, absolute deadline and notification identity in the owning canonical hold. Exercise a real blocked model through suspension and drain, no model call on release, exact original-root continuation and an expired deadline before model admission. A later operation may replace only already released continuation controls; it must never release an active foreign hold. Unknown task schemas and absent cold writers block maintenance rather than becoming completed, cancelled or unlimited.

Drain completion hooks before closing their detached scheduler, then wait for every accepted job and pending payload without shutdown cancellation. Test a real tail write, cancelled wait, recording failure consumed by ordinary settlement, cold namespace and held owner release. Reopen native admission only after the canonical released commit is confirmed; inject a lost final acknowledgement and reconcile the original lease without repeating domain release writes or replaying payloads.

Native process participation covers preparation, supervised trees, output drainage and original claim release. Exercise a real tail file and a retained physical coordinator claim outside the current resident set. A supervisor start without a native acknowledgement cannot be certified by local handle/file cleanup; keep its operation held until the actual owning proof is reconciled.

Track native Workspace claims before asynchronous admission and recheck after the physical lease arrives. Retain actual finalizers beyond physical release. Bound accepted tail authority to an open native callback, separately from unknown reconciliation state; test an escaped exclusive callback after failed saving and foreign Runtime/Store process binding. Canonical receipt recovery may release another lease object: reconcile the exact physical claim/token without treating a resolved release call, historical receipt or empty resident set as proof. Never gate lower Environment acquisition in a way that prevents accepted final saves.

For per-Session physical source capture, close new claims through the canonical root/ancestor epoch intent and retain accepted tails through its mutation contract. Select actual source members and Workspace bindings, drain native process output as well as claim release, and hold original native geometry through the final source facts. Installed writer evidence must come from the actual native lock and primary Store; standalone Store locks acquire no such authority. Test token replacement, late children, cancellation, escaped callbacks and capture/release races across the first asynchronous check. Keep physical IO outside final SQL; synchronous capability checks complement the repeated canonical source verifier.

Use the same captured input for native acquisition and retained geometry. Pin a borrowed claim before asynchronous validation through callback completion and refuse release during that interval. Reserve one minimal covering footprint for nested roots, compare actual Home aliases when finding retained writers, and gate the native process entry through the original Session capability. Failed capture cleanup must preserve its original inventory and both failures until release reconciliation succeeds.

Fence new mount transitions before allocation use and canonical intent publication, while draining actual accepted requests. Check catalog coverage independently of transition indexes. Reconcile a lost acknowledgement only from the exact original native mount receipt; an orphaned preparing row cannot authorize materialization from an earlier head. Reject attaching over an unresolved save. Exercise real native receipts, cancelled waits, missing indexes and half-published transitions; separate transition drainage from complete external-resource capture.

For Environment deallocation, reserve actual native mounted paths before publishing the release intent and retain the original physical claims through saving, detach and catalog publication. Recheck admission after reservation; a later hold must reject an unpublished intent while allowing an accepted release to finish. Test a real competing coordinator and an object Workspace's final bytes. Bind provider callbacks to the exact Runtime/Store/artifact lifetime, settle repeated calls once, and drain started work if a wrapper returns or throws early. Remote paths cannot supply controller-side physical proof.

Verify release inventory against canonical catalog coverage independently of its reverse index. Block new use admission throughout release preparation so a disjoint Workspace cannot appear after root reservation. Reconcile retained releases through the same physical owner; distinguish an original acknowledged detach from a missing view or missing receipt. Exercise those three counterexamples and a lost detach response with real native files.

For Home formats read before SQL startup, version the strict reader fence before publishing its dependent binding. Require the current native ownership reader for member and hosted Homes, including permanent epoch/adoption/command semantics alongside maintenance. Put the upgrade in one owning central maintenance migration under a current opaque frozen lease, not in ordinary reads or provisioning. Hold that operation's native lock across the real file lifetime so concurrent release cannot reopen admission; it grants no ordinary mutation bypass. Retain the owner identity and credentials, resume only the exact partially published file pair, and test previous Node and actual pinned-component worker readers before and after the fence. Distinguish those checks from installed-generation acceptance. A startup format fence cannot prove an already running physical writer stopped.

For embedded producer collections, build paged metadata beside the canonical write and bind it to that record's revision. Upgrade historical producers through the owning central migration; forbid complete body reads in steady metadata and byte windows. Export canonical evidence rather than local SQL revision indexes, rebuild target metadata during authorized activation, and test a different target revision plus injected derived rows.

For native file capture, use canonical streamed pages and a disk inventory instead of raising whole-manifest limits. Verify native identities before any object export as well as after capture; a parent replaced during enumeration must export no outside bytes. Resolve future cache placement through canonical ancestors before creating it, and prove rejected overlap leaves source entries and timestamps unchanged. Restore through private staging, measure filesystem name equivalence and reject corruption or cancellation before empty-destination publication. The caller still owns physical exclusion and durable retention.

Bind aggregate file ports to the original physical lease issued only within its exact drained capture callback. Test pending acquisition, another binding, deferred callback use and release independently; a persisted file receipt or held Session epoch cannot grant native filesystem authority.

For bodyless field reads, guard the canonical Part and complete execution record independently; a small response does not prove small intermediate residency. Preserve complete canonical metadata and unknown fields while limiting only header presentation. Exercise a running Part whose original Rollout input arrives later without a Part write: resolve the existing native input locator, version the actual source selection and recheck it after a held range. Target rebuilding must follow canonical execution records and artifacts, not copied derived indexes.

Recovery authority-change evidence must join the real policy writer's native transaction. Select domain-owned redacted projections before composition seals, initialize their baseline through a central owning migration, and test rollback, missing coverage, unhooked mutations and retained credentials across upgrade. Current authorization remains canonical; hashes or history entries cannot grant access. A restored journal cannot certify its missing later interval or another writer cohort. Missing history requires current authorization re-establishment, not a replacement baseline that claims continuity.

Test artifact cancellation after a reader has acquired its pin and the canonical reference has been deleted. Close the iterator under the original aborted queue scope, then verify collection can reclaim the bytes. Pure in-memory pin release belongs to the original owner and must not require new queue admission; ordinary I/O retains cancellation checks.

## Migrate Existing Data

For optional components, keep canonical rewrites with the registered owner and give extracted work a new owner receipt. Preserve historical shared migration IDs and dependency nodes, but do not let a completed shared receipt skip delayed installation. Limit updates to verified owner fields; ordinary edits must retain unknown extension fields while public schemas hide unavailable kinds. Test core-only startup, delayed install, uninstall/reinstall, completed released receipts, partial interruption and destination collisions. Never replay destructive orphan cleanup as a catch-up. Keep installation-selection upgrades in the dependency-light pre-bootstrap path, retain old evidence and generations, and verify third-party pins, package locks and API4 grants with real archives.

When one retained owner can reference another optional source, project only copied owner fields and include selected source identities in derived-index fingerprints. Backfill source identity from exact canonical references; an orphan reference does not prove the default source. Keep metadata access upgrades separate from history preparation, and verify sidebar reads do not scan messages. Historical control-message, tool-part and Inbox requirements must be derived from confirmed owner records; update existing display versions with their canonical metadata transaction, preserve text and unknown fields, and test direct history HTTP access without first loading Session detail.

For aggregate configuration fields with optional child owners, contribute `storedShape` separately from the public `shape`; use `project` to hide unavailable child records before public validation. Preserve the stored/public difference across both merge and replacement writes, while validating incoming edits against selected owners. Cover current domain fragments and legacy monolithic input, global and project writes, public reads and exports, rejected edits to unavailable owners, and reinstall recovery. Normalization after parsing cannot protect records already stripped by a public schema.

Completing public configuration registration does not make retained storage strict. Keep unknown root fields and nested owner extensions on disk while projecting them out of public reads, including cold startup with legacy monolithic input. A delayed container upgrade must preserve explicit destination settings written while an owner was absent. Historical shared configuration receipts retain their IDs; extracted semantic conversions get an owner receipt and preserve unrecognized legacy fields. Publish destination files durably before removing migrated source fields, then verify interruption and repeated execution without replaying destructive cleanup.

Mark migrations that convert file configuration with `configuration: "files"`. Runtime excludes them after composition when an exclusive `ConfigSource` owns configuration, leaving their receipts pending for later local activation. Keep credential and cache conversions in separate migrations so exclusive hosting still upgrades non-configuration data. Test both source registration orders, mixed-domain tracking and the same Home reopening without the host source.

Choose migration execution independently of its data scope. New migrations must explicitly declare `startup`, `session`, `owner`, `record`, `after-convergence` or `maintenance`; `scope: session` alone does not mean lazy. Do not enumerate historical Sessions/operations, replay journals, decode message bodies or read artifact bytes to admit the application. Put owner transforms behind the central owner runner and pure compatibility transforms behind record access. Keep unknown recovery coverage durable and fence only its owner before execution; never replace unknown coverage with an empty clean index. Historical imports and full usage rebuilds require explicit resume/request, including old queued jobs. See [history admission](../../../docs/decisions/implemented/bug-fix/2026-10-10-history-work-outside-startup.md).

Optional owner metadata upgrades must also obey the startup history budget: use central per-Session receipts for metadata and pure record transforms for message reads. Exercise a populated component installation with pending and completed global receipts, then verify bounded Session reads, message/display agreement and atomic terminal extraction.

Test the first navigation after a composition change separately from startup and warm reads. Seed absent and partial outdated indexes, pending metadata receipts and thousands of unrelated owners; assert zero history traversal, a concurrent business writer admitted between metadata batches, complete canonical membership and retained activity. Input predicates must observe earlier dependency upgrades and leave no receipt for absent input. Keep historical recovery enrollment with explicit Session preparation. Pass only the declared owner fields to migration callbacks; internal dispatch tags can override record-kind filters when callbacks spread their input. Exercise storage failure, rollback, retry and the rendered sidebar error state so an unavailable snapshot cannot appear as data loss.

Exercise repeated catalog refreshes during real interaction with many archived owners. Use storage batch reads instead of unbounded per-record promises; simultaneous callers multiply reader admissions even when most records are filtered from the result. Test both a catalog larger than the admission queue and overlapping reads of a smaller catalog.

Test a released completion ledger with the new migration absent, interrupted and complete. Include both owner kinds, simultaneous requests, deleted owners, a corrupt cold owner and restart. Measure real read/scan counts on populated SQL stores; empty-home speed alone cannot establish bounded startup. Verify first-page work separately from full export/maintenance and retain original source evidence until its owner verifies the upgrade.

Register optional session fields, creation/import hooks and indexes through the owning package’s `session-schema.ts` before runtime startup. Keep the persistence reader tolerant of unloaded fields while public schemas expose only installed owners. Workflow session migrations stay with Workflows and preserve their historical `session` tracking ledger; moving ownership must not replay or discard migration history.

For immutable owner metadata, use Session schema mutation validation before publication, and declare parent inheritance only for the owner's own fields. Test rollback, changed or missing parents, conflicting child fields, unbound history, unloaded-owner edits and reinstall. Keep validation free of external effects because it runs in the retryable transaction; its detached input is evidence for a decision, not a mutation target. Imports and forks need their own authority checks rather than copying execution ownership automatically.

1. Add a migration whenever an existing persisted shape can reach the new code.
2. Make the migration deterministic and idempotent. Record dependencies and ordering explicitly.
   Identity renames must detect an occupied destination before discarding any source. Cover both key orders, permission maps and existing target files; publish renamed files without replacement, and preserve ambiguous definitions for explicit recovery.
3. Migrate to one canonical current path, then remove obsolete runtime adapters where the migrated state makes them unnecessary.
4. Keep compatibility readers only at a named boundary when migration cannot make old data impossible; do not spread legacy checks through business logic. For post-activation JSON checks, distinguish inert startup metadata from divergent business authority. Validate historical initializer schemas against canonical SQL state, preserve the original bytes, and never adopt legacy migration claims or grants. Test repeated and deferred startup, populated conflicts, changed files and read failures; do not use local data cleanup as the fix.
5. Preserve secrets and owner-only permissions. Never log raw credentials or include them in diagnostics fixtures. Apply credential owner checks inside serialized deletion and invalidation mutations as well as writes; background OAuth probes must clear only their own ephemeral verifier, never an interactive owner's persisted PKCE state. Revoke the previous authentication round before awaiting cleanup, and retain recovery exclusion until cleanup ends. A provider shared with ordinary header reads cannot use its last token read as an authentication-attempt identity; coordinate SDK authentication at an explicit operation boundary and capture a separate credential snapshot for that round. Compare the expected stored entry inside the mutation and advance that snapshot only after its own commit. Test late successful writes as well as rejected credentials against both a newer owner and a same-owner credential replacement.
6. Build old-state fixtures from schemas emitted by shipped writers. Do not use a synthetic superset of multiple historical variants as the only upgrade fixture.
7. Validate the historical fields a migration reads or rewrites, and preserve unrelated metadata when updating the record.
