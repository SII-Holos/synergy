# Digital Twin

Optional next-user-message prediction. The public component registers configuration, a hidden Agent and lazy preparation; the separate HTTP adapter contributes `POST /digital-twin/predict-next-input` and the `digital-twin` capability. `service` exposes independent recorded prediction and shutdown, and `contract` exposes validated request, result and settings schemas.

Full installations select this component. Core does not. Digital Twin depends on public Harness corpus/context APIs and Local Runtime, without a Library dependency. Configuration belongs to `35-digital-twin.jsonc`: `automatic` defaults to false and a null or absent `model` follows the current Session. No profile, training or source-selection setup is required.

The composer shows a suggestion only after a successful completed root and on an eligible empty draft. Tab inserts it, Escape dismisses it, and sending remains explicit. Generated suggestions stay saved locally across navigation and reload until accepted, dismissed, edited over or superseded by new work; restoration does not call the model. Manual prediction is available when automatic prediction is disabled. Accepted suggestions retain generic assistance metadata so subsequent predictions do not treat them as original voice.

Historical eligibility is not proof of authorship. Copied tasks in legacy user messages can pass the voice filter when paste/source metadata and recognizable quotation formatting are absent. New assistance provenance prevents known feedback loops but cannot establish who wrote older text. Evaluate the selected evidence as well as the predictions before claiming personalization quality.

Legacy history is scanned through the shared credential detector before use. Discovery completes across each selected context/evidence batch before masking, so a later recognized credential also protects earlier occurrences. Credential-bearing originals are excluded from voice examples and statistics. The registered-value revision withdraws old projections immediately and fences requests while background rebuilding runs. This does not claim complete recognition of unknown secret formats.

See the [decision record](../../docs/decisions/implemented/feature/2026-10-21-digital-twin-next-input.md) for ownership, provenance and quality constraints. Run focused tests with `bun test test` and type checking with `bun run typecheck`.

Run the optional offline evaluation against an isolated copy with `bun packages/digital-twin/script/evaluate.ts --home <isolated-parent> --output <private-directory> --model <provider/model> --judge <provider/model>`. It uses the configured provider infrastructure and makes paid model calls. Keep its private reports outside the repository.

The evaluator visits every eligible immutable historical continuation, freezes predictability before generating candidates, and compares context, voice and full recipes under identical generation settings. It excludes unverified history and preserves failed calls separately from emitted candidates. Source, corpus and model configuration hashes identify an experiment; each dispatched recipe is saved before invocation and after completion. Resuming never replaces an already dispatched sample. Reports include all cases, supplied evidence, category coverage, errors, paired uncertainty and provider receipts; absent usage fields stay unknown. The default batch has four independent cases after the first case, using normal model admission.

Ranked retrieval limits candidates after lexical matching and message deduplication. Voice projections load into a Runtime cache in background pages, then publish ready selections outside prediction requests and update by source events; source references and numeric statistics remain rebuildable. First use resumes unfinished work and reconciles owner metadata once, including history changed while the component was absent. Preparation and cache loading obey the shared background pause gate. Online and temporal recipes share scoring, fragment boundaries, identity tie-breaking, family diversity and representative budgets. Replay spends the raw query budget before eligibility filtering, using source-attributed ordinary text from immutable native requests; its conservative availability time is the first recorded observation. Missing membership, deletion and rollback history remain reported catalog gaps, so these results describe reconstructable history rather than the complete live corpus. Reports show each recipe's content and voice denominators, separate successful and failed latency, and actual provider timing and cache fields. Historical material without immutable provenance is excluded, so replay evidence coverage is reported separately from the live corpus.
