Apply a complete text patch to the selected Workspace. Read existing source files with read first. Permissions remain unchanged.

Pass an object with patch containing exactly one document:
*** Begin Patch
*** Add File: notes.txt
+New text
*** Update File: source.ts
@@
-old text
+new text
*** Delete File: obsolete.txt
*** End Patch

An Update may contain *** Move to: destination immediately after its header, with or without text hunks. Destinations must be absent; move parents must exist. Prefix unchanged lines with a space, removals with -, and additions with +. Each @@ hunk needs unique exact original context, including whitespace. An optional @@ followed by a space and an exact anchor line narrows the following hunk. *** End of File may finish the final hunk and requires a match at the actual tail; insertion without context requires this marker.

Relative paths resolve in the selected Workspace. Existing files must be regular UTF-8 text and unchanged since your read. The whole patch is validated and authorized before any target changes. Duplicate/aliased paths, overlapping hunks, malformed documents, binary files, symlinks, stale reads and ambiguous matches are rejected. Updates preserve BOM, unchanged line endings and terminal-newline state. Add uses LF and a terminal newline unless empty.

Sections commit in order with version checks. This is not a multi-file transaction: a failure or cancellation stops remaining work and does not roll back earlier effects. Results identify committed, failed, not-started, unknown and unsaved stages, including update-before-move failures. Inspect partial/unresolved results and current files before issuing a new patch; never replay the whole patch to retry an uncertain operation.
