Apply a complete text patch to the selected Workspace. Read existing source files with read first. Permissions remain unchanged.

Pass an object with patch containing exactly one document:
*** Begin Patch
*** Add File: notes.txt
+New text
*** Update File: source.ts
@@
-old text
+new text
*** Delete File: obsolete.txt
*** End Patch

An Update may contain *** Move to: destination immediately after its header, with or without text hunks. Add replaces the whole file if it exists. Move may replace an existing destination and create missing parent directories. Read every existing file that will be changed or overwritten, including a Move destination.

Prefix unchanged lines with a space, removals with -, and additions with +. Use @@ between hunks, or @@ followed by a context line to search after that anchor. Put hunks in original source order. Matching prefers exact lines, then ignores trailing whitespace, then leading/trailing whitespace, then common Unicode punctuation and space variants. Each tier selects the first matching span after the previous hunk, so include enough context to target the intended occurrence. A hunk with only + lines appends at EOF. *** End of File constrains a hunk to the actual tail. The first hunk may omit @@; bare blank context lines and whitespace around structural markers are accepted.

Relative paths resolve in the selected Workspace. Existing files must be regular UTF-8 text and unchanged since your read. The whole patch is validated and authorized before any target changes. Duplicate/aliased or dependent paths, overlapping/out-of-order hunks, malformed documents, binary files, symlinks and stale reads are rejected. Updates preserve BOM, unchanged line endings and terminal-newline state. Add uses LF and a terminal newline unless empty.

Sections commit in order with version checks. This is not a multi-file transaction: a failure or cancellation stops remaining work and does not roll back earlier effects. Move writes its destination before deleting its source; a failed source deletion can leave both files. Results identify each operation's path and committed, failed, not-started, unknown or unsaved state. Inspect partial/unresolved results and current files before issuing a new patch; never replay the whole patch to retry an uncertain operation.
