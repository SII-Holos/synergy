Send an actionable user message to a session. The target session's agent will process and respond to the message.

A target already running a task joins the message to that task's next model call, whoever sends it, without interrupting a tool or model request already in progress. Any other target queues the message as a new task, which starts after the current task finishes; a paused session stays paused and cancellation is never overridden. A steer that the target's task ends without reading is parked as a failed delivery — resend it.

The target history records the message as forwarded from the sending session while preserving the supplied content as the target's user request.

The result reports the admitted mode and queue/message IDs. Queue admission is not confirmation that the target has read or acted on the message.

The `target` parameter identifies which session to send to:
- A session ID (e.g. "ses_xxx") to send to a specific session

Only `role: "user"` is supported. Omitting `role` defaults to `user`. Calls with `role: "assistant"` are rejected; retry them with `role: "user"`.
