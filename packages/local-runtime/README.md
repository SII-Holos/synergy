# Local runtime

`@ericsanchezok/synergy-local-runtime` composes the harness with local filesystem/process tools, workspace handling, skills, commands and interactive questions. It does not import the HTTP server or desktop product modules.

`openLocalRuntime({ mode: "oneshot" })` registers local capabilities and acquires the harness lifecycle handle. Await `close()` or use `await using` to drain sessions, worker pools, child processes and telemetry before releasing the isolated home. Lifecycle implementation belongs to `@ericsanchezok/synergy-harness/lifecycle`.

`createLocalClient(handle, { scopeID })` (or an explicit directory selector) provides the session, event, permission and question operations used by the CLI. The client enters its supplied Runtime and resolves its Scope for each operation. HTTP routes delegate session creation, input and command submission to the same `session-api` functions; remote CLI calls continue to use the SDK.

Question keeps native pending requests and resolves them through `Question.decide`. The first committed answer retains its actor in Session-owned decision receipts; private answers are redacted there and in lifecycle events while the native caller receives the original. An outer admission rollback preserves the pending request.

Run `bun test test/client.test.ts` for the in-process Scope/event contract and `bun run typecheck`. Tests use the isolated home preload declared in `bunfig.toml`.

Package entrypoint contracts are verified by `bun test test/component.test.ts test/cli/scope.test.ts test/skill/summary.test.ts test/workspace/relocation.test.ts`: selected worker registration, Home reload wiring, CLI Scope cleanup, discovered skill summaries and copied Git metadata independence.

`registerLocalRuntime()` also registers bundled model SDK factories and the custom SDK loader. Agent worker bootstrap creates an explicit Runtime context, registers local capabilities, then starts the harness runner.

Local Runtime registers the native processor for Harness's `AttachmentImageInput`. The codec loads only when a model request contains local image bytes. Original Assets stay immutable; model copies follow the shared image budget, and decoding failures become individual image placeholders. See [Assets and attachments](../../docs/architecture/session-and-messages.md#assets-and-attachments).

Source workers launch this package’s `src/agent-worker.ts` through the harness worker-entry registration. The full product registers its own entry; compiled executables dispatch the same composition through `__agent-turn-runner`.

Native execution belongs here: `process/pty`, `file/watcher`, and the macOS/Linux/Windows sandbox backends and helper sources. `registerLocalRuntime()` registers the sandbox host and the file-watcher startup contribution before commands or workers execute. Build sandbox helpers with `bun script/build-helper.ts`; Linux bwrap development setup uses `bash script/download-bwrap.sh`.

Trusted host workers use `OwnedProcess.prepare({ ownership, ... })` from `process/owned-process`. Its ownership callback receives an immutable native process-tree reference before activation. Persist that reference before returning from `bindProcess`; verify exit in `release` before relinquishing the host claim. `OwnedProcess.inspect` preserves uncertainty after lost supervisors and `terminate` addresses only the recorded tree. Completion receipts remain available during release and are removed afterward. Workspace commands supply their real access lease through the same ownership interface. Validate standalone workers with `bun test test/process/host-worker.test.ts` and Linux tree proof with `test/process/owned-process-linux.test.ts` on Linux.

Supervisor startup follows the selected Runtime environment described in [Execution boundaries](../../docs/architecture/execution-boundaries.md). Verify launcher, working-directory and command-environment isolation with `bun test test/process/supervisor-environment.test.ts` on each supported OS.

Explicit JITless execution uses Bun's bundled C compiler to bind the same packaged native libraries; ordinary execution uses Bun's engine FFI. Neither mode requires a separate compiler at execution time. `bun test test/process/native-bindings.test.ts` checks file publication, process ownership and PTY output in both modes.

Human PTYs use the composed Host origin and retain their own process lifetime. Existing resource frames must still pass original-owner admission through preparation; a Session label is not a native Task identity. Verify `test/process/pty-origin.test.ts`; see [shared process ownership](../../docs/decisions/implemented/architecture/2026-11-12-keep-shared-processes-under-explicit-host-origins.md).

Local Runtime registers a borrowed native Environment provider without allocating resources. `localRuntime({ environment: false })` omits it for embedded compositions that supply other providers. `environment: "native"` registers only the explicit native default and omits personal Environment profiles and their resolver. The native Executor shares process ownership and Workspace coordination with local tools; see [Environments](../../docs/architecture/environments.md). Validate it with `bun test test/environment test/workspace/coordinator.test.ts`.

Native deallocation resolves exact mounted paths from their original native receipts and acquires the existing Workspace retirement claims before publishing its release intent. Those claims cover final object saving, detach and idle publication if Runtime maintenance starts later. New release admission remains blocked. Remote providers retain their own physical ownership; controller paths do not prove remote exclusion. Verify `test/workspace/mount-maintenance.test.ts`.

Hosts opening a `NativeExecutor` directly supply a `WorkspaceCoordinator` from `workspace/coordinator`. Cooperating native executors use the same host claim directory; isolated test runtimes use a private one. Execution input staging and sandbox cleanup stay with this executor through saved completion. Protocol version 2 uses explicit resource pins separately from managed mutation paths and Sandbox policy; update the Execution Host image together with its client. The `localRuntime` composition factory forwards the same optional coordinator to the canonical registration owner; omission keeps host-wide coordination. A physical-machine fixture shares one private coordinator or directory across its cooperating Runtimes.

`registerDockerEnvironment({ endpoint })` registers a managed Docker provider in the composing Runtime. Local Unix sockets and remote TLS Docker Engine endpoints use the same lifecycle. `ExecutionHost.listen` and `RemoteExecutor` expose the same Executor through authenticated Unix sockets or HTTPS. Build the separate execution image with `bun run build:execution-host`; run its real allocation test with `SYNERGY_TEST_DOCKER_ENVIRONMENT_IMAGE=synergy-execution-host:development bun test test/environment/docker.test.ts`. Pass `--arch x64` or `--arch arm64` to build for a specific Linux target. The image contains a process supervisor, native ownership library, verified file watcher and Linux sandbox helper, without an Agent Runtime or Agent database. The Docker host must support unprivileged user namespaces and nested bubblewrap; incompatible kernel or security-module policies fail contained commands.

`environment/docker` exports `dockerEnvironmentHostConfig()` for a privileged Engine broker to validate the exact confinement policy used by the provider. Hosts validate the image, allocation identity, resource limits and mount selection independently; the helper grants no Engine access.

Trusted host composition can supply `engineTransport` and `executorTransport` to `dockerEnvironment`. Each receives the complete Request, including deadline, body, allocation target and authentication; it owns the authenticated network hop and must honor cancellation. Allocation, incarnation checks, credentials, Workspace save and release still belong to the provider. A failed custom transport never falls back to a direct Engine or Executor connection.

On Docker hosts with AppArmor enabled, load the supplied `src/environment/vendor/synergy-execution.apparmor` using `sudo apparmor_parser -r <profile-file>` on the daemon host before allocation. Synergy selects its `synergy-execution-v1` profile automatically; a missing profile fails allocation. The policy permits the inner sandbox's mount operations while preserving Docker's other AppArmor restrictions. The runtime does not install host policies or disable AppArmor.

The `workspace/blob-store` export supplies `s3BlobStore` and `ossBlobStore` for Harness `WorkspaceBlobs` registration. Their credential callbacks allow the host to rotate credentials without persisting them in Workspace specs. Classic and anchored file tools select dormant object or active Executor views through the same file facade; file-only object edits allocate no compute. Validate signing, bounded reads, checkpoint materialization and source-loss restoration with `bun test test/workspace/blob-store.test.ts test/workspace/tree.test.ts`.

Coding reads and searches use shared display budgets; anchored edits return compact final-file previews with full UI diffs. See [workspace file architecture](../../docs/architecture/workspace-and-files.md). The fixed-input observation probe at `test/tools/coding-observation-probe.test.ts` can emit versioned UTF-8 byte measurements through `SYNERGY_OBSERVATION_REPORT`; it does not invoke a model or estimate token savings.

Selective hosts call `registerLocalToolInputHistory()` from `./tool-input-history` while composing their tool catalog. This retains owned input migrations without registering native providers or product tool groups.

Local Runtime registers the native directory Host for [paused Session transfer](../../docs/architecture/session-transfer.md). It captures under Workspace coordination, rejects Runtime-data overlap and linked Git metadata, and materializes a verified private directory before publication.

`NativeWorkspacePortableTree` captures complete files through canonical portability pages with a disk inventory and bounded file buffers. It validates the entire source before exporting content, preserves exact bytes, links and modes, and restores through a private directory with measured filesystem path-equivalence checks. Its caller supplies physical ownership and storage retention. `workspace/portable-git` substitutes independent sanitized Git metadata for the top-level `.git`, preserving refs, objects, HEAD and staged index while excluding source credentials and executable configuration. Working-file credentials still block capture. Unsupported Git dependencies fail before surrender. Verify `test/workspace/{portable-tree,portable-git,portable-tree-git}.test.ts`; see [streamed native trees](../../docs/decisions/implemented/architecture/2026-11-12-stream-native-workspace-trees-through-portable-pages.md) and [independent Git preparation](../../docs/decisions/implemented/architecture/2026-11-12-materialize-independent-git-workspaces-for-native-transfer.md).

`workspace/portable-target` prepares private native destinations with a durable exact intent and verified receipt. It retains exclusive directory ownership inside its explicit publication callback without publishing a catalog during preparation. `NativeWorkspacePortableTree.verify` measures actual bytes, including Git configuration, through a local checksum sink. Verify `test/workspace/portable-target.test.ts`; see [private native preparation](../../docs/decisions/implemented/architecture/2026-11-12-prepare-private-native-workspace-destinations.md).

Workspace composition registers the private target Host alongside the source Host. Selecting `SessionTransferWorkspaces.register()` composes the native file owner. Mapped catalogs publish under native directory ownership across the existing Session epoch transaction. This selection keeps the production organization controller disabled. Verify `test/workspace/session-workspaces-transfer.test.ts`; see [native Workspace publication](../../docs/decisions/implemented/architecture/2026-11-12-publish-native-workspace-mappings-with-session-epochs.md).

`NativeSessionTransferPhysical` retains exact native Workspace claims for a canonical source cohort. It drains accepted Session process output and file finalizers, checks actual installed writer ownership, rejects unknown retained native writers and keeps physical roots held through source publication. Nested file capture borrows the original native parent claim. Its synchronous assertion complements the source epoch verifier; releasing it never resumes execution. Run `bun test test/workspace/session-{transfer-access,physical-transfer}.test.ts`; see [native source claims](../../docs/decisions/implemented/architecture/2026-11-12-bind-native-source-claims-to-exact-session-cohorts.md).

Aggregate file owners obtain that same original lease through `sourceCapture(binding)` only in the exact open capture. `assertSource()` checks the native lifetime during capture and retained ownership; pending or released owners and escaped capture callbacks cannot grant it. File candidates additionally retain `sourceCaptureVerifier(binding)`, which binds one actual successful callback attempt and cannot revive after failure or a later retry. Verify `test/workspace/{session-physical-transfer,workspace-source-export}.test.ts`; see [attempt-bound file proof](../../docs/decisions/implemented/bug-fix/2026-11-12-bind-native-file-proof-to-capture-attempt.md).

Local Workspace composition also contributes native process maintenance. Runtime-owned `OwnedProcess` preparation obeys canonical admission, then remains tracked through actual tree, output and ownership-release completion. Maintenance waits without killing or replaying commands and refuses retained current-Home physical claims even when the resident set is empty. Unconfirmed native starts or cleanup require reconciliation. This does not replace remote/resource or Workspace mutation owners. Run `bun test test/process/maintenance.test.ts test/process/owned-process.test.ts`; see [native process maintenance](../../docs/decisions/implemented/architecture/2026-11-12-drain-native-process-ownership-for-maintenance.md).

Native Workspace leases expose `isReleased` from their exact coordinator ledger identity and token. A resolved release call can leave a live process retained; a later canonical checkpoint acknowledgement can release the same physical claim through a recovered lease object. Harness claim maintenance follows that physical evidence while keeping native finalizers and unknown failures separate. Run `bun test test/workspace/access-maintenance.test.ts test/workspace/maintenance.test.ts`; see [native claim drainage](../../docs/decisions/implemented/architecture/2026-11-12-drain-workspace-claims-through-native-release-evidence.md).

The native mount maintenance fixture exercises real file-host receipts through attach/detach admission, cancelled transition waits and lost acknowledgements. It rejects implicit recreation from an orphaned preparing record or replacement of a pending save. Run `bun test test/workspace/mount-maintenance.test.ts test/workspace/operations.test.ts`; see [mount evidence](../../docs/decisions/implemented/architecture/2026-11-12-reconcile-workspace-mounts-from-original-native-evidence.md).

`workspace/file-host` materializes and imports paged saved heads through the canonical portable reader and native materializer. Private preparation applies native ownership and verifies complete content before no-replace publication. A pending mount records its original prepared directory identity for cold reconciliation; equal bytes cannot authorize another directory. Materialization requires an absent destination and never retires an existing directory, even if empty. Verify `test/workspace/{file-host-paged,file-host,tree,portable-tree}.test.ts`; see [paged native FileHost](../../docs/decisions/implemented/architecture/2026-11-12-materialize-paged-heads-through-native-file-host.md).

`file/view` browses and reads dormant paged object heads through the canonical Workspace callback index. Metadata-only operations fetch no file bodies; range and observation reads retain one immutable tree and the original range. Verify `test/workspace-file/{paged-view,selected-view}.test.ts`; see [selected paged files](../../docs/decisions/implemented/architecture/2026-11-12-read-selected-workspace-files-through-paged-indexes.md).

Bash, the tool resolver and user shell carry their canonical Session/root/Run/tool origin into Environment execution. A paused Task cannot first dispatch after its native connection completes; confirmed original no-effect cancellation settles through normal saving and release. Verify `test/environment/bash.test.ts` and `test/session/{shell,tool-resolver-bash-profile}.test.ts`; see [operation origins](../../docs/decisions/implemented/architecture/2026-11-12-retain-native-environment-operation-origins.md).

Native checkpoints, before-images and managed file imports use the same disk-indexed portable inventory. Checkpoint policy preserves native receipt bytes, including sensitive paths; transfer capture retains its separate exclusion policy. Harness saves and preserves each complete paged graph before acknowledging the original receipt. Selected Snapshot restoration reads only requested original headers. Verify `test/workspace/{mount-paged,execution-recovery}.test.ts` and `test/workspace-file/{restore-paged,restore-origin,managed-transfer}.test.ts`; see [paged Workspace producers](../../docs/decisions/implemented/architecture/2026-11-12-write-paged-workspace-heads-through-indexed-chunks.md).

The singular `session-transfer-workspace` Host remains registered for the public version-one Session export, with its fixed legacy Workspace tree, existing 100,000-entry and 64 MiB archive limits. Its capture retains native `WorkspaceAccess.exclusive` even without an aggregate capture frame. The aggregate `session-transfer-workspaces` owner uses the paged protocol separately. Verify the actual version-one prepare/export with `test/workspace/producer-compatibility.test.ts`.

The Native provider describes only its strict empty spec. `SessionTransferEnvironments` reader two retains canonical completed operations and every saved output frame while requiring a compatible target catalog entry. Historical source targets do not create allocations, mounts or Uses. Verify `test/session-transfer-environments-native.test.ts` and `test/session-transfer-environment-history.test.ts` for actual two-Home publication, rollback, rehashed corrupt packages and unchanged private facts. Active operations and cloud mapping consent remain unavailable; see [completed history](../../docs/decisions/implemented/architecture/2026-11-12-transfer-completed-environment-history-through-native-owners.md).

`workspace/move` supplies the registered native source for Harness `WorkspaceMove`. Final capture borrows an actual retained source frame when present and retains its own durable exclusive claim through publication or unknown outcome. Cold recovery uses the native provider's original owner, token and unchanged physical roots. It reuses portable Git capture and the existing streamed tree, blocks Runtime data and unmapped writable locations, and leaves source directories intact. Verify `test/workspace/move.test.ts`; see [retained Workspace moves](../../docs/decisions/implemented/architecture/2026-11-12-publish-native-workspace-moves-with-retained-range-receipts.md). The `workspace/native-adoption` export binds explicit existing-directory selection to the original Move request, complete difference consent and final Core/Epoch publication. It preserves the target version and releases native claims outside SQL. Verify `test/workspace/native-adoption.test.ts`; see [existing native adoption](../../docs/decisions/implemented/architecture/2026-11-13-adopt-existing-native-workspaces-through-original-handoff-claims.md).

`file/view` also consumes registered dormant remote file sources for ordinary tools and the canonical file service. Metadata, links, ranged reads, observations and mutations retain one logical lease; the provider owns remote identity and CAS. Remote writes use Harness operation receipts, retain unknown outcomes and reconcile original IDs after restart without copying a head into this Runtime. Verify `test/workspace-file/remote-source.test.ts` with the selected-view and ordinary workspace-file tool suites; see [remote file sources](../../docs/decisions/implemented/architecture/2026-11-12-route-dormant-remote-files-through-owned-workspace-sources.md).

`file/atomic-write` retains original root and descendant directory descriptors for private atomic replacement. The caller verifies its domain authority after opening and before effects. Unsupported native targets fail before source retirement; the helper grants no Home authority. Verify `test/file/atomic-write.test.ts` and `test/process/native-bindings.test.ts` in both JIT modes; see [service recovery publication](../../docs/decisions/implemented/architecture/2026-11-12-publish-service-only-recovery-after-current-policy-and-native-completion.md).

The physical cohort inventory retains exact metadata for registered remote Workspace sources. It drains the same Session and process owners while the remote capture provider supplies its service snapshot; a pathless Locator gains no native directory claim. See [keep-cloud return](../../docs/decisions/implemented/architecture/2026-11-12-retain-live-workspaces-through-return-handoff.md).

Native Move hosts require the actual writable primary and its existing Bootstrap dataset header; manually composed fixtures must supply that owning metadata. A retained release checks the original namespace, claim token, Host and physical ledger without borrowing authority over a replacement directory. Capture and preparation still validate the current physical directory. See [native cleanup ownership](../../docs/decisions/implemented/architecture/2026-11-13-own-revoked-target-cleanup-through-original-handoff-evidence.md); verify `test/workspace/{move,native-adoption}.test.ts`.

`workspace/cleanup` reads an existing native Host identity and registers only the retained WorkspaceMove release owner. It is mutually exclusive with full source registration and cannot prepare or capture a directory. See [restricted cleanup](../../docs/decisions/implemented/feature/2026-11-13-reconcile-original-machine-targets-through-a-restricted-cli.md).
