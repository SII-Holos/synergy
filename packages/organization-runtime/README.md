Its historical machine identity and signed command metadata remain evidence, while fresh execution and Continue require their separate owners. Real HTTPS/WSS acceptance preserves the private Home and checks restored bytes and current access. The member adapter provisions a stable, dedicated Home for an organization, account and device, enrolls its machine identity, and opens an explicitly selected Agent Runtime. Enrollment and startup do not grant Session execution authority.

`prepareMemberHome({ baseDirectory, identity, origin })` requires an absolute managed base directory and an exact HTTPS origin. The directory key hashes the three identity fields, independent of the service address. Existing personal directories and symbolic-link Homes are refused. Provisioning publishes the generic Harness ownership marker before any Runtime initialization, then durably records its initial state and machine key. Interrupted initial provisioning resumes with the same key. Established identities with missing, mismatched or unsupported records fail closed.

`readMemberHome(home, identity)` returns public binding metadata only. The Ed25519 private key stays in the Home's private credential file. `enrollMemberRuntime({ home, identity, ticket, ca?, signal? })` verifies the ticket's organization, account, device and public key before signing its registration proof. The request uses verified TLS, a dedicated connection pool, no ambient proxy, no browser credentials and no redirects. A supplied CA adds explicit deployment trust without disabling certificate verification.

The `./home` and `./registration` metadata entries support Node hosts as well as Bun without importing the Agent lifecycle or requiring Bun ambient types. Desktop can provision the dedicated Home and read its public enrollment before an installed launcher prepares its module generation. Both hosts use the context-free Harness `HomeOwnershipFile` entry with the same ownership records, bounded metadata reads and atomic private writes. Positive test-home detection runs before any provisioning lock or directory write; this does not make Agent execution available in Node.

The machine-key directory uses the standard sensitive-path classification and sandbox credential protections described in [execution boundaries](../../docs/architecture/execution-boundaries.md).

The ticket is not persisted. Only public registration metadata is saved after the service returns a matching active receipt. Lost responses can be retried with the same ticket while it remains available; the service's immutable receipt prevents duplicate activation. `readMemberRegistration(home, identity)` from `./registration` reads this local cache, which never substitutes for current service authorization. Changed deployment or Runtime identities require explicit recovery.

`openMemberConnection({ home, identity, buildVersion, ca?, signal?, connectTimeoutMs? })` opens the machine's outbound WSS bridge using its persisted identity. It signs a fresh proof and declares bridge capability; an explicit `commands` receiver factory additionally declares command support after binding the verified handshake and connection cancellation signal. A verified matching handshake persists the connection epoch before returning. If the server has advanced beyond a lost local acknowledgment, the adapter reconciles that higher epoch and retries once. A lower epoch or changed identity requires explicit recovery; neither service nor local snapshots can silently rewind the checkpoint.

The handle exposes the acknowledged `connected` metadata, a `resources` client, a `closed` result and async `close()`/disposal. Heartbeats validate epoch and sequence, expiry reports offline, and shutdown drains owned checkpoint, command and resource work. Already-received protocol errors survive an immediately following socket close. Frame validation stays ordered; command callbacks use separate bounded execution and reconciliation windows so a pending control cannot block heartbeats or receipt queries. Capacity refusal keeps the connection available. Cancellation reaches file-lock waits, so stopping a connection does not wait for another owner to release a checkpoint lock. See [online forwarding](../../docs/architecture/organization.md#online-command-forwarding) for window and ordering rules.

`resources.retention/describe/bind/release/reserve/inspect` signs native proofs through the verified connection's machine key. `resources.invoke` accepts only a service-signed fixed HTTP connection capability, sends bounded JSON to the configured service route and retains capacity until the response body drains or cancellation. `resources.invokeMcp` accepts only a service-signed MCP HTTP/SSE capability, sends one strict list or tool operation and parses the bounded JSON result. The `commands` factory receives this client as its third argument. It uses generated HTTP methods and the deployment's verified CA, validates response identities and capability signatures, and cancels pending calls when the connection ends. Reconnect creates a fresh client; explicit queries can inspect the original call without replay. Retention inspection reconciles an uncertain bind without reacquiring resources, including when resource availability changes. Release verifies the returned root, generation, materialization evidence and outcome. See [resource control](../../docs/decisions/implemented/architecture/2026-11-09-own-member-resource-control-by-connection.md), [fixed HTTP member invocation](../../docs/decisions/implemented/architecture/2026-11-09-member-fixed-http-connection-client.md) and [MCP business connections](../../docs/decisions/implemented/architecture/2026-11-09-forward-organization-mcp-connections.md). The resident command factory supplies this client to native execution preparation and the durable release observer.

Member compositions replace the personal SDK loader with fixed OpenAI-compatible and Anthropic-compatible factories. A factory requires a prepared one-call capability and the verified connection's public deployment context; it verifies the signature, provider target and start window before transmission. It retains Harness fetch recording and timeouts while enforcing deployment TLS, omitted cookies, direct transport and rejected redirects. SDK reuse cannot resend a capability. Portable model metadata contains no upstream key or endpoint, and unclassified billing remains unknown. Actual workers consume this interface after native Session and per-call preparation; primary and derived calls retain the canonical root. See [model gateway](../../docs/architecture/organization.md#model-gateway).

The command intake owner validates signed creation, bounded text input, pause, Continue and cancel, then commits its receipt with the native effect. New task and steer input wakes the native scheduler after commit; context and replay do not wake it. Creation retains the signed actor as creator. Member creation uses the explicitly bound project default Workspace and dormant native Environment; old Sessions keep their own selections. The local binding APIs return safe summaries and compare-and-set the existing Scope without changing project identity. Logical-effect deduplication is separate from terminal attempts, ordered skip proofs and durable reception sequences. Controls enter the canonical Session Scope; Continue joins native admission after draining execution and verifies both pause time and control version. Cancel binds a run and observed control version, publishes its receipt after native commit and retains its callback and control lock through drainage. The receiver requires a verified connection, preserves current tools on pause and does not authorize user roles or allocate model capabilities. Receipt queries observe cancellation activity separately through native bounded evidence, rechecking binding and control versions without recovering execution. The resident bridge binds all intake callbacks to its Agent Runtime context. Standalone provisioning connections omit this capability unless explicitly supplied a receiver. See [Runtime command intake](../../docs/architecture/organization.md#runtime-command-intake) and `test/command-intake.test.ts` for restart, rejection, rollback and race coverage.

`openMemberRuntime({ home, identity, environment?, entry?, listen?, desktop?, ca?, signal? })` requires an enrolled, matching Home. It reuses Agent Runtime bootstrap with explicit features, a process lock and independent storage. Without `listen`, it opens in one-shot mode without a listener, eager workers or resident recovery. `listen: { port, token }` selects the existing Server component and resident lifecycle on `127.0.0.1`; the port must be an explicit integer from 1 through 65535, and the private bearer credential must encode 32 random bytes as lowercase hexadecimal. The credential stays in the owning Runtime environment and protects health and business routes. Failed startup releases that Runtime's listener and storage ownership. Library, Memory and plugins are unselected. Member composition selects the explicit native Environment provider without personal profile resolution; hosted composition omits native execution. `SessionExecutionSource` admits accepted native tasks with resource descriptors; `ProviderRequestSource` binds each canonical root/Run and reserves its finite model capability. The resident connection tools bind selected fixed HTTP or MCP resources to the same accepted root and reserve a separate one-call capability. The MCP tool lists remote tools before calling a selected name and keeps endpoint and credential data out of model-visible results. Admitted Cortex descendants reuse the accepted ancestor grant identity after lineage verification; unsupported connection protocols, unadmitted children and offline preparation remain denied. See [native execution](../../docs/architecture/organization.md#member-native-execution), [Cortex lineage](../../docs/decisions/implemented/architecture/2026-11-09-authorize-member-cortex-lineage.md), [fixed HTTP native tool](../../docs/decisions/implemented/architecture/2026-11-09-member-fixed-http-native-tool.md) and [MCP business connections](../../docs/decisions/implemented/architecture/2026-11-09-forward-organization-mcp-connections.md).

`desktop: { browserToken }` explicitly selects the existing Browser component for a listening `desktop-managed` or `dev-desktop-managed` member. The resident composition owns one outbound bridge and reconnect delay. Remote availability does not block local HTTP readiness. Transient disconnection and explicitly retryable availability errors use exponential backoff with jitter, capped at thirty seconds; a connection surviving its negotiated offline interval resets the backoff. Replacement, revocation, protocol mismatch and local identity failures stop automatic reconnect. Shutdown aborts an in-flight handshake or delay and drains pending checkpoint writes before releasing storage. The private supervisor request's CA applies to enrollment and resident WSS. A cached enrollment record never grants live execution authority. See the [resident bridge decision](../../docs/decisions/implemented/architecture/2026-11-08-member-resident-bridge.md).
