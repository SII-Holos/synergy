# Organization Runtime adapter

The member adapter provisions a stable, dedicated Home for an organization, account and device, enrolls its machine identity, and opens an explicitly selected Agent Runtime. Enrollment and startup do not grant Session execution authority.

`prepareMemberHome({ baseDirectory, identity, origin })` requires an absolute managed base directory and an exact HTTPS origin. The directory key hashes the three identity fields, independent of the service address. Existing personal directories and symbolic-link Homes are refused. Provisioning publishes the generic Harness ownership marker before any Runtime initialization, then durably records its initial state and machine key. Interrupted initial provisioning resumes with the same key. Established identities with missing, mismatched or unsupported records fail closed.

`readMemberHome(home, identity)` returns public binding metadata only. The Ed25519 private key stays in the Home's private credential file. `enrollMemberRuntime({ home, identity, ticket, ca?, signal? })` verifies the ticket's organization, account, device and public key before signing its registration proof. The request uses verified TLS, a dedicated connection pool, no ambient proxy, no browser credentials and no redirects. A supplied CA adds explicit deployment trust without disabling certificate verification.

The machine-key directory uses the standard sensitive-path classification and sandbox credential protections described in [execution boundaries](../../docs/architecture/execution-boundaries.md).

The ticket is not persisted. Only public registration metadata is saved after the service returns a matching active receipt. Lost responses can be retried with the same ticket while it remains available; the service's immutable receipt prevents duplicate activation. `readMemberRegistration(home, identity)` reads this local cache, which never substitutes for current service authorization. Changed deployment or Runtime identities require explicit recovery.

`openMemberConnection({ home, identity, buildVersion, ca?, signal?, connectTimeoutMs? })` opens the machine's outbound WSS bridge using its persisted identity. It signs a fresh proof and declares only the implemented bridge capability. A verified matching handshake persists the connection epoch before returning. If the server has advanced beyond a lost local acknowledgment, the adapter reconciles that higher epoch and retries once. A lower epoch or changed identity requires explicit recovery; neither service nor local snapshots can silently rewind the checkpoint.

The handle exposes the acknowledged `connected` metadata, a `closed` result and async `close()`/disposal. Heartbeats validate epoch and sequence, expiry reports offline, and shutdown drains owned checkpoint work. Already-received protocol errors survive an immediately following socket close. Frame and queued-window validation reject unsupported input. Cancellation reaches file-lock waits, so stopping a connection does not wait for another owner to release a checkpoint lock.

`openMemberRuntime({ home, identity, environment?, signal? })` requires an enrolled, matching Home. It reuses Agent Runtime bootstrap with explicit features, a process lock and independent storage. Its Local Runtime selection has no execution Environment, listener, eager workers or resident recovery. Library, Memory, plugins and Desktop capabilities are unselected. `SessionExecutionSource` rejects execution until organization command admission is implemented. The outbound bridge has its own lifecycle; a cached enrollment record never grants live execution authority.

The host environment retains only operating-system executable lookup and locale settings and rebinds Home/XDG/application paths to the member Home. Configuration and model catalogs use exclusive empty host sources; global, inline and project configuration files cannot select private providers or instructions. Instructions load only from the explicitly selected Scope/Workspace, and filesystem/bundled Skill discovery is disabled. Organization resource configuration and published Skill sources belong to their later owners. Agent and policy workers carry the public identity and the same sources, and verify the persisted Home owner before readiness. See [member composition](../../docs/decisions/implemented/architecture/2026-11-08-member-runtime-composition.md).

Run `bun run typecheck`, focused `bun test test/home.test.ts test/enrollment.test.ts test/connection.test.ts test/runtime.test.ts`, or `bun run test:coverage`. The tests use isolated Homes, real organization storage, HTTPS/WSS listeners with a test-only certificate, and actual Agent/policy worker processes. Desktop supervision, organization command admission and Session coordination remain separate adapter responsibilities.
