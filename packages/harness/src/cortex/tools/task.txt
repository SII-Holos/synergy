Delegate one coherent, independently verifiable deliverable to a specialist agent.

Available agent types:
{agents}

Use for independent ready work or specialist tasks; handle quick actions directly. Do not delegate work needing immediate user back-and-forth. Resolve design decisions before dependent implementation, or assign a bounded investigation explicitly. Include goal, settled decisions, evidence, scope, deliverable, verification and escalation conditions; the parent owns decomposition, integration and acceptance, not the user. Subagent results are not directly visible to the user.

Launch independent tasks concurrently only when inputs and write/resource ownership allow it; continue independent parent work. Wait for prerequisites before dependent work. Do not bundle separately decidable goals or split tightly coupled work merely by file, duration or step count.

- background: true returns taskId immediately. Otherwise wait up to 300 seconds, returning the full result if finished or auto-backgrounding with taskId.
- Completion automatically wakes you with a notification, not the final result. Retrieve it once with task_output(taskId, mode="full"). Full/default output acknowledges and clears the notification; diagnostic modes do not.
- task_output diagnostic modes: summary (status/health/elapsed time), progress (tool activity/health/duration), tail (recent conversation). Use for evidence-based diagnosis, stale health or cancellation decisions; do not poll/loop for progress. task_list gives an overview.
- task_output(block: true) is valid only with full/default mode and waits up to 300 seconds. Do not schedule extra completion wake-ups.
- session_id continues an idle session owned by this parent with retained context. Busy or differently owned sessions are rejected; provide only new information when continuing.
- output accepts summary, final_response, or structured with schema and maxRepairTurns. Structured schemas support objects, arrays, primitives, anyOf and oneOf; results include rendered JSON and structured metadata.
- model selects this subagent's model. Omit it to inherit this turn. Prefer a role from the delegation model list below (parent, default, thinking, mid, creative, mini, nano, long). provider/model is accepted only when that model is connected and selectable. An unavailable model fails instead of falling back.
- For a DAG node pass dag_node_id; completion/failure updates the node automatically.
