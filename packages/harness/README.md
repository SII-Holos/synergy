# harness

This package owns Synergy's generic execution runtime. Application hosts use the [public entry points](../../docs/architecture/README.md#harness-public-entry-points); individual host contracts are declared explicitly in `package.json`. Test-only exports are excluded from published packages.

Run `bun run typecheck`, `bun run test`, and `bun run build` from this package.

Model SDK implementations belong to `local-runtime`. Research hosts register `ProviderSdkSource` with synchronous and asynchronous factory loaders; SDK access before registration fails explicitly. The `ai` engine remains a harness dependency and itself includes the Gateway adapter transitively.

Custom SDK factories belong to each Runtime instance. Research hosts using agent workers register a bootstrap entry with `registerAgentWorkerEntrypoint()` that creates its explicit Runtime context and installs the same SDK source before starting the harness runner; in-process experiments register their source in the current process.

The harness owns permission policy and the `SandboxHost` execution contract. OS sandbox implementations, native PTYs and filesystem watchers belong to `local-runtime`. Sandboxed tool execution without a registered host fails explicitly; a bare research harness starts no native file watcher.

`PermissionNext.decide` records one native winner through `session/decision-receipts`. Runtime rules, attribution and receipts share the caller's Storage transaction; promise settlement, rule caches and notifications follow commit. This store retains historical decisions without restoring pending approvals after restart.

Embedded tool admission uses `tool/policy-source`: a host can narrow visible and deferred identities and authorize exact calls before execution resources are acquired. The source cannot widen the registry or replace permission and sandbox decisions. The public `cortex/tools` entry exposes the complete suite for explicit registration.

Initialized tools may declare `resourceNeeds(args)` for input-dependent Workspace or execution requirements. Those requirements augment static declarations and use the same resource admission, capability gate and release path. Directory-independent actions remain usable without allocating a Workspace; precise file operations retain their resolved-path permission requests.

The `environment` host entries own durable allocation and operation identities. Register providers before opening a Runtime; missing providers fail explicitly. See [Environments](../../docs/architecture/environments.md) for execution, checkpoint and recovery semantics.

Hosts supply immutable environment and paths, composition, and storage ownership to `RuntimeHandle.open()`. Imports have no registration side effects. Enter work with `handle.run()` or capture callbacks with `handle.bind()`; await `close()` or use `await using`. Multiple handles can coexist in one process. See [Runtime and Scope](../../docs/architecture/runtime-and-scope.md) for lifecycle and workspace semantics.

`HomeOwnership` preserves an explicitly provisioned Home's domain and identity independently of optional execution components. A host selects the matching owner during composition; initialization rejects missing, mismatched or unsupported ownership before execution storage opens. Legacy personal Homes retain their existing behavior. Owners persist initial identity through their provisioning or non-executing migration path; ordinary Runtime startup does not assign an organization identity to an existing personal Home.

Optional configuration owners register their public `shape` through `ConfigExtensions`. Aggregate fields can also provide a tolerant `storedShape` and a `project` callback that hides unavailable child records. Global and project edits retain hidden stored fields, including replacement writes; clients and execution only receive selected owners. Reinstalling an owner restores its configuration from the retained domain files.

Hosts with a different file delivery mechanism register `AttachmentDelivery` guidance during composition. The selected response instructions and execution-tool instructions replace the default immutable-attachment guidance together, and remain isolated to that Runtime. This changes model instructions only: the host must also supply the matching delivery tools and authorization. Without a registration, the existing attachment behavior and guidance remain unchanged.

The public `/usage` entry exposes retained accounting, typed queries, clear/rebuild operations, and explicit host lifecycle/transfer integration. Its [accounting contract](../../docs/architecture/usage-accounting.md) is independent of transcript and archive retention.

The public `/rollout` entry provides `RolloutSnapshot.modelCalls()` for current run and model-call metadata without journal replay, tool evidence or artifact bodies. `current()` maintains a reusable validated journal prefix during concurrent appends; `read()` retains strict historical replay for integrity checks and archives.

Selective tool catalogs use `cortexTools()` and register `registerCortexToolInputHistory()` from `./cortex/tools` before sealing the Runtime. The history registration keeps owned session migrations independent of product tool registration.

Harness owns manual paused Session migration through `session/transfer` and the explicit `session/transfer-workspace` Host contract. The protocol does not execute historical calls; see [Session transfer](../../docs/architecture/session-transfer.md).

Trusted hosts compose continuation authorization and receipts through `SessionResume.request()` admission hooks, with a separate actor and cancellation signal. `RolloutLifecycle.cancel()` composes cancellation receipts before physical drainage. `RolloutQuery.activity()` separately observes bounded recorded descendants and process evidence without execution recovery. See [Session controls](../../docs/architecture/session-and-messages.md#one-active-loop) for transaction ownership, control serialization and retained identity.

The public `session/transfer` entry also exposes `SessionTransferEpochs` and `SessionTransferStream` for trusted portability owners. Epoch transitions retain prior surrender/retirement evidence; stream verification never grants execution authority. Native binary streams share the Storage prepared-token and pack-pin lifetime. See [Session transfer](../../docs/architecture/session-transfer.md).

Object artifact deployments also use the canonical binary stream APIs. New writes use checksum-pinned format 2 manifest pages; historical format 1 artifacts remain readable. Upload intents protect each chunk/page before external writes, while SQL-paged validation and garbage collection preserve backup pins and shared content. See [Agent storage](../../docs/architecture/agent-storage.md) and `test/storage/object-artifacts.test.ts`.

`SessionHistory.preparePartFields()` prepares exact native fields without blocking a remote request on full conversion. Ready descriptors have bodyless headers; `partField()` reads bounded UTF8 byte ranges with native version checks. Regenerable pages survive restart, share collection leases and drain before Storage closes. This native operation does not authorize remote reads. See [Message Parts](../../docs/architecture/session-and-messages.md#message-parts) and `test/session/{part-field,part-field-cache,rollout-tool-part-index}.test.ts`.

`Asset.open()` streams verified immutable content; `Asset.installStream()` installs it through the selected file or stored owner before Session activation. Content installation and SQL publication have separate atomicity. See [Asset installation](../../docs/decisions/implemented/architecture/2026-11-11-install-immutable-assets-before-session-publication.md) and `test/asset/portable.test.ts`.

The public `session/transfer` entry exposes `SessionTransferEvidence` for explicit registration. It seals an exact frozen member graph, deduplicates Asset/full-output dependencies on disk and validates target contents before paused publication. Organization objects require trusted source authority; a global hash or alias grants no access. Restarted targets rebuild their preparation proof. Frozen shutdown and reads retain unresolved recovery without rewriting evidence. Historical snapshots and native truncation files require their own integration. Complete Markdown/JSON extraction retains one field's parse tree. See [dependency verification](../../docs/decisions/implemented/architecture/2026-11-11-verify-portable-assets-and-tool-output-dependencies.md) and `test/session/{transfer-evidence,transfer-recovery}.test.ts`.

Snapshot owners and deletion jobs use version 3 with one retention identity for reads, subsequent captures and cleanup. Central record migration preserves old self-retention semantics; missing ownership and unknown versions grant no read access to retained bytes. See [Snapshot retention authority](../../docs/decisions/implemented/architecture/2026-11-11-version-snapshot-retention-authority.md) and `test/snapshot/retention-identity.test.ts`.

The public `/session/transfer` entry exposes explicitly registered `SessionTransferSnapshots` for standalone streamed Git history, private destination verification and epoch-owned paused adoption. Runtime restart rebuilds preparation proof; permanent retirement and source cancellation clean only their private preparation data. See [streamed Snapshot history](../../docs/decisions/implemented/architecture/2026-11-11-stage-streamed-snapshot-history-before-epoch-activation.md) and `test/snapshot/portable-{source,target}.test.ts`.

Child Session indexes use a versioned count header and seekable rows. `Session.childEntries()` streams native metadata without loading the full parent or historical Scope catalog; `Session.children()` remains an explicit complete read. See [child index ownership](../../docs/architecture/session-and-messages.md#session-mutation-and-index-projection) and `test/session/{child-index-pages,session-child-index,records}.test.ts`.

Registered portability owners declare staged read dependencies. Their bound contexts expose only the declared owner's records from the same handoff member; the core owner enumerates its exact Snapshot roots. Raw Core requirements need compatible proof in that member's partition. Reusing persisted staging after restart rechecks reader compatibility before body access. Snapshot inventory streams retained identities, and portable summaries invalidate local diff tokens without stripping unknown fields. See [staged owner dependencies](../../docs/decisions/implemented/architecture/2026-11-11-declare-staged-owner-read-dependencies.md) and `test/session/{transfer-staging-dependencies,transfer-core-required-owners,transfer-staging-compatibility}.test.ts`.

Trusted Host backup owners use `storage/checkpoint` with the installed `Storage.Handle`. `StorageCheckpoint.exportArchive()` exports a verified namespace with fixed immutable byte references and separate authenticated secret recovery entries; the external versioned recovery key never enters the archive. `verifyArchive()` checks complete inventories. `restoreArchive()` requires an independent empty namespace and a final owning-domain fence in the same transaction as restored record/reference publication. Neither namespace completion nor a connection shutdown proves that an old Runtime has physically stopped or grants permission to replay execution. Private archives must not become ordinary organization-admin downloads. See [namespace checkpoint ownership](../../docs/architecture/agent-storage.md#namespace-checkpoints) and `test/storage/{checkpoint,checkpoint-archive}.test.ts`.
