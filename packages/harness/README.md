# harness

This package owns Synergy's generic execution runtime. Application hosts use the [public entry points](../../docs/architecture/README.md#harness-public-entry-points); individual host contracts are declared explicitly in `package.json`. Test-only exports are excluded from published packages.

Run `bun run typecheck`, `bun run test`, and `bun run build` from this package.

Model SDK implementations belong to `local-runtime`. Research hosts register `ProviderSdkSource` with synchronous and asynchronous factory loaders; SDK access before registration fails explicitly. The `ai` engine remains a harness dependency and itself includes the Gateway adapter transitively.

Custom SDK factories belong to each Runtime instance. Research hosts using agent workers register a bootstrap entry with `registerAgentWorkerEntrypoint()` that creates its explicit Runtime context and installs the same SDK source before starting the harness runner; in-process experiments register their source in the current process.

The harness owns permission policy and the `SandboxHost` execution contract. OS sandbox implementations, native PTYs and filesystem watchers belong to `local-runtime`. Sandboxed tool execution without a registered host fails explicitly; a bare research harness starts no native file watcher.

`PermissionNext.decide` records one native winner through `session/decision-receipts`. Runtime rules, attribution and receipts share the caller's Storage transaction; promise settlement, rule caches and notifications follow commit. This store retains historical decisions without restoring pending approvals after restart.

Embedded tool admission uses `tool/policy-source`: a host can narrow visible and deferred identities and authorize exact calls before execution resources are acquired. The source cannot widen the registry or replace permission and sandbox decisions. The public `cortex/tools` entry exposes the complete suite for explicit registration.

Initialized tools may declare `resourceNeeds(args)` for input-dependent Workspace or execution requirements. Those requirements augment static declarations and use the same resource admission, capability gate and release path. Directory-independent actions remain usable without allocating a Workspace; precise file operations retain their resolved-path permission requests.

The `environment` host entries own durable allocation and operation identities. Register providers before opening a Runtime; missing providers fail explicitly. See [Environments](../../docs/architecture/environments.md) for execution, checkpoint and recovery semantics.

A provider's optional `withDeallocation()` holds its original physical ownership around release admission, resource finalization and catalog publication. The Environment owner retains one actual completion, rejects escaped or foreign-storage callbacks and drains an already started release even if the wrapper returns or fails early. See [native deallocation](../../docs/decisions/implemented/bug-fix/2026-11-12-retain-native-deallocation-claims-through-final-saving.md) and `test/environment/deallocation-owner.test.ts`.

Hosts supply immutable environment and paths, composition, and storage ownership to `RuntimeHandle.open()`. Imports have no registration side effects. Enter work with `handle.run()` or capture callbacks with `handle.bind()`; await `close()` or use `await using`. Multiple handles can coexist in one process. See [Runtime and Scope](../../docs/architecture/runtime-and-scope.md) for lifecycle and workspace semantics.

`HomeOwnership` preserves an explicitly provisioned Home's domain and identity independently of optional execution components. A host selects the matching owner during composition; initialization rejects missing, mismatched or unsupported ownership before execution storage opens. Legacy personal Homes retain their existing behavior. Owners persist initial identity through their provisioning or non-executing migration path; ordinary Runtime startup does not assign an organization identity to an existing personal Home.

`lifecycle/namespace-identity` composes an owning native identity reader before startup. Its bounded public descriptor is backed by opaque evidence for the actual primary Store, artifact configuration, Home reader and native writer. Fresh verification rejects replaced or closed contexts; a caller-provided label is insufficient. See [namespace provenance](../../docs/decisions/implemented/architecture/2026-11-12-bind-backup-namespaces-to-owning-enrollment-readers.md) and `test/lifecycle/namespace-identity.test.ts`.

Optional configuration owners register their public `shape` through `ConfigExtensions`. Aggregate fields can also provide a tolerant `storedShape` and a `project` callback that hides unavailable child records. Global and project edits retain hidden stored fields, including replacement writes; clients and execution only receive selected owners. Reinstalling an owner restores its configuration from the retained domain files.

Hosts with a different file delivery mechanism register `AttachmentDelivery` guidance during composition. The selected response instructions and execution-tool instructions replace the default immutable-attachment guidance together, and remain isolated to that Runtime. This changes model instructions only: the host must also supply the matching delivery tools and authorization. Without a registration, the existing attachment behavior and guidance remain unchanged.

The public `/usage` entry exposes retained accounting, typed queries, clear/rebuild operations, and explicit host lifecycle/transfer integration. Its [accounting contract](../../docs/architecture/usage-accounting.md) is independent of transcript and archive retention.

The public `/rollout` entry provides `RolloutSnapshot.modelCalls()` for current run and model-call metadata without journal replay, tool evidence or artifact bodies. `current()` maintains a reusable validated journal prefix during concurrent appends; `read()` retains strict historical replay for integrity checks and archives.

Selective tool catalogs use `cortexTools()` and register `registerCortexToolInputHistory()` from `./cortex/tools` before sealing the Runtime. The history registration keeps owned session migrations independent of product tool registration.

Harness owns manual paused Session migration through `session/transfer` and the explicit `session/transfer-workspace` Host contract. The protocol does not execute historical calls; see [Session transfer](../../docs/architecture/session-transfer.md).

Trusted hosts compose continuation authorization and receipts through `SessionResume.request()` admission hooks, with a separate actor and cancellation signal. `RolloutLifecycle.cancel()` composes cancellation receipts before physical drainage. `RolloutQuery.activity()` separately observes bounded recorded descendants and process evidence without execution recovery. See [Session controls](../../docs/architecture/session-and-messages.md#one-active-loop) for transaction ownership, control serialization and retained identity.

The public `session/transfer` entry also exposes `SessionTransferEpochs` and `SessionTransferStream` for trusted portability owners. Epoch transitions retain prior surrender/retirement evidence; stream verification never grants execution authority. Native binary streams share the Storage prepared-token and pack-pin lifetime. See [Session transfer](../../docs/architecture/session-transfer.md).

Workspace Session admission uses the canonical transfer gate. Accepted native tails retain mutation checks, and retained exclusive claims lend only their original native geometry within a live callback. Installed server writer evidence is opaque and bound to the actual Runtime and primary Store. See [native source claims](../../docs/decisions/implemented/architecture/2026-11-12-bind-native-source-claims-to-exact-session-cohorts.md) and `test/{workspace/access-maintenance,util/server-process-lock-ownership}.test.ts`.

Object artifact deployments also use the canonical binary stream APIs. New writes use checksum-pinned format 2 manifest pages; historical format 1 artifacts remain readable. Upload intents protect each chunk/page before external writes, while SQL-paged validation and garbage collection preserve backup pins and shared content. See [Agent storage](../../docs/architecture/agent-storage.md) and `test/storage/object-artifacts.test.ts`.

Stream producer admission spans the Runtime's Stores and keys. Bounded private spooling leaves the destination artifact gate available to producer reads and cache writes, then canonical backend preparation installs the original native pin. Shutdown drains queued and active preparations before backend closure; raw Store owners await their calls before closing. Verify `test/storage/artifact-stream-producer.test.ts`; see [producer composition](../../docs/decisions/implemented/bug-fix/2026-11-12-spool-producers-before-artifact-adoption.md).

`SessionHistory.preparePartFields()` reads producer-derived headers and field sources without decoding the full Part or tool execution record. `partField()` seeks bounded UTF8 windows; versions bind the Part revision and currently resolved original-input source. Checkpoint preparation remains cancellable and drains before Storage closes. Central upgrades and portable target activation rebuild derived metadata without changing canonical unknown fields. This native operation does not authorize remote reads. See [native field sources](../../docs/decisions/implemented/architecture/2026-11-12-read-native-fields-from-producer-derived-sources.md) and `test/session/{part-field-header,part-field,part-field-cache,rollout-tool-part-index}.test.ts`.

`SessionHistory.attachmentContent()` reads bounded binary ranges from the current canonical AttachmentPart's retained producer artifact. Missing or partial evidence stays unavailable; the read never captures a global Asset reference. Native part version and exact artifact owner/ref are checked around each range. See [attachment producer evidence](../../docs/decisions/implemented/architecture/2026-11-12-read-session-attachments-from-canonical-producer-evidence.md) and `test/session/attachment-content.test.ts`.

`SessionHistory.attachmentPage()` pages revision-bound producer metadata without reading the canonical tool Part. Ordinal byte reads reuse that version and the exact Session artifact owner. Central migration prepares old producers; portable Core rebuilds the derived rows after target publication. Verify `test/session/{attachment-index,transfer-core}.test.ts`; see [paged attachments](../../docs/decisions/implemented/architecture/2026-11-12-page-tool-attachments-by-canonical-producer-revision.md).

`Asset.open()` streams verified immutable content; `Asset.installStream()` installs it through the selected file or stored owner before Session activation. Content installation and SQL publication have separate atomicity. See [Asset installation](../../docs/decisions/implemented/architecture/2026-11-11-install-immutable-assets-before-session-publication.md) and `test/asset/portable.test.ts`.

The public `session/transfer` entry exposes `SessionTransferEvidence` for explicit registration. It seals an exact frozen member graph, deduplicates Asset/full-output dependencies on disk and validates target contents before paused publication. Organization objects require trusted source authority; a global hash or alias grants no access. Restarted targets rebuild their preparation proof. Frozen shutdown and reads retain unresolved recovery without rewriting evidence. Historical snapshots and native truncation files require their own integration. Complete Markdown/JSON extraction retains one field's parse tree. See [dependency verification](../../docs/decisions/implemented/architecture/2026-11-11-verify-portable-assets-and-tool-output-dependencies.md) and `test/session/{transfer-evidence,transfer-recovery}.test.ts`.

Snapshot owners and deletion jobs use version 3 with one retention identity for reads, subsequent captures and cleanup. Central record migration preserves old self-retention semantics; missing ownership and unknown versions grant no read access to retained bytes. See [Snapshot retention authority](../../docs/decisions/implemented/architecture/2026-11-11-version-snapshot-retention-authority.md) and `test/snapshot/retention-identity.test.ts`.

Stored Snapshot headers use version 2 with bounded descriptor pages and canonical binary chunks. The explicit maintenance migration relinks historical chunk references, and `SnapshotMaintenance.collectStoredPreparations()` reconciles uncertain preparations under native leases. See [paged Snapshot content](../../docs/decisions/implemented/architecture/2026-11-12-page-stored-snapshot-content-and-preserve-preparation-evidence.md) and `test/snapshot/{paged-content,preparation,persistence,retention-epoch}.test.ts`.

The synchronous Task tool drains parent-abort cancellation through the native Cortex owner. A paused-turn reason preserves a child only with its current canonical transfer/maintenance hold and matching parent; ordinary cancellation and actual cleanup failures retain their existing outcomes. See [Cortex native controls](../../docs/decisions/implemented/architecture/2026-11-11-preserve-native-cortex-handoff-controls.md) and `test/cortex/{parent-abort,task-tool-abort}.test.ts`.

The public `/session/snapshot-maintenance` entry exposes trusted operator `withCapture()`. It pins the Home while its own native checkpoint export supplies fixed ownership and layout, then returns callback-bound opaque root readers; shutdown aborts and drains active captures. This inventory primitive does not constitute a complete deployment archive. See [operator Snapshot capture](../../docs/decisions/implemented/architecture/2026-11-11-bind-operator-snapshot-inventory-to-native-checkpoints.md) and `test/snapshot/checkpoint.test.ts`.

Within that capture, `exportSnapshots()` creates an independent canonical namespace segment containing complete native/legacy Git packs and exact refs, or stored graphs reconstructed from the fixed archive. `withRestoredSegment()` verifies its parent namespace and stages every repository before exposing callback-bound private paths; it publishes no active ownership or execution. Both operations drain on Runtime shutdown. See [Snapshot segments](../../docs/decisions/implemented/architecture/2026-11-12-capture-complete-snapshot-segments-and-stage-restoration.md) and `test/snapshot/segment.test.ts`.

The public `/session/transfer` entry exposes explicitly registered `SessionTransferSnapshots` for standalone streamed Git history, private destination verification and epoch-owned paused adoption. Runtime restart rebuilds preparation proof; permanent retirement and source cancellation clean only their private preparation data. See [streamed Snapshot history](../../docs/decisions/implemented/architecture/2026-11-11-stage-streamed-snapshot-history-before-epoch-activation.md) and `test/snapshot/portable-{source,target}.test.ts`.

Child Session indexes use a versioned count header and seekable rows. `Session.childEntries()` streams native metadata without loading the full parent or historical Scope catalog; `Session.children()` remains an explicit complete read. See [child index ownership](../../docs/architecture/session-and-messages.md#session-mutation-and-index-projection) and `test/session/{child-index-pages,session-child-index,records}.test.ts`.

Native Cortex summary pages use a Session-owned projection updated with canonical writers and compatibility publication. They exclude private payloads, survive restart and retain exact-child disambiguation for cold output. Explicit owning preparation handles older parents. See [Cortex metadata pages](../../docs/decisions/implemented/architecture/2026-11-11-page-native-cortex-metadata-without-child-payloads.md) and `test/session/cortex-index.test.ts`.

Registered portability owners declare staged read dependencies. Their bound contexts expose only the declared owner's records from the same handoff member; the core owner enumerates its exact Snapshot roots. Raw Core requirements need compatible proof in that member's partition. Reusing persisted staging after restart rechecks reader compatibility before body access. Snapshot inventory streams retained identities, and portable summaries invalidate local diff tokens without stripping unknown fields. See [staged owner dependencies](../../docs/decisions/implemented/architecture/2026-11-11-declare-staged-owner-read-dependencies.md) and `test/session/{transfer-staging-dependencies,transfer-core-required-owners,transfer-staging-compatibility}.test.ts`.

Portable Core schema 2 seals native child membership and owner references. Staging validates the complete canonical parent tree and actual owner partitions before returning a root preparation context; the proof remains bound to that Runtime and package during paused publication. See [aggregate membership](../../docs/decisions/implemented/architecture/2026-11-11-seal-portable-core-aggregate-membership.md) and `test/session/transfer-membership*.test.ts`.

Aggregate activation snapshots its manifest, callback and original signal before waiting, and carries optional cancellation through native epoch-lock admission and the final Storage commit guard. A cancelled request before commit leaves private staging and prepared epochs without publishing Sessions. Verify `test/session/transfer-activation-cancel.test.ts`; see [activation cancellation](../../docs/decisions/implemented/bug-fix/2026-11-12-cancel-native-activation-before-epoch-publication.md).

Trusted Host backup owners use `storage/checkpoint` with the installed `Storage.Handle`. `StorageCheckpoint.exportArchive()` exports a verified namespace with fixed immutable byte references and separate authenticated secret recovery entries; the external versioned recovery key never enters the archive. `verifyArchive()` checks complete inventories. `restoreArchive()` requires an independent empty namespace and a final owning-domain fence in the same transaction as restored record/reference publication. Neither namespace completion nor a connection shutdown proves that an old Runtime has physically stopped or grants permission to replay execution. Private archives must not become ordinary organization-admin downloads. See [namespace checkpoint ownership](../../docs/architecture/agent-storage.md#namespace-checkpoints) and `test/storage/{checkpoint,checkpoint-archive}.test.ts`.

Trusted capture owners read logical protected entries with `StorageCheckpoint.entries()`, which shares the native verification walk and refuses incomplete consumption. Complete its iteration before sealing a private capture index; no ordinary account or physical-location permission is added. Verify `test/storage/checkpoint-entries.test.ts`.

`storage/runtime-maintenance` retains native purpose/cohort holds and opaque Runtime/Handle-bound lease and drainage receipts. Base registration protects retained operations independently of selected owners. Execution, automatic driving, new user input and Continue honor the hold while accepted input remains readable. The Session owner pauses native turns and drains their leases and tail saves without replaying input. The LoopJob owner then closes scheduling and drains all accepted background jobs, including detached work, without cancellation. Recording failures remain blocking across retries. Native admission reopens only through the confirmed `released` callback, after every owner's release and the canonical commit; a lost acknowledgement requires the same lease to reconcile it. Frozen writes and cold-cohort reclaims remain blocked. Other resource owners must supply actual drainage; this does not replace offline `StorageMaintenance`. Verify `test/storage/runtime-maintenance.test.ts` and `test/session/{runtime-maintenance,maintenance-owner,loop-job-maintenance}.test.ts`; see [maintenance ownership](../../docs/architecture/agent-storage.md#runtime-maintenance-operations).

The public `/session/transfer` entry exposes `SessionTransferSource` for canonical aggregate preparation. It retains source holds, drains selected owners before child-to-root final freezing, rechecks native membership and the caller's command barrier, validates the complete frozen graph and reconciles its immutable streamed package. Native LoopJob capture preserves recording failures through ordinary settlement and repeated preparation, including undiscovered descendants; snapshot drainage waits without consuming those errors or cancelling the original save. Optional `beforeFreeze()` runs after native tails outside SQL, before final epoch fences; it does not supply physical ownership itself. Failed preparation never starts recovery. Organization dispatch, cold writer reconciliation and physical resource drainage remain caller responsibilities. Verify `test/session/transfer-source*.test.ts`; see [source preparation ordering](../../docs/decisions/implemented/architecture/2026-11-12-drain-portable-source-owners-before-final-freezing.md).

Aggregate source cancellation repairs the complete held cohort before one transaction cancels its epochs and publishes an immutable receipt. Failed receipt writes roll back every cancellation; surrender remains irreversible. Native task identity and pause survive, with no package export, initial-input replay or automatic Continue. Verify `test/session/{transfer-source-cancel,transfer-source-task}.test.ts`.

Aggregate surrender permanently changes all exact frozen member epochs and its package/preparation receipt in one transaction. Destination staged-member iteration validates the graph and yields parent-first canonical metadata through a private disk frontier, without publishing Sessions or borrowing source objects. Both preserve restart/error boundaries; signed organization permits and physical ownership remain caller responsibilities. Verify `test/session/{transfer-source-surrender,transfer-staging-members}.test.ts`.

The `workspace/portable-tree` contract describes bounded native file metadata and roots over the canonical streamed portability protocol. Local Runtime owns actual capture and restoration; this contract grants no physical or execution authority. See [streamed native trees](../../docs/decisions/implemented/architecture/2026-11-12-stream-native-workspace-trees-through-portable-pages.md).

Base registration contributes native Environment maintenance. New allocation/execution intents obey the hold; original receipts and final saves remain available. Pending requests, uncertain process/stream completion and unfinished saves block freezing. Verify `test/environment/maintenance.test.ts`; see [Environment maintenance](../../docs/architecture/environments.md#execution-and-saving).

Workspace operation maintenance fences new mutation staging and publication while preserving exact accepted-result reads. It waits for real request lifetimes and reconciles the original mounted file receipt, checkpoint, acknowledgement and resource use; a missing receipt stays unknown without a replacement write. Verify `test/workspace/maintenance.test.ts` and Local Runtime's matching suite. Complete resource capture still needs its own native owners. See [Workspace mutation maintenance](../../docs/decisions/implemented/architecture/2026-11-12-reconcile-workspace-mutation-receipts-during-maintenance.md).

`WorkspaceAccess` contributes the native claim owner when its Host is selected. Maintenance rejects new non-read claims before and after physical admission, drains actual leases through final saves and `afterRelease`, and retains unknown release failures. Existing claim callbacks retain only their actual open lifetime; escaped callbacks cannot reuse a completed or failed scope. Process binding checks the originating Runtime and Store. Physical Hosts report release through the original claim/token so canonical receipt recovery can release a different lease object without trapping the original waiter. Verify `test/workspace/access-maintenance.test.ts` and Local Runtime's matching suite; see [native claim drainage](../../docs/decisions/implemented/architecture/2026-11-12-drain-workspace-claims-through-native-release-evidence.md).

Workspace mount maintenance fences new attach/detach intents, waits for actual transition promises and checks bounded native indexes against the canonical catalog. A completed original mount receipt can finish its preparing publication without materializing again; an orphaned preparation, unavailable view, unfinished save or missing index remains held. Ordinary attach cannot reopen a saving view. This transition owner does not capture external live volumes or prove unique deployment writers. Verify Local Runtime's `test/workspace/mount-maintenance.test.ts`; see [mount evidence](../../docs/decisions/implemented/architecture/2026-11-12-reconcile-workspace-mounts-from-original-native-evidence.md).

Portability owners declare staged read dependencies separately from `publicationBefore`. Native staging rejects missing/cyclic publication owners before receiving bytes and publishes owners topologically within the activation transaction, preserving each owner's incoming parent-first member order. This lets verified native Workspace catalog identities precede Core publication without granting broader staged reads. Verify `test/session/transfer-publication-order.test.ts`; see [native publication order](../../docs/decisions/implemented/architecture/2026-11-12-order-native-portability-owner-publication.md).
