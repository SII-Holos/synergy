# Decision Record: Slim static prompt and tool context injection

Status: implemented

## Problem

Primary sessions inject roughly 50k tokens (synergy-max) and 45k tokens (synergy) of static context before the first user message. Three sources carry pure waste:

- Worktree sessions inject the repository `AGENTS.md` twice — the original checkout and the worktree are separate trust roots, and the checkout copy is byte-identical to the worktree copy, so every worktree session pays ~3.2k tokens for zero information gain.
- The `skill` tool inlines the full frontmatter description of every accessible skill into its own tool description — 105 skills, ~52k characters (~13k tokens) per session, most of it multi-line "when to use" prose.
- DAG semantics are taught twice: the synergy system prompt's "Planning with DAGs" section (~3.5k tokens with statuses, auto-promotion, validation, and three worked examples) restates what the `dagwrite` tool description already specifies, and `bash.txt` restates background-process management that the `process` tool description owns. Both copies are billed every session.

## Decision

- `InstructionFiles.load()` dedupes the merged instruction parts by exact body equality after stripping the `Instructions from: <path>` header, keeping the first occurrence (global → scope-root-to-workspace → explicit). Any content difference keeps both copies.
- `skill.ts` gains `truncateSkillDescription()`: first line, whitespace-collapsed, cut at a word boundary at 100 characters with an ellipsis. It is applied only when building the catalog inside the tool description; `skill()` still loads the full text, and the UI reads raw frontmatter.
- Tool descriptions slim to hard budgets with ownership moved, not deleted: `bash.txt` ≤ 7,000 B (background-process teaching replaced by a pointer to `process`), `revise-file.txt` ≤ 5,000 B (anchored discipline duplicated from `view-file`/`save-file` compressed to pointers), `dagwrite.txt` ≤ 6,500 B as the sole authoritative DAG semantics source. `docs/reference/tools.md` is regenerated by the generator.
- The synergy prompt's "Planning with DAGs" section collapses to a summary that points at the `dagwrite` tool description as the authority; polling-discipline literals asserted by `test/agent/task-polling-prompt.test.ts` are preserved verbatim.
- A new size-budget test locks rendered prompt budgets (both primary builders) and source byte budgets for the slimmed files so the reduction cannot silently regrow.

## Alternatives considered

- **A `skill_search` lazy-loading tool** — rejected: dropping descriptions from the catalog entirely saves more, but requires the full first-party tool workflow (registration, taxonomy, web presentation) and turns skill discovery into a two-hop lookup.
- **Per-agent skill filtering** — rejected: maintaining per-agent relevance rules costs more than the ~1k additional tokens they would save.
- **Active-memory budgeting or automatic demotion of `always` memories** — deferred: `<runtime-context>` memory injection is per-turn uncached and grows without bound, but capping it changes recall semantics and persistence behavior; it needs its own decision rather than riding on this text-level pass.
- **Rewriting the synergy base prompt wholesale** — rejected: behavioral contracts (polling discipline, anti-patterns, task-output retrieval) are embedded in the prose; section-by-section convergence guarded by literal assertions is the safe route.

## Consequences

First-turn static injection drops from ~50k to ~36–38k tokens for synergy-max and ~45k to ~33–35k for synergy; the saving repeats on every cache-invalidation replay. Upgrading invalidates every user's cached system prefix once. Skill discovery loses trigger phrases beyond the first description line — the full text still loads through `skill()`. Byte-identical instruction files across directories now inject once; distinct content is unaffected. The DAG/bash knowledge remains available in exactly one authoritative place each, at the tool description the model already reads when deciding to call the tool.
