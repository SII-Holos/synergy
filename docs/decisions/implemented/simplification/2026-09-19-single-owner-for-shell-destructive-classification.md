# Decision Record: One classifier owns shell destructive classification

Status: implemented

## Problem

The bash risk classifier was one of three layers that each decided whether a command was destructive. `ShellSafety.classifyBashRisk` tokenized the command, while `analyzeDestructiveCommand` (a `DESTRUCTIVE_PATTERNS` list plus a resilient regex table) and `isDestructive` (a lowercase substring scan) both scanned the raw command text.

The layers covered different shapes, so none could be removed. The token-aware classifier did not recognize `rm` at all, which meant `rm -rf /`, `rm -rf ~`, `mkfs.ext4 /dev/sda`, `chmod -R 777 /`, and `shred /etc/passwd` were caught only by the substring layers — `ShellSafety.isHardline("rm -rf /")` returned `false`. Conversely, the substring layers could not distinguish a command from argument text, so recovery commands were refused: `git rebase --abort` and `git rebase --continue` matched the `"git rebase "` substring, and `sudo true` was labelled with the reason `matched destructive pattern: sudo`.

Because the substring layers were the only owner of the host-level shapes, and the token-aware layer was the only owner of the git semantics, each new benign command shape risked reopening the same denial class. The `2026-09-10-unified-read-only-shell-catalog` record described the same structural debt for the read-only catalog.

## Decision

`ShellSafety.classifyBashRisk` is the single owner of every shell risk that the OS sandbox cannot express, and the substring layers are deleted.

Host-level destruction is now decided from tokenized operands: an `rm` whose target is the filesystem root, the home directory, or a wildcard form of either is `shell_hardline`, as are the filesystem and power tools (`mkfs.*`, `fdisk`, `parted`, `lvremove`, `pvremove`, `vgremove`, `shutdown`, `reboot`, `halt`, `poweroff`) except their read-only and help forms — so `fdisk -l`, `parted --list`, `mkfs -h`, and `shutdown --help` are executable while `fdisk /dev/sda` and `shutdown -h now` are not. Privilege escalation is a first-class classifier input rather than a side effect of the substring layer, and it walks substitutions, heredocs, wrappers, and fd replay once at the top level under the shared classification budget.

Remote irreversibility follows the destination branch rather than the flag spelling. A force or delete against a protected branch (`main`, `master`, `dev`, `develop`, `trunk`) is `shell_remote_write`; the same operation against an explicitly named non-protected branch is `shell_remote_publish`, because the loss is bounded by that branch's own commits. `--force-with-lease` and `--force-if-includes` are no longer destructive in themselves. An unbounded destination set (`--all`, `--tags`, `--mirror`, or a repository-selecting flag) stays a remote write, and a bare `git push --force` stays a remote write because `push.default` resolves its destination only at runtime.

Irreversible local history keeps its boundary (`reset --hard`, `clean -fdx`, `stash drop`, `stash clear`, `checkout -- <path>`, `filter-branch`, `filter-repo`, `reflog expire|delete`), while reflog- or worktree-recoverable operations stopped being destructive: `rebase`, `reset --soft`/`--mixed`, `stash pop`, `commit --amend`, `revert`, `pull --rebase`, and `git rm`. `git clean -f`/`-fd` is not destructive because it removes only untracked files; removing ignored files (`-x`) is.

The lexer helpers the deleted layers used (`splitCompoundCommands`, `stripWrappers`) keep their owning module (`shell-command.ts`) and their tests moved to `test/enforcement/shell-command.test.ts`; the re-export from `gate.ts` is gone.

Network detection follows the same rule. `hasNetworkActivity` scanned the whole command string for tool names and URL schemes, so `echo "see https://example.com for docs"`, `rg -n "ssh " docs/`, and `git commit -m "fix npm install docs"` all minted `network_request`. Because an allowed `network_request` also relaxes the sandbox network mode to full, a false positive both misreported the command and granted egress it never needed. The capability is now decided from the resolved command: a closed set of network tools (`host` included for DNS), the git and OpenSSL subcommands that contact a remote, package-manager subcommands that reach a registry, and an rsync operand carrying a remote host. Wrappers (`timeout 5 curl …`), shell and interpreter re-parse payloads, code-executing heredocs (`bash <<EOF`, gated on the header executing stdin as code so `cat <<EOF` stays data), and command substitutions are unwrapped and re-scanned recursively. `/dev/tcp` and `/dev/udp` are matched on unquoted text at every recursion level — the check runs inside the recursive walker, so a redirect buried in a quoted `bash -c`/`eval`/heredoc payload is caught once the payload is unwrapped, while quoted documentation text stays inert. An inline interpreter payload (`python -c`, `node -e`, `--eval`) reports the capability outright: the code can open a socket with no static tell, and the sandbox relaxation driven by this very capability is the difference between a permitted connection and a runtime denial with no explanatory capability — failing closed there matches budget exhaustion, which fails closed for the same reason. Budget or depth exhaustion fails closed.

## Alternatives considered

- **Keep the substring layers as defense-in-depth.** Rejected: they were the only owner of the host-level shapes while the token-aware classifier was the only owner of the git semantics, so no layer was redundant and each new shape required editing two implementations that disagreed. Deleting them required completing the token-aware classifier first, which is why the coverage assertions landed before the deletion.
- **Fix only the reported symptoms (`git rebase --abort`, the `sudo` reason string).** Rejected: the misclassification was structural. A substring scan cannot separate a command from argument text, so the same class of error returns with the next command shape, and the host-level shapes would still have two owners.
- **Keep one substring layer and delete the other.** Rejected: the two substring layers were not duplicates — `isDestructive` also called `ShellSafety.hasSudoInvocation`, so deleting it alone would have silently dropped privilege-escalation detection rather than consolidating it.
- **Keep `--force-with-lease` destructive because it can still overwrite remote history.** Rejected: it is git's documented safe alternative to `--force`, and treating the flag itself as destructive refused ordinary feature-branch publishing. The irreversibility that matters is whether the destination is shared history, which the destination branch determines directly.
- **Delete the destructive layers before completing the token-aware classifier.** Rejected: at that point eleven host-level shapes had no owner at all, so the deletion would have removed a hard boundary rather than a redundant one.
- **Detect network activity by matching URL schemes and tool names only in executable position.** Partially adopted; the implementation resolves the command name and subcommand instead, because a scheme can appear in a legitimate operand (`curl --url https://…` is redundant while `echo https://…` is inert) and because subcommand determines whether a package manager actually reaches a registry (`npm run build` does not).

## Consequences

Network classification retains `go mod download`/`tidy`/`vendor`, Git global options and `env` wrappers; command lookup (`command -v`/`-V`) does not open a connection. Wrapper traversal uses the same finite classification budget. Explicit non-protected remote branch deletion follows the documented publish classification. Whole-directory `rm` spellings (`.`, `./`, `./*`, `..`, `*`) remain conservative hardline targets; only named workspace subtrees receive the ordinary-write treatment.

The eleven host-level shapes and the git and gh classifications have one owner, so behavior is decided by tokenized operands instead of by argument text. Recovery and reversible operations are no longer refused: `git rebase --abort`, `git rebase --continue`, `git rebase main`, `git reset --soft`, `git stash pop`, `git commit --amend`, `git revert`, `git rm`, `git pull --rebase`, and force-pushes to non-protected branches execute under `autonomous`.

The change knowingly gives up conservatism in three places. Force-pushing a non-protected branch and `git clean -fd` are no longer refused under `autonomous`; the boundary is now "unrecoverable" rather than "rewrites history", and a branch's own commits remain recoverable through the reflog. `rm -rf` targeting a named workspace subtree is no longer refused either — it is an ordinary write that the OS sandbox contains, which is consistent with the ownership rule but means the refusal now depends on the sandbox being enforced.

Two limits are unresolved. The read-only risk catalog and the find/fd exec-target inspection still exist and remain owned by `ShellSafety`; consolidating them depends on the sandbox owning shell filesystem reach, which is not yet the case. And the boundary is still a static judgement about remote state and irreversibility, so a wrong judgement is possible; the regression corpus in `test/enforcement/destructive-boundary.test.ts` pins both sides of every boundary this record describes so a future edit cannot move one silently.
