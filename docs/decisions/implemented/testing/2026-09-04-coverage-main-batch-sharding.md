# Decision Record: Shard the synergy coverage main batch across single processes

Status: implemented

## Problem

The Coverage job on `dev` failed four times on 2026-09-04 (and intermittently on 09-03 and on PR branches) while the same commits passed other runs. `packages/synergy/script/coverage-run.ts` executed the entire non-isolated suite — ~150 test files — inside one shared Bun process, so leaked module state (stale `Config.current` overrides, channel registries, late async rejections, LibraryDB singletons) from one file could poison any file that ran after it. The observed CI signatures were whole-file sub-millisecond failures in `test/email/imap.test.ts` (including pure-function `isTruncated` cases, proving module-load-level poisoning) plus `ChannelHost`/`managed-project-ownership` assertion failures. A local reproduction on a clean `dev` checkout failed the same main batch with a different victim set, confirming non-deterministic cross-file pollution rather than product regressions. The existing mitigation — appending files to `ISOLATED_COVERAGE_FILES` — is whack-a-mole: four prior isolate commits each patched the list and the suite kept finding new victims (postmortems 0001–0003 document the same shared-process mechanism).

The first sharding iteration also surfaced a meta-problem: position-based (round-robin) dealing meant every isolation-list edit shifted every remaining file's shard assignment, so each fix reshuffled all neighbor combinations and exposed a new round of order-dependent victims (`boss-workflow` on 2026-09-05 CI, after `library/database` joined the list).

## Decision

Three layers (shared by both the Coverage and Test jobs — `test-ci.ts` imports the same planner, because Bun's native `--shard` cannot exclude files and Test-job flake recurrences on 2026-09-05 made the single-job isolation a standing gap):

1. **Stable-hash sharding.** The planner in `coverage-run.ts` assigns main-batch files to sequential single-process shards by FNV-1a hash of the file path (default 4 shards, `SYNERGY_BATCH_SHARDS` overridable). A file's shard depends only on its own name, so editing the isolation list or adding suites never reshuffles the remaining files' assignments. Coverage batches write lcov under `coverage/shards/<n>/`, merged by `script/coverage-check.ts` with existing union semantics; Test-job batches keep per-batch JUnit reports via `SYNERGY_TEST_JUNIT_DIR`.
2. **Isolation list for state- or load-sensitive suites** (`ISOLATED_BATCH_FILES`, each entry verified green standalone and failing only inside shared batches): `test/channel/clarus-assignment.test.ts`, `test/channel/clarus-invite-accept.test.ts`, `test/channel/feishu-provider.test.ts`, `test/channel/host.test.ts`, `test/channel/managed-project-ownership.test.ts`, `test/channel/svg-raster-standalone.test.ts`, `test/cli/daemon-entry.test.ts` (mock-modules `src/server/runtime.ts`), `test/config/import.test.ts`, `test/daemon/observe.test.ts`, `test/daemon/spec.test.ts`, `test/email/imap.test.ts` (global config/channel registries poisoned by siblings on CI), `test/global/test-home-guard.test.ts` (subprocess contract around the real-home guard), `test/holos/runtime.test.ts`, `test/library/database.test.ts`, `test/library/experience-recall.test.ts`, `test/library/experience-reencode.test.ts` (LibraryDB singleton repopulated, cleaned, or left stale by siblings — the reopen-current-job signature also failed the Test job), `test/library/embedding.test.ts`, `test/library/embedding-local.test.ts`, `test/vector/embedding-standalone.test.ts` (real transformers/ONNX runtime exceeds the run timeout under batch load), `test/plugin/mcp-declarative-oauth.test.ts`, `test/provider/catalog-stability.test.ts`, `test/provider/proxy.test.ts`, `test/server/nav-global-routes.test.ts`, `test/server/plugin-official-install.test.ts`, `test/server/plugin-registry-routes.test.ts`, `test/server/skill-route.test.ts`, `test/session/retry.test.ts`, `test/storage/storage-retry.test.ts` (spies global `fs.rename`/`fs.unlink`), `test/storage/storage-silent-not-found.test.ts` (asserts metrics on a shared observability store), `test/tool/auto-expand.test.ts`, `test/tool/openai-image-gen.test.ts`, `test/tool/session-search.test.ts` (scans session stores under the shared home).

The same CI round exposed unrelated `dev` regressions this PR carries: `packages/app`'s Coverage gate counted the new `DevicePushBlock.tsx` (introduced by #1315) as never-loaded — it joins the existing settings-panels exemptions — and `packages/synergy`'s gate counted the new `src/push/index.ts` barrel (#1315) as never-loaded, which joined the existing barrel exemptions.

3. **Root fixes for what isolation was papering over.** Five suites were silently order-dependent on `product-registration` mounts from alphabetically earlier siblings (`test/session/boss-workflow.test.ts`, `test/skill/synergy-agent-tooling.test.ts`, `test/skill/synergy-prompt-architect.test.ts`, `test/server/config-import-route.test.ts`, `test/plugin/system-transform-hook.test.ts`); they now mount it themselves per the established convention. `session_search` gained product-level orphan tolerance: page-index entries whose `info.json` no longer exists (interrupted delete) are skipped instead of failing the whole search, matching the global search route's existing semantics, with a regression test.

## Alternatives considered

- **Keep growing the isolation list.** Rejected: it had already been patched four times without converging; sharding shrinks the blast radius structurally, and stable-hash assignment removes the reshuffle-amplifier that made each list edit create new victims.
- **Fix each leak at its source (reset every module singleton between files).** Rejected as the primary fix: the leak sources are spread across dozens of suites that intentionally mutate module-level state (mock injection is the established test pattern here), and Bun 1.3.x offers no per-file module registry reset. Root fixes are applied where a true product gap exists (session_search orphan tolerance).
- **Run the suite with `--parallel` workers under coverage.** Rejected: postmortem 0001 showed worker processes do not inherit preload-set isolation env, which is exactly how fixtures once landed in the real home; the spawn-per-shard orchestrator keeps every batch in a child with injected env.
- **Sum `FNH` across shards to recover function coverage.** Rejected: summing overcounts (155% on local shard data) because Bun's lcov records per file are already per-batch aggregates, not disjoint sets.
- **True per-function union across shards.** Impossible on the pinned Bun 1.3.14: the lcov writer emits no `FN:`/`FNDA:` records (its source comment states per-function coverage is unsupported because JSC does not expose function names; tracked upstream as oven-sh/bun#19247, #31484, PR #35725), there is no coverage-dump env var, and `node:inspector` precise coverage only exists from Bun 1.4.0+ (oven-sh/bun#31823). Accepted as a documented limitation with margin monitoring (below).

## Consequences

The Coverage job trades some wall-clock (sequential shards, ~4× process startup) for isolation between files; total test work is unchanged and per-line lcov merging stays exact. Function coverage from a shard merge is now a conservative lower bound (max of per-shard aggregates) instead of the near-true single-process number: on a local full run the max-merge package-level figure was 77.3% against the 75% gate, with the capped-sum upper bound at 85.3%. The gate therefore cannot falsely pass a regression, but sustained margin erosion means the fix is upgrading Bun (≥1.4.1's internal `--parallel` unions function coverage correctly, oven-sh/bun#40678, or inspector-based V8 profiles), not summing. Stable-hash sharding also makes shard sizes statistical rather than exact; the contract tests pin determinism and full coverage of files, not per-shard counts. Failure reporting per shard is unchanged (`coverage batches failed: shard N (exit M)`).
