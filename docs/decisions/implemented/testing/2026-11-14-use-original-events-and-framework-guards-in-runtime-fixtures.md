# Decision Record: Use original events and framework guards in Runtime fixtures

Status: implemented

## Problem

Native correctness fixtures combine cold Runtime preparation, actual model/tool work and resource drainage. Shorter observation races can expire before their framework guard, while repeated HTTP pending reads impose an unrelated readiness budget. These waits do not establish product latency requirements or explain a genuinely failed producer.

## Decision

The Organization Runtime native-execution fixture awaits its original online, RootCompleted and resource-release promises directly. It removes the four-second observation race and uses the same package's existing thirty-second whole-case correctness guard. Actual model and auxiliary calls, completed ledger records, permits, exact lost-release behavior and native cleanup remain asserted. The shared knowledge-task completion observer also uses its owning framework guard. It preserves exact completed calls, the original released receipt, zero retained per-root leases, immediate failure/cancellation and its existing yielding; elapsed time alone cannot veto a valid completion. A canonical terminal assistant error is matched to the exact accepted Root, retained as a tagged outcome and rethrown after the existing safe diagnostic; auxiliary errors and another Root cannot stand in for that outcome.

The live sync fixture uses a ninety-second whole-case deadlock guard. A complete local success path required 59.643 seconds under an intermediate sixty-second guard, leaving insufficient room for shared-runner variation and cleanup. The final guard accommodates that measured compound workload. Its original 512 messages and Parts, native tail, both share generations, fifteen-second predicates and every writer, batch, history and byte assertion remain unchanged. The adjustment changes only the former forty-five-second framework guard.

The generation-only sync fixture uses the same ninety-second whole-case guard as the live fixture. In the covered original workload its first generation and history were complete at 38.902 seconds; the second generation began at 39.054 seconds, leaving less than six seconds before the former forty-five-second framework guard. That guard preempted the original fifteen-second second-batch predicate. Only the whole-case guard changes; both complete generations, the original 512 messages/Parts, work budgets and every existing predicate and content assertion remain required.

The live knowledge-update fixture awaits its original heartbeat and actual held business-request entry without four-second observation timers, under its existing thirty-second framework guard. Before task input it subscribes to the original Runtime's terminal assistant errors and matches the exact accepted root, including an event received before the input reply. A producer error competes with request-entry readiness without a timer and retains its original safe failure diagnostic and error. The observer unsubscribes and the business barrier releases during normal cleanup. The connection must remain uncancelled while selection changes, and the original next-model-boundary, call-count, ledger, immutable input and Skill-provenance assertions remain unchanged.

The Hosted Question fixture subscribes inside the actual Runtime before input, filtering the original Session's Asked and producer failure/completion events. Callbacks retain the original outcome without issuing HTTP requests. Asked readiness triggers one original HTTP pending query matched by the exact Question request ID; producer failure is reported with the existing safe summary and rethrown. Every observer unsubscribes in finally. This replaces five-millisecond HTTP polling and its four-second readiness cutoff under a thirty-second whole-case guard. Product deadlines, original three-second cancellation checks, creator-removal/private-waiting assertions and close/cold-restart paths remain intact.

The Hosted cross-object authority fixture awaits its original heartbeat, first model request, shared projection and held-export attempt without four-second readiness races. Five accepted Roots retain all model, tool, private/shared history, held projection and original release assertions under one ninety-second correctness hang guard. A canonical terminal assistant failure is matched to the exact accepted Root, retained without rejecting an unobserved promise, reported through the existing safe diagnostic and rethrown. The subscription starts before input and ends in the original cleanup. This scoped framework guard is not a product latency or capacity SLA; command, proof, cancellation and connection settings remain owned by their existing product paths.

Long native/model, synchronization, capacity and cloud/handoff fixtures explicitly select the Service's existing connection settings with a 25 ms heartbeat and its canonical default 30,000 ms offline interval. The fast heartbeat preserves their original readiness observation; the default offline interval accommodates genuine cold preparation without changing product settings or adding task retries. A coverage reproducer had already accepted native input and emitted 100 heartbeats before the Service closed it with code 4008: the last heartbeat was 391 ms old against the fixture's artificial 300 ms lease, before Asked or an upstream model request. The shared fixture retains 25/300 ms as its default for heartbeat-loss, held-callback and other connection-unit regressions. The original transport formulas also derive 30-second sync/blob observation deadlines from that negotiated offline interval, instead of the fast fixture's five-second/300-millisecond observations. Cancellation and unknown-outcome handling retain those original formulas; no independent timer override is introduced. Whole-case guards, command/proof deadlines, test synchronization predicates, workload sizes and the explicit capacity stage/total budgets remain unchanged.

## Alternatives considered

**Retain the short races and repeated pending requests.** They introduce separate completion thresholds and additional transport work rather than observing the native producer's readiness and failure.

**Increase product defaults or unrelated deadlines.** These fixture corrections select the existing product offline default for long integration work. They do not justify changing product settings, unrelated tests or explicit capacity acceptance.

**Accept a failed producer or reduce the workload.** A longer framework guard cannot repair UnknownError, lost evidence, authority failure or incomplete native drainage. The original outcomes and assertions remain required.

## Consequences

These are scoped correctness-fixture choices, following the existing [test design](../../../../.synergy/skill/testing-guide/references/test-design.md) and [local verification](../../../../.synergy/skill/testing-guide/references/local-verification.md) guidance. The owning behavioral assertions remain required; each run establishes its own platform, capacity and complete CI results. The knowledge-recovery family retains its verified fresh-read batching correction and all recovery, byte, rollback and cold-start assertions. Its eight instrumented correctness cases use a sixty-second whole-case framework guard: the measured repeated-recovery prefix reached 26.963 seconds before invoking the independent CLI child, whose original thirty-second watchdog and exit/pipe drainage remain unchanged. The earlier noninstrumented final case completed under its original thirty-second guard; that sample does not bound instrumented cold startup. The 10,000-message capacity workload and its 240-second stage and 600-second total budgets remain unchanged. Later acceptance updates record actual results without replacing those independent requirements.
