# Decision Record: CI 批次调度、静态夹具与精确选测

Status: implemented

## Problem

CI 的反馈时间同时受排队、重复准备、测试执行和分片不均影响。[全量运行样本](https://github.com/SII-Holos/synergy/actions/runs/37149451287)显示，新增浏览器文件缺少历史权重时会被当作很短的任务，而分区编号无法稳定代表其测试内容。浏览器夹具重复开发构建、重复 Task Home 成功控制，以及宽泛的 Desktop 与 native 输入归属也增加了计算量。取消但未获 runner 的 job 可能有 GitHub 合成的开始时间，直接相减会高估计算消耗。

## Decision

耗时快照以 OS、架构、Bun 版本和完整测试批次身份记录最近十次成功样本，suite 估时不再依赖分区编号。分区保持原有隔离批次，runner 分配估算两个执行槽的完成时间，保持既有执行池数量与生产者依赖。新批次使用同类样本的保守分位数。计划绑定快照摘要，候选权重随已通过准入的报告发布并经人工评审进入版本控制；它不参与测试是否通过的判断。队列与计算核算要求真实 runner 或 step 执行证据。

Workbench、Agenda、Office、Decision 和 Settings 浏览器夹具复用输入寻址的静态构建，每个用例仍拥有独立页面与状态。缓存身份包含源文件、依赖、alias 和 stub，复用前核对文件清单和字节，发布使用锁和原子替换。Task Home 成功验证合入现有短语义控制，停止与重试保持独立；Docker fault 用例只初始化真正接受故障注入的实验。Decision 与 Provider 的请求状态矩阵保留真实浏览器验证，同时复用静态编译；页面接线、键盘、几何与持久化行为保持覆盖。模型目录数据组合在 Harness 层使用真实临时缓存验证，Presets 保留产品启动、CLI 错误与持久化集成。

选测区分经双侧输入分析证明的独立测试入口、共享测试设施与生产代码。精确 coverage exemption 修改按所属包及源文件传播；阈值、命令、结构与未知输入保持全量。Web/Desktop 修改保留 Desktop 验收，原生修改保留原生平台和完整覆盖率基线。已知 benchmark adapter 使用专属映射；共享或未知文件仍选择所有 native harness。完整 dev/main 与每日冷运行保持启用。

基础准备在同一生产者内缓存 native 与 SDK/plugin 中间产物，最终 Web 和分发继续绑定被测提交。Prettier 使用内容缓存，外部 native 包只复用经过验证的对象和索引。安装测试的显式下载缓存按当前全部 tgz 内容摘要分区；即使包版本没有变化，也不能读取旧包内容。每次安装的 Home 与安装目录仍全新。冷运行绕过构建、中间产物及外部 native 对象缓存，正常依赖下载可以复用。

## Alternatives considered

**付费增加 runner 容量。** 保持免费执行资源，优先减少现有流水线的重复计算；并发增加本身无法消除重复准备和无效计算。

**直接删除慢测试或只运行单个变更文件。** 这会丢失集成、平台与包覆盖率证据。这里只合并能证明重复的行为，保留独有断言和完整受影响 suite。

**复用整个浏览器、安装 Home 或测试成功结果。** 可变状态会污染后续用例并掩盖隔离缺陷，因此缓存限于可验证的编译和下载内容。

**将浏览器请求状态矩阵迁入 Babel 编译的 Bun DOM 测试。** 窄测发现 inline source map 只恢复文件路径，lcov 仍包含超过源码长度的生成行号，直接合并会污染覆盖率阈值。因此这些场景保留浏览器执行，独立的覆盖率重映射工作不纳入本次优化。

**增加分片与生产者 job。** 在共享并发额度下可能延长排队。本次保留队列拓扑，先校准权重并消除重复工作，再以实测结果决定是否调整容量。

## Consequences

输入与报告验证增加了少量本地 I/O，并需要维护稳定的缓存身份和选测反例。缺少可解析输入时仍可能运行较多测试；这是避免漏选的明确取舍。新版本工具链缺乏匹配样本时使用保守估计，性能收益需要完成的 GitHub 运行验证，局部耗时与离线调度估算不能相加为整体提速。约十分钟仍是优化目标，测试和覆盖率准入不因超时目标而放宽。操作入口与测量口径由 [CI 验证](../../../operations/ci.md) 定义。
