# Decision Record: 显式保留 benchmark 判题修正

Status: implemented

## Problem

原生 verifier 自身可能错误地判定已完成的输出。DOOM 启动检查将已有帧文件当成新进程就绪，导致新 VM 初始化前就被终止。直接接受 reward 会混淆解题错误与判题错误，静默修正冻结任务则会破坏实验身份和原始成绩的可追溯性。

## Decision

经过运行对照验证的修正以 [独立补丁](../../../../benchmark/patches/README.md) 保存，绑定上游 revision、原文件摘要和修正文件摘要。默认清单与 runner 不自动应用补丁；修正实验必须使用独立题目副本与新的冻结身份。原始 reward、修正后的验证结果和所有尝试的消耗分别保留。

输出重建只复用原生记录中模型实际写入的内容，不引入参考解或人工解题修复。未保留原始二进制时，即使重建使用相同编译器且产物大小一致，也只能标记为源码重建验证，不能声称原始二进制的字节身份已经确认。

## Alternatives considered

**静默修补所有现有运行。** 这会让同一个实验身份对应不同判题条件，并掩盖原始错误观察，因此不采用。

**不断重跑模型直到通过。** 这会引入新的解题样本和成本，且不能解释同一答案为何被判错，因此先对既有输出做无模型调用的诊断。

**将所有原生失败都认定为解题失败。** 原生测试也依赖进程、文件和时序，实际对照已经表明这种解释会错误归因，因此解题状态与原始 reward 分别记录。

## Consequences

实验能保留原生可比视图，同时公开修正依据。维护者需要管理额外的任务摘要和验证条件；修正结果不能伪装成未改动 verifier 的原始成绩。具体的失败机制和验证记录留在 [复盘](../../../postmortem/0016-stale-frame-invalidated-doom-verifier.md)。
