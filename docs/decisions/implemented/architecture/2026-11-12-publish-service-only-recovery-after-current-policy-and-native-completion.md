# Decision Record: Publish service-only recovery after current policy and native completion

Status: implemented

## Problem

A reconstructed H1 namespace still has the H0 deployment and an inactive prepared signer. Releasing its restoration hold before publishing a fresh identity and installing the actual H1 service settings could revive old browser authority or start the target with different clients. A successful SQL publication also needs a recoverable native completion when its original observer or Source has closed.

## Decision

The first complete service recovery supports a canonical zero-writer cohort. Its owner streams the actual namespace, checks unpublished ownership, and rejects member, hosted, resource, Session, unknown operation and external composition facts that require additional reconciliation. Known schema metadata and native checkpoint/maintenance receipts do not imply active writers. An empty caller-supplied roster cannot certify recovery.

Publication consumes the original Target, authenticated existing prepared key, callback-bound physical Source inspection and verified H1 native settings. The signing owner rechecks the actual covered H1 journal and original current-policy receipt in the target write transaction. It retires legacy logins before changing Deployment incarnation, reuses the prepared key, and commits a strict publication receipt under the original restoration hold. Canonical publication rows require their owning mutation frame. Completion and failure guards remain attached to the actual outer commit, including when a nested failure is caught. Exact retry returns the original receipt.

After installation callbacks close, the domain reads that committed receipt through its composition-registered publication owner. An independently retained completion installs the source's effective H1 settings in the canonical configuration file, completes the original native intent, then releases only its original restored maintenance operation through [native publication](2026-11-12-complete-native-publication-before-releasing-restored-admission.md). Configuration publication opens the original root descriptor before revalidating the actual Home permit. Local native `openat`, `mkdirat` and `renameat` operations create and replace the configuration relative to retained descriptors; replacing the root pathname cannot redirect the write. An unpublished temporary file never truncates the prior configuration. Native target preparation preflights this Darwin/Linux requirement before Source retirement; unsupported platforms remain blocked. Closing the service joins accepted completion; cancelling an earlier observer cannot undo a committed publication.

Ordinary restored startup first inspects the completed native frames without opening SQL. It then opens the original primary Store and verifies the actual domain receipt, fresh signing identity, native configuration and original released operation before migrations, authentication or transports. Once completion and release are established, ordinary configuration changes remain valid and a later backup may replace the maintenance current pointer. Completion retry does not overwrite those later settings.

## Alternatives considered

**Publish directly from metadata or a caller verification function.** Neither binds the original prepared private key, actual Source fence, canonical H1 policy and native settings.

**Apply native settings while retaining the installation callback.** Native completion takes the original Home lock independently; nesting it would compete with the installation lock and conflate reversible preparation with committed completion.

**Treat all nonempty cohorts as recovered.** Registration and resource facts identify additional possible writers. They require their actual owning retirement or reconciliation proof.

## Consequences

The focused service fixture closes Source and Target callbacks, reconstructs H1 from fixed archives, cancels the final publication write and retries with the same inactive key. It then closes the Source, lets the publication observer leave, retains an actual settings-write acknowledgement failure for shutdown, retries from the same committed receipt, holds the subsequent real native settings write while service shutdown waits, and reopens the restored Home through ordinary startup. The old H0 cookie is rejected; a new login and H1 client authorization succeed; restored binary bytes retain their hash. A new backup and canonical configuration edit remain restartable, and exact completion retry preserves that edit. A real root replacement at the native write boundary leaves replacement configuration unchanged while the original Home guard refuses readiness.

This unit enables normal control-plane service recovery with no unreconciled external writers. Nonempty member, hosted, resource and Session cohorts remain blocked until their owners supply real reconciliation. It does not enable machine handoff, resume recovered Agent work or grant automatic Continue.
