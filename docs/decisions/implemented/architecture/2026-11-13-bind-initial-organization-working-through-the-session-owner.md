# Decision Record: Bind initial organization Working through the Session owner

Status: implemented

## Problem

A selected Service Workspace can be available through its authorized file API while the native Session has no Working reference. Ordinary file tools then remain unavailable. A native directory or fabricated move receipt cannot represent this initial selection, and early execution authorization precedes the actual materialized task root.

## Decision

The existing model-preparation contribution binds the actual accepted resource contract after root materialization and before tool preparation. It describes the selected Service Workspace and publishes a contentless, pathless Catalog alias through the original Catalog owner. A strict version-three Locator retains the native owning Session, original grant/root provenance and exact organization, deployment, project, resource and generation. It is not a move or Handoff receipt and grants no execution authority.

The original Session transition consumes the actual Catalog and its registered synchronous file-source inspection owner, retaining the Workspace identifier with a null native directory. It rechecks the complete Catalog in the publishing transaction. It cannot replace a native directory or another selected resource. The model loop reloads the committed Session after preparation.

An interrupted Catalog publication can be reused by a later accepted task for the same native Session and resource tuple. Its original audit provenance remains unchanged; the new task still supplies current authorization and uses the original Session transition. Optional whole-root fields are omitted from JSON bindings rather than serialized as undefined.

Whole-root Handoff uses the archive owner's existing empty-root representation and reader-seven compatibility gate. Older peers reject before source freezing. Object publication destinations remain nonempty paths; an initial Locator cannot substitute a target publication receipt. Home reader four fences previous native readers before these bindings can persist.

## Alternatives considered

**Relax the tool's Workspace requirement.** Subsequent resource resolution still needs an actual owned Workspace.

**Invent a local directory, content head or move receipt.** This creates independent authority or evidence for an operation that never happened.

**Bind before materializing the task root.** The original binding proof correctly refuses that phase.

**Rewrite orphan provenance to the next grant.** Provenance records the original publication; current authorization comes from the new accepted task.

## Consequences

Ordinary ReadTool can access a selected remote Workspace without compute allocation or local fallback. Current access loss still rejects reads and new commands. Real TLS/SDK tests cover an active writer with a no-compute observer and a cancelled original task followed by an independent task after interrupted Session publication. Separate owner tests retain native binding, cold metadata, strict Locator and whole-root compatibility checks.
