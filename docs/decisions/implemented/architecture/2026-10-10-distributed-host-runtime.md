# Decision Record: 暂停 Session 的手动跨 Host 迁移

Status: implemented

## Problem

用户需要将一个暂停中的任务及其未提交文件转移到另一台已连接设备，并沿用已有消息、工具结果和文件历史继续工作。复制 transcript 无法恢复未消费输入和执行证据；重跑历史工具或模型会重复计算，并可能重复外部副作用。设备故障后的自动接管还需要可用副本、发现与执行权仲裁，超出第一版所需。

## Decision

由用户从暂停任务的操作菜单选择目标设备，客户端使用已有服务器连接和生成 SDK 完成两端交接。第一版采用按需传输和双端持久状态，不建立 Coordinator、固定设备数量或全局调度服务。[Session 迁移架构](../../../architecture/session-transfer.md)定义数据、门禁、恢复和支持范围。

源端捕获前持久冻结 Session；目标端验证完整包、私有 Workspace 和历史对象后返回 prepared 回执。源端持久记录 committed 后才释放激活凭证。目标端核对摘要与凭证，在一个业务事务内发布原 Session 身份和索引。迁移保持暂停，用户在目标设备点击继续才触发执行。已完成的计算结果作为记录恢复，不执行 trace 中的模型或工具。

取消凭证与激活凭证分离。源端只能在提交前签发取消凭证；目标端用其校验和清理未激活状态。提交后通信失败保留源端门禁，重试完成原目标，不能自行回滚。重启从数据库和持久传输包恢复，客户端无需保留唯一副本。

Harness 拥有协议、逻辑证据和执行门禁；Local Runtime 通过显式注册的 Host 接口捕获和物化原生目录。复制目标 Workspace 建立新身份，Scope 保留逻辑归属并使用目标自己的本地配置。权限批准和跨设备凭据不随任务复制。目标始终使用自己的执行环境。

## Alternatives considered

**直接导入 SessionExport。** 该接口服务于历史查看和导入，身份及执行语义不同，不能代替保留 Session 身份、Inbox、Rollout 和原子交接的迁移协议。

**在目标重放 trace 的所有调用。** 已完成计算无需重新执行，且工具副作用无法由重放安全消除，因此迁移只恢复已持久化的证据和暂停位置。

**第一版实现去中心化自动接管。** 网络分区下的执行权、未持久步骤、可用副本和外部效果对账都需要另外的协议。手动交接在两端在线时满足当前目标，之后可在相同持久数据模型上扩展调度。

**复制整机 Home 或 SQLite 活跃文件。** 会携带不相关任务、配置、凭据及进程本地状态，且不能证明单任务的一致性，因此使用拥有者记录和校验过的文件包。

## Consequences

用户可以选择任意已连接且兼容的目标 Host，不需要固定常驻协调服务器。没有长期的多设备 Workspace 副本；空间开销发生在迁移期间，成功后清理两端临时 ZIP，保留目标 Workspace 和源端只读历史。源 Workspace 的用户文件保留，由用户自行管理。

第一版传输一个普通交互根 Session，要求相同平台、版本和组件组合，至多一个独立原生目录 Workspace。子 Session 树、工作流、无人值守入口、原生 Browser/Computer 状态、不确定工具效果、活跃 Environment 操作、共享或挂载 Workspace、关联 Git worktree 与多 Workspace 文件历史会拒绝迁移。两端必须在线；单个迁移 ZIP 上限为 64 MiB，更大的 Workspace 需要后续的流式传输能力。

生产 Web 的 SPA 连接策略允许 HTTP/HTTPS，以支持用户配置的另一台服务器；目标认证与 CORS 校验仍然生效。脚本、文档和 frame 的限制不随连接策略放宽。

目标设备的模型、凭据、插件与项目配置由用户独立配置。迁移不承诺与源端完全相同的外部依赖；缺少模型或凭据时继续执行由现有执行错误处理报告，用户可调整目标配置。源端已经提交交接后不能删除执行门禁来恢复运行；目标存储永久丢失的人工灾难恢复属于后续能力。
