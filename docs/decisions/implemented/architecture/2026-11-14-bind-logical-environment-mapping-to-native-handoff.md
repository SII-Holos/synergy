# Decision Record: Bind logical Environment mapping to native handoff

Status: implemented

## Problem

A Workspace destination does not determine where future commands execute. Native and organization Environment identities have different owners, and moving a conversation cannot move an allocation or silently select another execution destination. A renderer-selected identifier cannot prove native ownership or replace participant consent.

## Decision

Handoff bridge eight carries an explicit native, organization or none Environment mapping. The complete mapping joins the confirmed plan hash; its own hash also binds source and target machine facts and prepared native conversion. Older bridges reject the new choice before source inspection or freezing. Service record four upgrades supported prior records through its central owning migration and rejects unknown addresses and formats.

The Service reads canonical project/resource selection and current Environment metadata. Its authorized paged Environment directory uses an owning project/resource index, rebuilt through the central migration for old locators. Archive readers validate that exact index kind and retain older archives without inventing missing rows. A real organization resource change updates Workspace and Environment roles in one existing selection CAS. Pure native/none mappings preserve an originally absent resource contract; they cannot manufacture organization authority. See the [empty-contract postmortem](../../../postmortem/0191-native-handoff-required-an-unowned-resource-contract.md).

The Runtime verifies the current signed machine plan and actual enrolled primary before opening a private mapping callback. Environment reader three retains bounded immutable facts while its original source, target and final activation guards require that live callback. A native target uses its inspected registered descriptor; explicit preparation can create scoped borrowed metadata without allocating compute. Its actual identity, generation and descriptor enter prepared conversion and must match activation. A new mapping hash cannot be attached to an older source fact.

Cloud return retains the selected organization execution destination by default. Downloading a private current copy requires a separately explicit compatible native or none choice. Activation stays paused; Continue and fresh execution authorization remain independent. Native processes, credentials, allocations and mount receipts remain with their original owners.

## Alternatives considered

**Infer execution from the Workspace destination.** File placement and command execution are independent choices, especially when returning a conversation while retaining cloud compute.

**Trust a renderer's Environment identifier or reuse the Workspace hash.** Neither proves the complete logical choice, native descriptor or destination preparation.

**Create an empty organization contract for every local mapping.** The real empty-contract regression shows that pure native mappings need no organization resource transaction. Creating one would invent authority.

**Copy allocations and provider configuration.** These carry physical ownership and private credentials rather than portable conversation state.

## Consequences

The existing native transfer, selection, Environment and epoch owners remain authoritative. Compatibility is explicit at each wire and persistence boundary. Tests cover legacy readers, actual commit-time callback expiry, authorized catalogs, the real enrolled native-to-none flow, and rendered explicit choices in English and Chinese. Complete cloud execution and Workspace lifecycle acceptance remain separate from metadata mapping validation.
