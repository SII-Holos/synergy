# Decision Record: Reconcile Hosted writers through original Source retirement

Status: implemented

## Problem

A service registration describes a possible writer but cannot prove that its original native Home has retired. Replacing registrations during service recovery can also conceal a missing H1 writer, revive a revoked Runtime, or make old Target execution facts appear current. The service and each Hosted namespace have separate Stores and native publication lifetimes.

## Decision

The service recovery owner consumes callback-bound Kernel namespace retirement inspections. Each genuine inspection retains its original native Source, frozen maintenance operation, permanent Home fence and service Target request. The owner fully authenticates the service H1 checkpoint before classifying records, stages its complete inventory in task-owned SQLite, then compares every supported Target record with that inventory. The canonical Hosted roster must match the entire set of original Source proofs. Member registrations, unknown native owners and missing, foreign or expired inspections block publication.

Model and Connection policy records and private credentials remain covered by the actual H1 authority Journal. Their canonical identities, resource roles and derived access references are checked against the complete H1 inventory. Supported Session directory records require the same original Hosted driver and no handoff or retained execution. Command, grant, gateway, retention, Workspace, Environment and object facts require additional owning reconciliation and remain blocked, including command counters without a pending attempt. Final-looking metadata alone does not establish physical execution settlement.

The original service publication transaction updates each verified Hosted registration to the fresh deployment incarnation and increments its revision while preserving runtime identity, public key, state, connection epoch and attribution. A private mutation frame permits only those exact writes and their owning authority Journal entries. Any later unclassified mutation poisons the actual transaction even if its immediate failure is caught. The commit guard retains all original Target and Source inspections; no new enrollment or key is created.

Version-two service publication receipts add the verified H1 namespace hash and bounded per-Runtime children under the existing receipt. Each child binds the original Source reference, original registration and exact published registration. Version-one receipts retain the zero-writer path without conversion. The original Home publication owner reads a single requested Runtime mapping and its current canonical registration, preserving revocation and monotonic revision and connection epoch checks. Kernel publication inspection binds those facts to the service's actual committed publication and callback lifetime so a separate Hosted Target can consume them without reverse package imports or structural proof objects.

The service can complete its own native publication before a Hosted Target completes. The Hosted Target remains independently held until its owning native recovery verifies the actual H1 archive and service publication. This ordering avoids a readiness cycle and does not claim atomic commits across the two Stores.

## Alternatives considered

**Accept a caller-supplied roster or verifier.** Neither proves the full canonical H1 roster, original Source lifetime or permanent retirement. The implementation accepts only Kernel-issued opaque inspections.

**Enroll replacement Runtimes.** Replacement identities lose original key, revocation and Session ownership evidence and can conceal stale Target facts. Publication updates only the verified original registrations.

**Allow whole execution roots after observing final records.** Command acceptance and a final-looking counter do not prove native work, resource streams or retained grants have settled. Unsupported owners continue to block until their actual lifecycle supplies coverage.

**Persist another recovery phase ledger.** The original Home installation and committed service publication already own progress. Bounded immutable mapping children extend that publication evidence without introducing another authority.

## Consequences

The service unit uses genuine Kernel NativeSource retirement fixtures with actual format-four Source Homes and original format-three Target installations. It verifies complete roster coverage, copied and expired proof rejection, rollback, preservation of revoked registrations, caught late-write poisoning, private policy records, missing access coverage and an unknown retention owner beyond an ordinary page. These fixtures establish the service reconciliation rules; actual Hosted native credential installation, task recovery and Continue remain separate owning integration evidence. Recovery of a cohort with unsupported execution or infrastructure facts stays blocked.
