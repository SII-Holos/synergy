# Decision Record: Close handoff resource generations without input replay

Status: implemented

## Problem

A paused Run must stop retaining source resources before service commit. A terminal release would falsely finish that Run, while retaining the old grant would permit stale use or keep occupancy locked. After cancellation or paused target activation, the original accepted input still belongs to its original actor and machine epoch; rewriting it to the new controller would destroy admission evidence.

## Decision

Current grants distinguish terminal release from nonterminal handoff and control closure. Handoff closure binds the exact source generation, handoff tuple, frozen package and prepared target hash. It owns a separate finite machine signature and immutable receipt and checks the actual gateway completion set both inside the transaction and at commit. Grant state, occupancy, retained index, closure receipt and authority history commit together. Receipt replay rechecks canonical original reception and closed-grant control provenance without requiring the historical source to remain the current directory driver. Generation-zero provisional intake has its own closure cause without inventing a materialized Run.

The service inventories retained grants by an owning derived Session/epoch index. Every grant writer updates that index in its existing transaction. A central migration rebuilds it from validated canonical grants; hot inventory pages re-read the canonical grant and original accepted command and verify the count against the directory. A local lease list cannot establish completeness. Inventory and close require the current prepared handoff and authenticated source connection, and neither returns business credentials or body data.

The native source obtains the current inventory outside its final SQL transaction. Each close proof matches canonical original reception and, for a successor grant, the exact stored independent Continue. A bound generation also requires the original native root and Run. Proof creation cannot bind execution while frozen. The source retains observed closure receipts and the final empty-inventory checkpoint; its final surrender verifier only reads that checkpoint and rechecks existing native barriers. Service commit independently requires zero current retained grants. Losing a close reply does not reopen a generation; a fresh inventory reconciles progress without replaying input or repeating the closed mutation.

Paused activation creates no grant. A later independently admitted Continue supplies current control provenance and a new provisional grant, preserving the original input actor, admission, attempt, resource contract, root and native budgets. The service owns the current root-grant pointer and closes any prior held generation before replacing it. A source cancellation also requires a fresh explicit Continue, whether its resources had already closed or remained held. Current control attribution remains separate from original input attribution.

Cancellation does not restore authority to an unclosed source generation. Handoff preparation indexes its reserved epoch in the same transaction. A migration-owned derived Session/epoch index locates the canonical latest outcome using the directory's next reserved epoch; it is not a second barrier record. Shared execution eligibility rechecks the exact source tuple, cancellation fact and frozen command cutoff. It requires the canonical accepted input or independent control to cross that cutoff. Binding, description and actual gateway reservation/authorization/dispatch share this check, including capabilities reserved before the handoff. New ordinary tasks admitted after the cutoff remain usable. Retention inspection, terminal cleanup and historical receipt reads do not run this execution gate. See [the retained-cancellation incident](../../../postmortem/0111-cancelled-handoff-reenabled-retained-grants.md).

A continued terminal release must name its current grant ID explicitly. The service compares that selector with its resolved canonical grant, including before idempotent receipt lookup. Legacy proofs without continuation retain their original contract; any supplied selector must still match. Clients verify the same current binding, original input and control provenance. The current organization portability reader retains this continuation contract and requires Core-first publication; earlier readers are rejected before package content is read. See [native Workspace controllers](2026-11-12-stage-native-workspace-files-through-organization-controllers.md) for that publication prerequisite.

Cleanup inspection uses the same retention operation with a separately signed, non-executable purpose. Exact original root, accepted control and optional grant/generation selectors return canonical known state or a proven absence for that control. A central migration owns the derived control-to-grant locator; exact historical selectors never mint a replacement grant. Description/binding schemas reject the cleanup purpose. Historical inspection verifies current machine identity and canonical original/control reception, then reads that accepted Runtime/epoch partition independently of the current directory driver. Execution acquisition still requires its current binding. Exact old source closure can therefore settle after target activation without issuing terminal release or reopening occupancy.

The native execution source persists an unresolved, bodyless cleanup intent before each description or binding dispatch. Once observed, each actual grant/generation has its own retained entry. Every outbound dispatch has its own unresolved entry, including repeated uncertain calls for the same control. Its original parsed proof expiry is committed before transmission. A matching verified response confirms that dispatch immediately; an unknown response cannot finally link or settle against a transient old generation or absence until the original signed commit window closes. The native clock only schedules probes; final cleanup compares the verified service inspection timestamp with the persisted signed expiry. Service write guards reject a delayed callback after that window. This retains reconciliation progress even when inspection overtakes the original request or the native process restarts. The entry stores canonical input/control lookup identities and acceptance digests, not another grant authority or accepted-body copy. A startup migration seeds a deterministic probe for every legacy reception, including settled receptions whose ordinary grant may have been reacquired by older code. Original released reception rows are never reopened. When a Session returns to a previous Home under a newer binding, native cleanup still reads the exact old accepted request/control, attempt, slot and root within the canonical organization/project Scope. It does not require historical acceptance to match the mutable current driver/epoch or Command State. Those current-state checks remain on execution description and binding. See [the returned-history incident](../../../postmortem/0116-native-cleanup-rejected-returned-session-history.md).

The connected observer reads bounded pending pages and exact Session/root partitions. Its bounded ready/retry cache falls back to the SQL indexes when full; it does not cap retained history or grant count. Running work waits for native events, while unresolved terminal tails or replies retry without repeating acquisition. A canonical historical terminal receipt settles only its exact generation. Permanent handoff/control closure has a separate local nonterminal settlement, and proven control absence settles only the corresponding unobserved intent. Native terminal evidence remains required before requesting a new terminal release. Closing stops subscriptions, aborts pending work and awaits accepted callbacks; an ignored late callback cannot write its response after cancellation. See [the reused-intent incident](../../../postmortem/0115-renewed-cleanup-intent-reused-an-old-generation.md).

## Alternatives considered

**Call terminal release during handoff.** That invents completion or cancellation for a Run whose task, continuation and budgets must survive.

**Rewrite original input to the destination or controller.** It changes the immutable actor and admission and makes a repeated initial prompt appear legitimate.

**Close only remembered local leases.** A crash can leave an accepted provisional or held service grant before its local callback records a lease.

**Reuse the original grant after activation.** Its source binding and generation no longer authorize destination execution or independent control.

## Consequences

Legacy grant upgrades preserve original bytes on read and do not fabricate handoff history. Previous strict grant readers reject the new version. The retained index is derived and migration-owned; grants and directory counts remain authoritative. Nonterminal closure does not reset native budgets, create a root, unpause work, allocate target resources or dispatch a model.

This unit implements explicit continuation, nonterminal handoff closure and automatic per-generation native reconciliation. Cleanup inspection remains available only to an authenticated current machine connection; it is not a revoked-machine recovery credential. The [integrated Environment and Workspace handoff](2026-11-14-bind-logical-environment-mapping-to-native-handoff.md) composes the public controller with the separate Environment, knowledge and WorkspaceMove owners; these closure receipts do not substitute for their native proofs.

## Verification

Service tests cover actual live gateway streams, exact source/target proofs, changed tuple/generation/hash, immutable replay, closure-write rollback, legacy migration and retained-index completeness beyond a page. Native tests preserve the original task receipt, root, actor and Run through source cancellation and target activation. Enrolled member/hosted Homes use generated APIs over verified HTTPS and actual WebSockets to close source occupancy, preserve an unknown committed-close result, activate paused, admit a separate Continue, bind a fresh generation, finish the same native Run and release the exact new grant. No user Runtime or real Home is used.


Native cleanup regressions cover ordinary generation-two reacquisition, an older pending terminal receipt followed by a lost renewed-bind response, lost provisional description, cold migration from settled legacy reception, exact Store/artifact isolation, bounded pending/root pages and close during an accepted inspection. Enrolled HTTPS/WSS controller tests use production native execution attachment after cancellation and paused target activation, preserving the original root and actor while the new grant releases automatically. The transferred source separately reconciles its permanent closure without a terminal release request.


The native adoption fixture now receives a real signed Inbox task and canonical Run before roundtrip. Original cleanup follows A/e1 to B/e2 and back to A/e3; the continued variant first cancels an actual reserved handoff and accepts an independent Continue, then uses B/e3 and A/e4 without reusing the cancelled epoch. Both retain the old local cleanup intent and immutable reception, reject altered Scope/root/control and future epochs, and keep old description/binding unavailable while the returned Session is paused. This is native owner evidence, separate from the enrolled HTTPS/WSS controller coverage.
