# Decision Record: Establish the organization shared synchronization ledger

Status: implemented

## Problem

Shared Sessions need a service-owned authorization and sequencing boundary before a member Runtime can export local state. A stale exporter must not publish into a newly revoked or re-shared Session, and the organization database must not become a transcript or local-path mirror.

## Decision

The organization protocol defines strict share-change, generation, checkpoint, batch and safe-event DTOs. The service stores a versioned per-generation checkpoint, batch idempotency marker and event projection. Creator-only share and revoke mutations use an exact generation compare-and-set, update the Session directory and private/shared visibility indexes in one transaction, and create a fresh generation state. Handoff blocks both mutations; revoke also requires the current driver Runtime to belong to the creator.

Each export batch binds the Session/project, binding epoch, share generation, contiguous sequence range and SHA-256 payload digest. The service rechecks current authorization and directory metadata, rejects stale generations or bindings, writes all event projections plus the batch marker and advances the checkpoint atomically. An exact duplicate returns the committed checkpoint; gaps and conflicting overlaps return a revision conflict without advancing it. Event reads authorize through the current shared Session and use bounded cursors. Projections contain only safe Session metadata, bounded summaries, integrity digests and attachment descriptors.

The member Runtime advertises synchronization as a separate capability. It writes safe event drafts and the latest safe projection of each event to a durable local outbox, persists the sequence-assigned batch before transmission, and removes the batch only after the service acknowledges its committed checkpoint. Payload preparation and transmission use bounded windows, while the outbox retains unacknowledged history without a product quota or silent discard. A reconnect re-reads the current share and binding before retrying, so an old generation cannot overwrite a later share; after a new share generation, the retained projection is rebuilt into a fresh baseline before incremental drafts are sent. Internal Cortex descendants are exported into the root ledger only after their parent chain and binding are proven; independent Sessions do not enter that ledger. Cortex lifecycle and parent-completion notification events remain metadata-only. Attachments and tool result/observation artifacts use content-addressed, generation-bound manifests and authenticated chunks no larger than 4 MiB; the service verifies the complete digest before making content readable and reauthorizes every status or content request. Search scans only the current generation's safe summaries, with bounded snippets and cursors, and never searches private bodies or blob bytes.

Canonical Session, message, Part, Rollout and Inbox notification commits capture thin identities through the original transactional StorageEventSinks queue. Capture and canonical mutation commit or roll back together, including native Part removals that history cannot reconstruct. Notification capture retains only the original bounded public summary and creation time before Inbox consumption. Native binding reads use Core.storedInfo to verify the actual Info/index/Scope/parent chain without client views, on-access migrations or lifecycle startup. Pre-mutation RAM diagnostics skip an incomplete creation pair without treating it as authority; capture, conversion and deletion still require valid original metadata.

A selected root pump reads at most 128 original delivery selectors, prepares masked DTOs and native artifact references outside SQL, and publishes at most 128 events or 1 MiB through the existing outbox writer. Only unsequenced updates of one identity coalesce. The generic queue is acknowledged only after durable local acceptance, while the original remote batch/hash ACK controls sequenced work. Failed conversion, close and cold restart retain original deliveries and drafts. Scoped drainage does not claim other roots are empty; a frozen root cannot starve a healthy root. Only the genuine original Source preparation callback can perform bounded local conversion while its epoch is frozen; escaped callbacks and ordinary frozen network dispatch remain rejected.

Actual pre-mutation guards register synchronous failure observation before native Session-owned and existing organization-sync writes, covering FULL before a commit fact, outbox conversion and batch/ACK persistence. Only the original SQLITE_FULL or ENOSPC cause reports storage_full; other failures retain their original error. Recovery requires a real local State write and COMMIT, then an exact pending observation acknowledgement before content dispatch. A newer failure or cancellation cannot be cleared by an older response, and cold remote-blocked recovery uses the same durability check. Status observation never acknowledges content.

Session deletion and Rollout evidence pruning retain dependencies while a root has native deliveries, drafts or a sequenced batch. Native Part replacement and removal keep their own write path. Existing artifact locators preserve bytes through collection until the original ACK. Attachment content references use the existing family indexed by original hash and byte count alongside its current Part alias. Replacing an attachment cannot change the Ref selected by an immutable old batch. Startup migration indexes only a provable existing alias. After acknowledged content permits native Session removal or Rollout retention, a fully absent canonical Session pair or exact missing Artifact metadata leaves that alias untouched without inventing an index. Partial or inconsistent owners, changed references, missing retained bytes and other read failures still block migration. Missing original Refs fail without consuming the immutable batch; this writer does not reconstruct lost historical aliases.

A fresh shared generation publishes its existing preparation coverage fact only in the original sharing transaction, after canonical metadata and checkpoint agreement and bounded empty-prefix checks for both event and projection state. Subsequent signed batches maintain canonical events and projections atomically, so first-screen reads do not replay an already covered fresh generation. Retained generations without that fact still use the original paged preparation path.

Prepared native history reads capture the same chronology-ID membership in one original readonly Store snapshot, paging marker keys in windows of 128. They retain the original first-four individual and subsequent 32-header hydration windows, deleted-header handling and storage-error propagation. Concurrent appends enter later incremental work; they do not change an already captured traversal. Missing or inconsistent chronology coverage uses the existing owning repair path. Captured ID and distinct pending-selector metadata remain proportional to history or pending work; these windows do not establish a constant bound on total Runtime or Native Store RSS.

Sync transport two extends the original state exchange with strict, safe storage observations. The service confirms this capability only when its actual storage-observation owner is registered. The current authenticated driver may report only `blocked/storage_full` or `pending` for its exact binding, sharing generation and unchanged checkpoint. The service updates its existing shared state under the live connection's final commit guard; this response neither acknowledges content nor deletes local work. Legacy sync-one state queries, batches and blobs retain their original contract, while a new Runtime requires an explicit sync-two acknowledgement instead of silently downgrading. Connection closure and caller cancellation preserve the original offline error, including after a reply arrives; only absent negotiation or a mismatched reply is a protocol error. A response outside its original lifetime cannot clear the local fault. Recovery confirms `pending` before original batch transmission resumes, and only the real canonical batch acknowledgement marks content synchronized. Full-disk capture and its retained native dependencies remain owned by the original transaction and durable outbox, not by the reported status.

Runtime batch and Blob mutations retain the actual captured `RuntimeConnectionLease`, rather than only its handshake. Its synchronous current-socket guard reaches the original SQL COMMIT for event/checkpoint publication, chunk/manifest publication, complete-hash publication and invalid-content removal. A connection closing after the final awaited write rolls that transaction back. Already committed partial chunks remain available for ordinary authorized retry; a missing reply never proves rollback. Tests hold each actual final write, close the signed connection and await its server-side pending producer before inspecting canonical records and artifact references. Browser-credential uploads retain their separate current-authority path.

An explicit Host can repair a lost historical attachment content index through `repairOrganizationSyncAttachmentContent` on the existing Runtime facade. The entry binds the actual enrolled namespace, organization and Runtime, original writable primary and physical writer, and an opaque backup lease still draining. It drains the original cohort before bounded metadata traversal, selects only the original same-epoch Session owner and fully verifies retained bytes against the immutable batch hash and length. Publication reenters the genuine guarded writer, checks the original drain receipt and unchanged batch/alias/Ref, and retains a synchronous original-frame COMMIT guard. Its write advances the native tail; subsequent work must drain again. The central maintenance flag alone cannot authorize this path, and the runner's migration-access mode is not a write exemption for repair. Missing or foreign evidence, unproven epochs and frozen transfer ownership remain UNKNOWN without changing the batch, alias or content. The entry neither releases the hold nor dispatches network requests. Tests use real enrollment and native artifacts; their lower transport fixture does not establish the complete production writer cohort or installed-package acceptance.

## Alternatives considered

**A Runtime-owned share flag** would let an offline or stale member decide who can read a Session, so it could not fence revocation or enforce project membership centrally.

**Direct transcript replication** would copy local bodies and paths into the organization service, violating the metadata-only boundary and making local storage semantics part of the service API.

**Last-write-wins batches** would hide dropped or reordered exports and could overwrite a later generation, so it could not provide a recoverable checkpoint or audit trail.

Portable synchronization is a separate `organization-sync` native owner at version one; the command owner remains version five and retains its historical bytes. Its partition carries original drafts/order/projections, immutable sequenced batches, artifact locators and resumable roots. The closed header is bound to the verified original native manifest. A post-capture ACK cannot rewrite that header, SourceFrozen checkpoint or prepared hash. Native Home reader five fences older exporters before they can discard a batch on epoch mismatch.

Complete shared handoff requires bridge ten and the implemented sync-two receipt callback. New Handoff stored variant five explicitly selects sync-transfer one; source facts carry the actual checkpoint and target facts its canonical hash. Older variants remain historical facts without fabricated empty checkpoints. An original Source preparation can settle only its existing immutable batch while draining/frozen, using the same native Store, connection, batch identity and original authority. Prepared retry retains the same manifest and facts. Fresh surrender permission and final binding COMMIT both require the exact original batch marker; nextSeq alone acknowledges nothing. Precommit Target receipt inspection retains original accepted-participant/current-permission gates; postcommit inspection binds the exact target and prepared hash. These metadata reads never authorize content replay or native execution. Abort and explicit closure preserve the original Runtime and Store until their accepted local conversion/drainage has settled; a detached unsubscribe cannot consult another ambient Runtime.

Shared history resolves original events and batches against exact epoch/driver sequence windows. Each transition needs the retained committed Handoff, original machine proof signatures, surrender and activation permits verified against the archived signing identity, and the exact single-event rebind marker. A batch cannot cross that marker. Version-five transitions also validate their original sync checkpoint/hash and pending marker; versions one through four keep their own optional fields without invented checkpoints. Current roles, live connections and inspection deadlines do not certify historical facts. Reading this chain grants no execution authority.

## Consequences

The service now has a reviewable foundation for shared projections, generation fencing, pagination, replay-safe export acknowledgments, Cortex child/notification projection, generation baselines, bounded safe-summary search and resumable content transfer. Permanent asset URLs, arbitrary payloads, private Session bodies and unrestricted blob search remain outside the organization storage contract.
