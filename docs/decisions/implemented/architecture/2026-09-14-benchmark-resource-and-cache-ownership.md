# Decision Record: Benchmark resource admission and immutable cache ownership

Status: implemented

## Problem

A concurrency count alone does not account for task memory, an independent verifier, preparation or multiple evaluator processes. Cache reuse also becomes unsafe when publication is interrupted or collection races with an experiment's frozen inputs. Re-running preparation on every trial wastes time while reusing writable task state changes the experiment.

## Decision

The [scheduler](../../../../benchmark/src/synergy_bench/resources.py) admits native task and verifier resource declarations against Docker capacity after explicit CPU and memory reserves. It checks host pressure, rejects impossible requests, bounds light-task backfill and retains running work under pressure. Shared leases coordinate evaluator processes using the same cache. Kernel locks release after parent death; remaining owned containers retain their reservation until cleanup. Preparation, doctor and scored execution use the same admission mechanism. Per-attempt admission adds a 0.2 CPU and 128 MiB allowance for recording and proxy services without changing native task limits. Source and package preparation reserves 2 CPUs and 4 GiB; cross-process build slots default to two. These build reservations are admission estimates, with actual utilization retained separately. CPU/RSS peaks are sampled maxima. Recovery returns private log ownership through the retained container image before reading native terminal records; the helper has no network, retains file modes and bytes, and also works when the original container has stopped.

Reservation totals come from the current lease ledger. CPU uses `math.fsum` over the candidate and individual held reservations; integer memory is summed directly. Eligibility uses an immutable snapshot of shared CPU components refreshed with lease health and ownership, then acquisition rechecks under the budget lock. It never compares the candidate against a rounded subtraction of used CPU from capacity. Updating or removing a lease cannot accumulate floating-point residue in a second usage counter. An empty pool can therefore admit its full budget, while remaining leases retain their sampled reservations. [Behavioral regressions](../../../../benchmark/test/test_adaptive_resources.py) exercise fractional CPU samples, overlapping leases, cancellation and shared publication/release failures through actual admission. Build waits record their pressure reason in `scheduling.json`, which the bounded CI collector retains without publishing frozen plans or private inputs.

The [monitor](../../../../benchmark/src/synergy_bench/monitor.py) consumes local Unix Engine API OOM events throughout execution and the final bounded history query, then closes the reader in `finally`. Both sources deduplicate by container ID, nanosecond timestamp and event type. Engine event delivery is best-effort, history is bounded and neither HTTP headers nor a lifecycle event acknowledges complete delivery. Exact `oom_events` therefore remains null; `observed_oom_events` retains the lower bound, with partial live or retrospective coverage carried into reports and trajectory analysis. This preserves the resource record structure, native scoring and historical evidence. [Closing regressions](../../../../benchmark/test/test_monitor.py) deliver events through a real Unix HTTP stream while history completes, times out or is cancelled. The [kernel control](../../../../benchmark/test/test_oom_docker.py) keeps PID 1 alive until a child is killed by SIGKILL, the cgroup OOM counter increases by one and the monitor receives the real OOM event. Only then does PID 1 exit and automatic removal occur; the retained event must still number one. This tests observation retention without assuming the daemon publishes every event before removing a container.

The [cache](../../../../benchmark/src/synergy_bench/cache.py) owns only objects and images with benchmark receipts. It addresses immutable source, package locks, platform and recipe inputs, serializes identical builders, publishes atomically and verifies retained bytes. Run references protect frozen inputs; temporary reservations protect explicitly supplied artifacts before initialization can collect unused objects. Independent runs can retire their own references between enumeration and file open: inspection skips only missing references, while surviving references remain protected and malformed or unreadable references fail the operation. The [cache regressions](../../../../benchmark/test/test_cache.py) reproduce this retirement using real files and verify that live frozen inputs cannot be collected. Collection never claims shared images and never performs global Docker prune. Image sizes are reported as logical bytes, with shared-layer over-counting disclosed. Source bundles register their inventory before atomic publication; missing publication remains invalid rather than becoming unowned data. Intermediate source/package images are counted only when owned artifact receipts identify the exact image ID; bundles remain usable after collecting an unused intermediate image. Read-only harness bundles share the same image prerequisites; prewarming deduplicates task images and checks capacity in batches. Long-lived execution relies on frozen-input references, allowing unrelated unreferenced cache collection.

Runtime recipe invalidation follows the actual executable boundary. [Synergy preparation](../../../../benchmark/src/synergy_bench/prepare.py) keys TypeScript sources plus the shared deadline helper; [external preparation](../../../../benchmark/src/synergy_bench/engines.py) independently keys every native Node entry point and observer. External harnesses use their own kind-checked bundles, not the unused external files copied into a Synergy bundle. Any new executed dependency must join its owner's recipe key and [invalidation regression](../../../../benchmark/test/test_prepare.py). Full bundle receipts still validate all retained bytes. The [CI collector](../../../../benchmark/src/synergy_bench/ci_evidence.py) deliberately keeps native Home archives local because they include authentication stores; published evidence retains archive and export validation metadata. Its [archive boundary regression](../../../../benchmark/test/test_ci_evidence.py) prevents packaged private Home content from bypassing the directory exclusion.

Preparation, agent execution, artifact collection, verifier preparation and execution, export and cleanup have distinct retained stages. Agent timing uses the native task deadline after the benchmark gateway dispatches the first model request; unresolved startup has its own deadline. Docker exec with no explicit command timeout inherits the enclosing native stage deadline; preparation defaults do not impose an additional agent cutoff. Explicit command deadlines and parent cancellation still terminate the owned process tree. Stage and prewarm diagnostics retain exception types, module/function/line locations and causes without exception values or locals, so failures can be traced against frozen code without persisting credentials. Native oracle execution uses Pier's resolved native deadline. Oracle audits execute isolated native solutions and verifiers, and preserve every selected task in their reports.

CI explicitly selects the collector's `preparation` family so dependency failures before trial creation retain their build output. Selection is limited to regular recipe-digest log files directly inside the preparation directory. Unpublished build directories, arbitrary filenames and symlinked files or cache ancestors remain excluded; failed preparation does not justify publishing an entire cache.

[Result reporting](../../../../benchmark/src/synergy_bench/report.py) preserves all attempts and separates primary native reward from auxiliary verifier metrics. Missing wire evidence yields unknown byte coverage. Missing experiment conditions prevent paired comparisons. Historical oracle records can be imported through a read-only report without repeating grading or rewriting the original records.

## Alternatives considered

**Use a fixed worker count for every task.** Mixed small tasks and 8 GiB tasks can exceed Docker memory even when CPU utilization is low.

**Allow an epsilon above the resource budget.** A tolerance changes admission limits and leaves duplicated usage state in place. Deriving totals from live leases removes accumulated residue without relaxing capacity or resetting the reservations of overlapping work.

**Collect every unused Docker object.** The Docker daemon is shared with unrelated projects. Absence of a running container does not establish benchmark ownership.

**Regenerate missing evidence during resume.** A rerun changes the attempted execution, cost and sampling policy. Recovery must first reconcile retained evidence and give any further execution a separate identity.

**Treat a numeric reward or archive checksum as sufficient validation.** Rewards do not prove functional tests started. A checksum only identifies bytes; native archive contents also need structural validation.

**Infer complete OOM coverage from connection or container lifecycle events.** The public Engine API supplies no gap or drain acknowledgement. Waiting for start/destroy events, adding sleeps or merging history cannot prove that the daemon published every OOM. Observed counts remain useful without claiming an exact total.

## Consequences

Conservative memory reservations and cache protection can defer new work. Pressure and capacity failures remain explicit. Frozen experimental inputs may require an explicit larger budget or smaller preparation batch. Concurrent legacy evaluators require a retained resource reservation until they finish because they do not publish shared leases. Independent native oracle audits distinguish task/environment problems from model performance without exposing oracle state to agent runs.
