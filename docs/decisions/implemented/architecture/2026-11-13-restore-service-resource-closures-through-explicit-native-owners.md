# Decision Record: Restore Service resource closures through explicit native owners

Status: implemented

## Problem

Canonical Workspace and Environment metadata can refer to data and native lifetimes outside ordinary Service records. Namespace checksums alone cannot establish complete object history, a reconstructed target or safe old-writer retirement. Inert archive verification must not require an active Runtime.

## Decision

Capture resources through one native owner under the original frozen namespace. Reuse the Workspace catalog, content references and archive decoder to retain every saved head and complete object/file closure. Validate historical indexes through their canonical coverage and bidirectional relationships. Bind the separate authenticated resource manifest into the Service native facet and aggregate installation request.

Keep pure verification separate from effects. Pure legacy and paged graph readers use private temporary indexes and return no capability. Capture retains the original archive, native lease and primary. Target preparation retains its actual Home permit, primary and supplied object ports through the callback and final import guard. Cold retry revalidates the same installation and complete material. Snapshot trusted target infrastructure before awaiting; archived Source credentials cannot choose a target.

Source preparation retains its original native witness and cannot reserve retirement. The coordinator durably writes the Reference, exits preparation and invokes the original PendingSource owner. That restricted opener reconstructs the same maintenance, Cloud, Environment and Workspace cohort from the actual Source infrastructure without opening authentication or transports. Only the verified permanent reservation and physical completion retire the old writer.

The database owner verifies the actual source backend, matching target backend and a fresh PostgreSQL namespace. The Home owner selects an explicit Environment recovery reader from the actual archived owner. Ordinary startup still requires native completion and SQL publication; metadata cannot make an older reader compatible.

## Alternatives considered

**Accept Workspace and Environment prefixes.** Prefixes prove neither canonical relationships, referenced bytes nor terminal native ownership.

**Copy only the latest head.** Earlier receipts can retain prior saved versions.

**Use pure validation as installation evidence.** A reader owns no target primary, Home permit or object ports.

**Infer target infrastructure from the Source archive.** This can reconnect the retired deployment instead of reconstructing an independent target.

**Allow Source preparation to retire its writer.** Preparation has no durable Reference or original retirement admission.

## Consequences

Dormant object Workspaces and genuinely idle Environments restore with their original identities and saved versions, explicit target ports and current policy. Unknown owners, retained native activity, incomplete indexes and missing or corrupt bytes remain blocked. The flow creates no compute allocation, command replay or Continue authority. A lost object-write acknowledgement can retry the same installation while ordinary serving stays held.

The resource suites exercise capture, authenticated whole-object omission, independent ports, a lost write acknowledgement, held startup, original-witness cold Source reopening, durable-Reference retirement and both saved versions after source-object removal. Pure archive and native-index suites cover codec reuse and malformed ownership. The PostgreSQL suite exercises the real backend and rejects a wrong Source or Target namespace before creating it.
