# Decision Record: Keep integrated session surfaces reachable and singular

Status: implemented

## Problem

Combining task details, compact location controls and long-message editing exposed outdated fixture boundaries and retired progress components. The old progress entry no longer mounted, but its components, translations and coverage exemptions remained. On narrow layouts the current inbox anchor could intercept a question's primary action.

## Decision

Remove the disconnected progress component family, its obsolete tests and coverage exemptions. Keep startup transitions separate from ongoing task details. Preserve the shared decision focus context and exercise it through the active decision surface. Fixtures isolate the new directory-owned execution and browser providers while retaining the actual permission coordinator and UI controls.

Reserve the current compact inbox footprint in question footers so their action remains hit-testable. This is a collision correction, not the deferred inbox relocation. Conversation fixtures resolve shared modules relative to the repository instead of a machine-specific checkout. Selection and computer tests assert the current shared menu indicator, complete identity, health and keyboard focus.

## Alternatives considered

**Restore the removed progress panel for its old tests.** This would reintroduce duplicate product entry points and maintenance ownership.

**Skip failing browser tests.** This would hide a real action collision along with outdated fixtures. Active behavior stays tested; only unreachable legacy behavior is removed.

## Consequences

Coverage manifests and localization extraction reflect only current code. Task details remains the ongoing-work entry point. Narrow decision surfaces retain reachable actions until the separate inbox integration is implemented.
