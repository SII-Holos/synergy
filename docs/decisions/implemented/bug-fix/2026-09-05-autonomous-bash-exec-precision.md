# Decision Record: Autonomous bash false positives from coarse find/fd exec rules and lexical misparses

Status: implemented

## Problem

Autonomous-profile sessions hard-denied benign read-only repository-statistics commands whose gate capabilities carried `shell_destructive` (two with a `matched destructive pattern: sudo` mislabel) plus opaque `file_external_write`, or an external-write path whose text was an awk regex literal. Live reproduction against the then-current dev showed every denied command was a read-only scan (`find -exec cat/wc {} +` LOC counting, slash-relative `cd packages/synergy/src`, `$(...)` assignments, awk field separators). Four independent classifier defects produced the denials:

1. `shell-safety.ts` `ARGUMENT_INJECTION_PATTERNS` treated any `find -exec/-execdir/-ok/-delete` and any `fd -x/--exec/--exec-batch` as destructive without inspecting the executed utility, so `find . -exec cat {} +` and `-exec wc -l {} +` were flagged exactly like `-exec rm`.
2. `shellWords` had no `$()`/backtick depth, so `files=$(find "$d" -name '*.ts' ...)` was split into `["files=$(find", "\"$d\"", ...]`; `simpleCommandParts` skipped the single assignment word and read the quoted fragment as a dynamic command name (`dynamicCommandName`), which made `hasSudoInvocation` return true (the mislabel) and the directory-change analyzer return opaque external-write risk.
3. `cdpathDependentDirectoryTarget` marked every relative cd target without a `/`, `~`, or `.` prefix — including slash-containing `cd packages/synergy/src` — as opaque, although the Bash execution environment is built from `SANDBOX_ENV_ALLOWLIST` (sandbox/backend.ts:160-184) and never carries a parent CDPATH; only an in-command definition can redirect such a target.
4. `gate.ts` `extractAbsolutePaths` surfaced awk/sed regex and pattern literals (bare `/` from `-F'/'`, `/^.../` regexes, candidates containing backslash/backtick/`$`) as absolute-path candidates, so a write-capable segment classified the regex text as an external write path.

The existing regression anchors in shell-safety.test.ts encoded the coarse semantics (`find . -exec ls {} \;` destructive, `-execdir cat` destructive, `fd -x echo` destructive), so the false positive was load-bearing test behavior.

## Decision

Refine the static shell classifier so benign read-only scan commands are allowed under autonomous while every real destructive find/fd execution stays blocked. Four changes, one PR:

- **Closed-world read-only exec whitelist (F1).** `shell-safety.ts` removes the blanket find/fd entries from `ARGUMENT_INJECTION_PATTERNS` and adds `hasUnsafeExecTarget`, which scans quote-masked executable text (`executableShellSyntaxText`) for `find`/`fd` executions. `-ok` and `-delete` stay unconditionally destructive; `-exec`/`-execdir`/`-x`/`-X`/`--exec`/`--exec-batch` inspect the executed utility against `READ_ONLY_EXEC_TOOLS` (cat, wc, grep family, head, tail, sort, uniq, cut, tr, od/hexdump/xxd, diff/cmp/comm, basename/dirname/readlink/stat/du/ls/file, echo/printf, nl/paste/join/expand/unexpand/fmt/fold/pr/column/seq, checksum tools, zcat/bzcat/xzcat, pwd/true/false). awk/gawk/sed are excluded (awk can `system()`, sed `-i` writes), as are xargs/tee (execute or write derived content), interpreters, shells, network tools, mutators, and unknown utilities — those fail closed as destructive. The scanner recurses into `$()`/backtick/process substitutions and fails closed on budget or depth exhaustion.
- **Substitution-aware word tokenization (F2).** `shellWords` tracks `$()` and backtick nesting (plus escaped grouping parentheses), so an assignment prefix stays one word and the quoted variable fragment is never read as a dynamic command name. This removes the sudo mislabel and the phantom opaque directory risk from assignment + substitution commands.
- **Slash-relative cd resolution with CDPATH text guard (F3).** `analyzeDirectoryChanges(command, options?)` gains `resolveSlashRelativeCd`. When set, a relative cd target containing a slash resolves statically against the cwd unless the command text itself defines CDPATH (`CDPATH=` or `export CDPATH`); bare-name targets (`cd node_modules`) and CDPATH-defining commands stay opaque. The enforcement gate passes `{ resolveSlashRelativeCd: true }`; the default (no options) preserves the previous conservative behavior for all other callers.
- **Regex/pattern literal rejection in path extraction (F4).** `gate.ts` `extractAbsolutePaths` drops candidates that are a lone `/`, open with `/^` (awk/sed regex), or contain backslash, backtick, or `$` (escaped/dynamic/regex metacharacters that are never statically resolvable paths). Real absolute paths, protected paths, and `/dev/` device paths are unaffected (device writes are handled by destructive/hardline layers).

Regression coverage: `packages/synergy/test/enforcement/autonomous-exec-precision.test.ts` anchors the four original commands verbatim (autonomous gate evaluation must allow with no destructive/external-write/sudo tag), a destructive find/fd negative matrix (rm, sh -c, curl, -delete, -ok, unknown utility, mixed `-exec rm ... -o -exec cat`), preservation of the remaining injection patterns (rg --pre, go test -exec, git show --output, git config --global, shell wrappers around destructive git, interpreter subprocesses), assignment+substitution fragment assertions, slash-relative cd resolution and CDPATH guards, and awk-regex external-path absence. Existing shell-safety.test.ts anchors were updated to the refined semantics (read-only exec utilities pass; mutators/unknowns stay destructive).

## Alternatives considered

**Whitelist write-capable utilities after find/fd -exec (scan-root containment).** Allowing `-exec mkdir/touch/cp` inside the scanned tree would require the classifier to bound the write to the scan root, expanding autonomous write capability beyond the reported need; the corpus only requires cat/wc. Rejected.

**Relax `shell_destructive`/`file_external_write` from `AUTONOMOUS_DENIED` or lower their capability risk.** The prior copy-operand decision record already rejects profile carve-outs for non-bypassable capabilities; relaxing the deny list breaks the SmartAllow hard-boundary invariant and treats a classifier bug at the policy layer. Rejected.

**Delegate the misclassification to SmartAllow.** `shell_destructive` and `file_external_write` are non-bypassable and never SmartAllow-eligible by design; routing classifier defects through an LLM gate would make a hard boundary model-dependent. Rejected.

**Scope the slash-relative cd resolution to autonomous only.** The static classifier is profile-independent, and guarded sessions execute bash under the same CDPATH-free allowlist environment; a profile-coupled static branch would complicate the boundary for no behavioral gain (guarded still asks for `shell` risk). Implemented profile-independently with the in-command CDPATH text guard. Rejected the profile-coupled variant.

**Rewrite shellWords by reusing walkShellChars wholesale.** `shellWords` has many consumers (git/gh taxonomy, heredoc headers, isBarePush, env -S splitting, exec-target scanning); a full parser swap is a larger regression surface than the reported defect needs. The minimal nesting-depth addition preserves every existing consumption. Rejected.

**Add awk/sed to the find-exec whitelist.** awk can execute `system()`, and sed `-i` writes in place; admitting them would require program-text analysis the corpus does not need. Rejected, with the exclusion documented on the whitelist.

## Consequences

Autonomous-profile sessions can run benign read-only scan commands over repository trees (`find -exec cat/wc`, slash-relative `cd` chains, `$(...)` assignments, awk field/regex literals) without false denials, while every genuinely destructive find/fd form (`-exec rm`, `sh -c`, curl, `-delete`, `-ok`, unknown utilities, fd mutators) remains a hard `shell_destructive` denial. The classifier is more precise: exec-target inspection replaces the "any find -exec is destructive" blanket, and word tokenization no longer mistakes substitution contents for command names, which also removes the `matched destructive pattern: sudo` mislabel and phantom opaque directory risk. Slash-relative cd resolution matches execution reality (the allowlist environment has no parent CDPATH) without weakening the bare-name/CDPATH-defined conservative cases, and regex/pattern literals no longer surface as external paths. Costs: one new exported options type on `analyzeDirectoryChanges` (default preserves old behavior), a closed whitelist that must be extended deliberately for future read-only exec tools, and updated shell-safety anchors that now distinguish read-only from mutating exec utilities. The change is confined to the static classifier and its tests; capability registry semantics, `AUTONOMOUS_DENIED`, SmartAllow eligibility, profile rules, and the OS-sandbox layer are untouched. This PR complements #1308 (null-device sink pseudo-path + write-redirect classification + autonomous sandbox containment), which fixes a disjoint set of false positives in the same enforcement surface; the two merge independently.
