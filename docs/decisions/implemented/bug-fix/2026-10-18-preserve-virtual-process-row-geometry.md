# Decision Record: Preserve virtual process geometry during disclosure and hydration

Status: implemented

## Problem

Expanding a long process can briefly overlap paragraphs and request bodies outside the intended reading window. Independent zero-height entrances turn the virtualizer's measured rows into a dense list before those same rows expand to their natural heights. Short tool-only fixtures do not expose the resulting demand growth. Independently, asynchronously hydrated bodies can paint at their natural height while neighbouring offsets still use a pending reservation until the next ResizeObserver publication.

## Decision

Manual parent-process and virtual activity disclosure keep mounted rows at their natural height and use the existing bounded fade. The virtualizer measures the same geometry that the reader sees. This replaces the virtual-row height interpolation in [process disclosure preparation](2026-10-08-process-disclosure-preparation-and-motion.md); pending reservations, conditional mount ownership and reading anchors remain. An activity wrapper whose neighbours are absolutely positioned cannot interpolate height independently of their published offsets.

The active outer conversation opts its non-exiting body and activity rows into descendant content observation through Solid Virtualizer’s `observeContent` predicate. Content and descendant inline-style mutations coalesce into one content-box measurement batch. Assistant body and nested process rows use that batch at the end of the current task while reading; all body rows use it in paged history; activity wrappers use it for disclosure changes. After mount effects settle, a body arriving during frame callbacks cannot paint over neighbours whose offsets still reflect its pending reservation. Latest-following body catch-up and latest-window user-message preparation retain their existing frame scheduling. Reading a process while returning from the background must not publish the user-message disclosure’s intermediate preparation heights. All reads precede publication, so independent Markdown completions do not each move the viewport. Resolved CSS dimensions can round a precise observer size; content measurements ignore differences within 0.01 px to avoid republishing rounding noise through reading-anchor restoration. Accepted measurements discard older queued observer entries for those targets. Wrapper position writes do not trigger another content measurement. New and changed body rows also publish measurements inside the existing history-shift transaction. Other initial rows, automatic exits, latest-following inner rows and ordinary CSS resize delivery retain their existing scheduling outside ResizeObserver delivery. Content measurement does not wait for animation readiness: an admitted viewport may be interactive while another body is still loading. Inactive views do not publish content measurements. Observers and pending targets release on virtual eviction and disposal. Both shipped Solid entrypoints carry the correction.

Body admission, cancellation, version validation and cache budgets retain their existing owners. Long prose tests cover cold reads, accepted-body reuse, narrow columns, reduced motion and CPU throttling. They sample overlap and mounted-row counts during the transition, independently of final layout. Cold-body admission covers both immediate and delayed responses in each Solid entrypoint. An isolated ResizeObserver probe samples layout during each rendering update, without modifying conversation geometry. It excludes between-frame DOM states that have not painted while retaining the overlap threshold; disabling content-size publication must still fail this check. See the [diagnosis](../../../postmortem/0080-virtual-process-disclosure-demand.md).

Loading earlier messages anchors an already visible process row when one exists. A page can extend the same root between its retained user message and its accepted process, so anchoring only the user message does not preserve the reader's content. A continuous activity uses keyed prepend compensation inside its own virtual viewport. Inner reading restoration runs when content changes or its measured layout settles, before paint, then retains its bounded frame retry for pending virtual measurements. This also preserves a Part inside a multi-Part row when preceding tool evidence grows; row-level compensation alone cannot preserve that position. After native movement, the process captures its new reading anchor immediately if the reading edge is mounted. Otherwise it waits for virtual rows to update instead of preserving an old overscan row below that edge. The outer reading owner observes inline placement changes on only its current anchor and ancestors, because a virtual offset can change without resizing that row or the total content extent. Corrections respect pending native movement and release with the reading owner. Expansion preferences, accepted bodies and the existing page request remain unchanged. Regression coverage loads history with process, tool groups and reasoning manually expanded, then explicitly expands newly admitted reasoning and verifies retained content.

## Alternatives considered

**Continue animating each virtual row's height.** The intermediate zero heights are real inputs to virtualization. Batched measurements alone do not prevent the demand window expanding to the whole process.

**Preload every process body.** Warm local prose reproduces the overlap without network requests. Preloading does not repair geometry and increases transfer and memory cost.

**Publish every resize directly inside ResizeObserver.** That reintroduces nested observer-delivery loops. Content mutation measurement runs before delivery and leaves CSS resize scheduling intact.

**Change every shared disclosure animation.** The defect involves independently positioned virtual neighbours. Naturally flowing disclosures and shared dialogs keep their existing motion.

**Poll geometry from a timer after each animation frame.** Network and Markdown tasks can update the DOM between that paint and the timer. Such a sample can report transient overlap absent from compositor frames; sampling within the rendering update tests the intended visual invariant.

## Consequences

The parent process stops compressing all paragraphs into a shared area during expansion. It gives up individual row-height interpolation while retaining brief visual feedback, keyboard access and rapid reversal. Demand remains proportional to the visible window; genuinely new uncached history still requires body reads. Transport and stored data are unchanged. Content changes require a bounded synchronous layout read for affected mounted rows; unchanged rows are not polled. Existing history, following, selection, layout-cache and hidden-view regressions remain acceptance requirements.
