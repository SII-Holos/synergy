# Decision Record: Continue original roots after native recovery

Status: implemented

## Problem

An independently restored Hosted Home preserves its original failed or paused Root but has a fresh deployment incarnation. Historical input authority cannot authorize another execution. Reusing startup restoration inspection during a live Continue also changes admission state while the original Session is writing. Restored worker processes must recognize the same completed native Home as their foreground process.

## Decision

Represent continuation provenance as exactly one original Handoff or completed recovery publication. Recovery provenance binds the original installation and Source reference hash. Service admission verifies the actual published Hosted mapping, current machine connection, accepted Continue, actor, API access, binding and current resource selection before creating a fresh execution grant. Preserve the original input, actor, Root and predecessor history. Original completed commands and credentials do not authorize execution in the fresh deployment.

Use a pure completed-restoration inspection during live execution. Retain the real process lock, primary Store, artifact owner, both storage-context pointers and canonical physical installation identities through inspection. Do not invoke the startup procedure that changes blocked admission state. Native publication supplies recovery provenance only after its actual completion, committed publication and released maintenance hold agree.

Reader six and the owning central migrations retain exact legacy grant and cleanup formats. Existing deterministic cleanup identities survive migration. Public Runtime Home advancement uses the original exclusive process lock, existing dataset, native maintenance witness and frozen owning migration. Both CLI entry points share this implementation; the same request reconciles interrupted work. Identity, enrollment, credentials, installation and publication bytes retain their original owners. Upgrading reports a required restart and starts no Agents.

For a paused accepted input that has no Message or Run, capture its actual private Inbox and original cleanup graph under the frozen Native owner. Only the exact deterministic original and an acyclic link to its unique provisional generation-zero observation qualify; an execution generation, unresolved dispatch or another authority remains blocking. Native manifest version two signs a body-free complete queue roster. Service history joins that roster to original reception, resource selection and both retained counts and indexes. The target verifies the original signature and restored private data before publication. A current explicit Continue atomically replaces original provisional retention with its real successor. Native Intake closes the old pending release only after observing that successor, without inventing an old terminal receipt.

Repeated observation of the same command result and state preserves the original attempt timestamp. All existing connection, original receipt, logical-request and sequence-closure checks still run. Snapshot comparison continues to require exact original facts.

Worker entry points read the actual Node-compatible Home and completed restoration before synchronously registering their selected components. Await this worker preflight before sealing composition. Keep generic component registration synchronous. Compare physical Home paths through their original real paths so a parent-directory alias does not misclassify a restored Home.

Historical activated Knowledge can retain its original binding after a completed Handoff. Locate that metadata epoch through the unique completed Handoff chain anchored to the current Directory, verifying original indexes, signatures, Native facts and command barriers at each step. Preserve the original activated header, summary and references; this metadata inspection grants no execution authority. A never-shared private Session can also retain the Service’s blocked control marker. Accept only generation zero with its original sequence, complete absence of every Session generation’s shared data and the actual completed incoming Handoff with no pending batch. Native private drafts and content keep their independent owners and are not inferred empty from that Service marker. Portable transfer headers use their owning current version when produced and retain explicit legacy readers.

## Alternatives considered

**Reuse an old grant or substitute a new input.** Either loses current authorization or changes the user’s original Root and actor.

**Clear restoration blocking after every live read.** Even a temporary blocked interval can reject concurrent ordinary Session writes.

**Assume every worker Home uses the initial format.** The foreground process can become ready while its actual Agent and Policy workers reject the restored installation.

**Rewrite archived native files to make an upgrade appear complete.** Original maintenance and migration receipts must establish advancement; mismatched files and completed receipts remain invalid.

## Consequences

Restoration and ordinary reconnect remain inert. A current explicit Continue can resume the original Root once; duplicate command reception retains its original acknowledgement. Tests exercise an actual failed Source, independent Service and Hosted restoration, zero replay, one appended execution segment, actual worker readiness and rejected damaged native identities. The queued case verifies the complete original restore and current continuation without substituting another input; malformed evidence and current authority refusals retain separate behavioral acceptance.
