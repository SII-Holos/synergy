# Decision Record: Continue original roots after native recovery

Status: implemented

## Problem

An independently restored Hosted Home preserves its original failed or paused Root but has a fresh deployment incarnation. Historical input authority cannot authorize another execution. Reusing startup restoration inspection during a live Continue also changes admission state while the original Session is writing. Restored worker processes must recognize the same completed native Home as their foreground process.

## Decision

Represent continuation provenance as exactly one original Handoff or completed recovery publication. Recovery provenance binds the original installation and Source reference hash. Service admission verifies the actual published Hosted mapping, current machine connection, accepted Continue, actor, API access, binding and current resource selection before creating a fresh execution grant. Preserve the original input, actor, Root and predecessor history. Original completed commands and credentials do not authorize execution in the fresh deployment.

The canonical `continuationOrigin` helper validates the exclusive Handoff-or-recovery origin before emitting only its present branch. A missing optional property must remain absent in Native persisted bindings; an own property containing `undefined` is not JSON data. Canonical signed and cleanup-identity JSON bytes remain unchanged, because their original serialization already omits that property. Retain the existing strict DTOs and record validation rather than coercing complete authority objects.

For a Root originally driven by another Runtime, resolve its historical Handoff path under the actual current Service write transaction. Retain the same Runtime, primary Store, transaction, dataset configuration and artifact owners around every read. The existing historical validator proves the original binding, completed Native facts, exact indexes, signatures and command barriers through the current Directory. Select the current Root pointer first; if it is absent, resolve the latest matching pointer along that verified predecessor path. The original released intake, current recovery publication and current explicit Continue still have separate owners. The resulting grant and later historical validation preserve the same original Root and predecessor rather than substituting a new input or treating a historical binding as current authorization.

Use a pure completed-restoration inspection during live execution. Retain the real process lock, primary Store, artifact owner, both storage-context pointers and canonical physical installation identities through inspection. Do not invoke the startup procedure that changes blocked admission state. Native publication supplies recovery provenance only after its actual completion, committed publication and released maintenance hold agree.

Reader six and the owning central migrations retain exact legacy grant and cleanup formats. Existing deterministic cleanup identities survive migration. Public Runtime Home advancement uses the original exclusive process lock, existing dataset, native maintenance witness and frozen owning migration. Both CLI entry points share this implementation; the same request reconciles interrupted work. Identity, enrollment, credentials, installation and publication bytes retain their original owners. Upgrading reports a required restart and starts no Agents. A restored Hosted Home has its own local installation incarnation, distinct from the Service deployment in its enrolled namespace. Home upgrade validates both original owners separately and preserves the complete Hosted namespace and unchanged local source/target identity. Service Home advancement still requires its installation incarnation to equal its own deployment. Source preparation retains its existing deployment check.

For a paused accepted input that has no Message or Run, capture its actual private Inbox and original cleanup graph under the frozen Native owner. Only the exact deterministic original and an acyclic link to its unique provisional generation-zero observation qualify; an execution generation, unresolved dispatch or another authority remains blocking. Native manifest version two signs a body-free complete queue roster. Service history joins that roster to original reception, resource selection and both retained counts and indexes. The target verifies the original signature and restored private data before publication. A current explicit Continue atomically replaces original provisional retention with its real successor. Native Intake closes the old pending release only after observing that successor, without inventing an old terminal receipt.

After a completed Native Handoff, a recovered Intake can belong to the current Runtime while its original input and immutable release belong to the former driver. When no local cleanup entries exist for that exact original authority, require the full original terminal release and receipt together with the actual Native epoch owner at the grant's target Runtime and epoch, with role target and phase activated. A returned Binding alone also describes a cancelled Source and cannot establish Target activation. Existing local pending entries remain blocking; this classification creates no old settlement, removes no unknown entry and grants no authority. Same-binding queued reconciliation retains its original cleanup graph and commit path.

Repeated observation of the same command result and state preserves the original attempt timestamp. All existing connection, original receipt, logical-request and sequence-closure checks still run. Snapshot comparison continues to require exact original facts.

Worker entry points read the actual Node-compatible Home and completed restoration before synchronously registering their selected components. Await this worker preflight before sealing composition. Keep generic component registration synchronous. Compare physical Home paths through their original real paths so a parent-directory alias does not misclassify a restored Home.

Historical activated Knowledge can retain its original binding after a completed Handoff. Locate that metadata epoch through the unique completed Handoff chain anchored to the current Directory, verifying original indexes, signatures, Native facts and command barriers at each step. Preserve the original activated header, summary and references; this metadata inspection grants no execution authority. Failed desired Knowledge updates retain their original complete active selection and native files; Service metadata follows the [original selection-history owner](../feature/2026-11-13-recover-exact-sealed-organization-knowledge.md). Nonempty Native recovery carries the actual Knowledge facet through the same frozen archive and Home restoration permit. Its relocation runs under that permit's original restoration transaction and final guard, preserving the original bytes while changing only the exact native cache address. Ordinary reopened Skill reads must succeed from the Target after the permanently retired Source cache is removed, without retrying the failed activation or replaying a model. This does not change the default empty selection or give a separate Service history proof authority over private native files. A never-shared private Session can also retain the Service’s blocked control marker. Accept only generation zero with its original sequence, complete absence of every Session generation’s shared data and the actual completed incoming Handoff with no pending batch. Native private drafts and content keep their independent owners and are not inferred empty from that Service marker. Portable transfer headers use their owning current version when produced and retain explicit legacy readers.

## Alternatives considered

**Reuse an old grant or substitute a new input.** Either loses current authorization or changes the user’s original Root and actor.

**Clear restoration blocking after every live read.** Even a temporary blocked interval can reject concurrent ordinary Session writes.

**Assume every worker Home uses the initial format.** The foreground process can become ready while its actual Agent and Policy workers reject the restored installation.

**Rewrite archived native files to make an upgrade appear complete.** Original maintenance and migration receipts must establish advancement; mismatched files and completed receipts remain invalid.

**Coerce complete authority objects through JSON before storage.** That hides the incorrect canonical projection and can erase other invalid values. Correct the owning origin helper while retaining strict Native record validation.

## Consequences

Restoration and ordinary reconnect remain inert. A current explicit Continue can resume the original Root once; duplicate command reception retains its original acknowledgement. Tests exercise an actual failed Source, independent Service and Hosted restoration, zero replay, one appended execution segment, actual worker readiness and rejected damaged native identities. The queued case verifies the complete original restore and current continuation without substituting another input; malformed evidence and current authority refusals retain separate behavioral acceptance.
