# Decision Record: Benchmark resource queues preserve useful progress

Status: implemented

## Problem

大任务等待资源时，固定预热批次把后续可运行的小任务挡在资源队列之外。续跑还会为已有终态的任务申请资源后才跳过。两者让进程存活与实际进展脱节。将容器内存上限始终作为完整预留，也会使低实际占用的推理任务长时间独占调度容量。

## Decision

[预热](../../../../benchmark/src/synergy_bench/maintenance.py) 将全部候选提交给有并发上限的资源池，并在任务完成后检查缓存预算；预算失败取消剩余准备并保留记录。[续跑](../../../../benchmark/src/synergy_bench/runner.py) 在资源申请之前识别终态和受限的零模型启动重试。冻结评测器及历史证据的规则保持有效。

[资源配置](../../../../benchmark/src/synergy_bench/config.py) 允许显式声明 `memory_reservation_fraction`，默认完整预留。小于 1 时只缩小调度预留，保留原题容器上限和 CPU 预留；共享租约记录缩放后的预留和原始资源请求（含运行开销）。宿主压力检查之外，全部 Docker 容器使用量达到调度容量的 80% 或采样失败时停止新增准入。Docker 采样最多缓存 5 秒，避免每个等待者重复执行昂贵查询。

预留策略属于实验条件，新条件必须创建新实验。它不改变候选答案、模型、工具、原生判题器或已保留结果。行为测试覆盖跨进程资源占用时的预热回填、终态跳过和显式内存超额订阅。

## Alternatives considered

**只提高并发数。** 内存仍然按完整上限预留时，大任务的准入数量不会改变；固定批次也仍会阻塞小任务。

**直接降低容器内存上限。** 这会改变原题运行环境，并让合法的编译或判题峰值更容易失败。

**始终保持完整预留。** 这是保留的默认策略，但不能满足根据实测占用研究更高吞吐的场景，因此允许独立声明而非静默放宽。

**给正在执行的冻结评测器替换调度代码。** 这会破坏实验身份和复现能力。新代码只用于新冻结的运行，历史消耗和不同条件均保留。

## Consequences

排队任务能够利用空闲容量，完成结果不再等待执行配额。显式超额订阅提高低占用工作负载的并行度，但采样是瞬时观测，不能防止已有任务同时增长造成 OOM。默认策略保持完整预留，跨进程准入仍按容量竞争，不提供全局先来先服务保证。修改过并发和预留条件的运行不能与旧运行直接比较耗时。
