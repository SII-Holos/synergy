# Decision Record: 网络错误共享分类与按执行阶段限制重试

Status: implemented

## Problem

同一个瞬时网络故障可以表现为原始 TypeError、SDK APICallError、多层 cause 或 worker 还原错误。按供应商或单一字符串修补会持续遗漏合法恢复路径，而宽泛匹配又会把证书、鉴权、程序错误和已经执行过的工具操作纳入重放。需要共享错误依据，同时保留各调用方对次数、截止时间及外部副作用的控制。

## Decision

[共享网络分类器](../../../../packages/util/src/network-error.ts) 识别已知 DNS、连接与传输错误，遍历有界 cause/errors 图，优先保留取消及明确的终止原因。域名不参与判定。worker 协议版本 9 保留嵌套错误与聚合成员，限制深度、节点与文本，使用显式截断错误避免静默丢弃拒绝重试的依据。

[供应商判定](../../../../packages/harness/src/provider/retry.ts) 在网络依据之外处理 HTTP 状态与明确的流错误类型，保留鉴权、输入、余额耗尽、未知异常及记录失败的终止语义。LLM 在 SDK 重试入口前规范化流启动错误，普通会话由处理器控制额外十次重试，AgentCall 禁用 SDK 重试并统一管理调用方指定的启动/正文额外次数与原始总截止时间；SDK 重试耗尽不会获得新的外层次数。

[共享退避](../../../../packages/util/src/retry.ts) 接收调用方取消信号，严格解析大小写不敏感的 Retry-After 与毫秒扩展。会话默认退避上限不受无关响应头影响，默认等待带随机抖动；有效服务端等待提示优先，并受计时器可表示上限约束。网页 GET 在同一个总截止时间内最多请求三次，完整读取成功才交付结果，权限和搜索去重按一次工具调用处理。

会话模型流正常完成后，处理器停止赋予自动模型重试资格。工具执行、后续调度及落盘错误不能通过重新调用模型恢复。模型流失败时已收到的工具提议不执行，成功恢复的尝试才可调度工具。开始下一次尝试前，通过既有 part-removal 写入与事件撤下失败尝试的文本、推理和未执行工具，保留原有内容、补丁和计费信息；全部调用与原始流继续保存在 rollout。取消而未开始恢复时保留最后的部分输出。流错误被消费后保持 failed 状态，即使消费者随即退出。

[共享恢复协调](../../../../packages/harness/src/provider/retry-coordinator.ts) 位于控制进程的 AgentTurn 入口，按配置端点及显式凭据等连接信息的单向散列分组。瞬时失败触发冷却与单个恢复探测；等待不占 worker，可取消且有五分钟准入上限。较旧请求或探测的成功不得清除较新失败。缓存最多 1,024 个分组，容量溢出时新分组沿用单调用重试。该机制不跨运行实例，也不增加请求次数。

具体审查证据、上游资料与范围边界见 [网络重试审查](../../../research/2026-09-15-network-retry-audit.md)。分类器、SDK 适配和共享退避旁保留采用标准与上游行为的来源。

## Alternatives considered

**只补 ETIMEOUT 或匹配 DeepSeek 域名。** 不能覆盖其他供应商、其他网站、多层包装和跨进程信息丢失，也无法解决误重试。

**全局包装 fetch，遇错一律重试。** 请求方法不足以确定业务幂等性，统一重放会影响令牌交换、插件、MCP 与写入操作，且容易与 SDK/会话预算相乘。

**每个业务维护自己的网络错误表。** 次数与恢复动作确实属于业务，但同一网络错误的事实依据无需重复维护；重复列表已经产生可观察差异。

**完全依赖 SDK 默认行为。** 固定版本 SDK 对原始错误的覆盖有限，而且不负责 Synergy 的 worker 协议、正文总截止时间、持久化以及工具调度阶段。

## Consequences

短暂 DNS、连接和服务故障能跨供应商恢复，明确的终止错误与用户取消更快反馈。失败尝试仍可能消耗模型费用，恢复不保证上游 exactly-once；网页 GET 重试也仍受原调用的权限与时长限制。

策略保持保守：证书失败、无效域名、错误图截断和未知异常停止自动重试。有效 Retry-After 可长于默认退避上限；上层总预算或取消必须终止不再需要的等待。失败内容通过既有消息事件撤下，权威调用记录和计费保持完整，因此不需要新增消息字段或迁移历史。共享冷却只约束本实例的恢复流量；MCP 工具、令牌交换及其他写入继续遵守各自的重放策略。
