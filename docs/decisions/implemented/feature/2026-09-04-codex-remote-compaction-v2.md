# Decision Record: Codex remote compaction v2 replay for openai-codex sessions

Status: implemented

## Problem

Long `openai-codex` sessions hit context overflow the same way any session does, but the local fix is lossy in a way that is unique to codex: SessionCompaction rewrites the conversation into a portable Markdown continuation summary and replays from the local history on the next turn. The codex backend, however, is the real owner of the conversation state — it stores token-for-token encrypted context that cannot be reconstructed locally (reasoning summaries, function state, cache entries). After a local-only compaction, the next codex turn re-sends the full rewritten history, paying re-ingestion cost and losing the backend-side compacted state the Codex CLI gets for free through its private `remote_compaction_v2` protocol. On sessions near the per-request input cap, the local rewrite can even fail to fit where a server-side compacted artifact would have succeeded.

## Decision

Add a config-gated (`compaction.codexRemote`, default `false`) best-effort remote-compaction track that mirrors the Codex CLI's server-side compaction protocol v2:

- **Request** (`CodexProvider.requestRemoteCompactionV2`): a normal streaming `/responses` call whose `input` ends with a `compaction_trigger` item and whose headers carry `x-codex-beta-features: remote_compaction_v2` plus the usual codex identity headers. Requested with `store: false` and the session as `prompt_cache_key`, from the conversation model (the root user message's model), in parallel with the local LLM summarization so a slow or failing remote call never delays the authoritative local summary. Bounded by a 90s timeout and the compaction abort signal; failures log and return `undefined`.
- **Persistence**: on the summary assistant message metadata (`metadata.remoteCompaction`, v2 record), store the opaque `compaction` item returned by the endpoint, a `replacementHistory` of the most recent real user messages (bounded to ~20k tokens; images retained as-is, text truncated per item) followed by the compaction item, usage, and the exact committed local summary text.
- **Replay** (`SessionCompaction.codexReplayPlan` → per-turn `codexReplay` on the turn input → worker registry): on later turns, the newest fulfilled compaction summary on the session yields a replay plan only when the current turn runs on the exact same codex provider/model that produced the artifact. The plan is registered in the worker-local registry (`setReplayPlan`) keyed by session, and the codex fetch layer (`rewriteCodexBody`) splices the persisted replacement history into the serialized request body in place of the compacted region.
- **Splice safety** (`applyReplaySplice`): conservative by design. The body must be a normal turn (never a compaction request), have a leading developer/system run, contain the stored summary text (exact first, whitespace-tolerant fallback) as the joined output of one consecutive run of assistant items, and have only user messages between the prefix and that run. The replacement must end in an opaque `compaction` item. Any mismatch returns the body unchanged — the turn proceeds with normal local-history replay.
- **Local summary stays authoritative and portable**: the Markdown summary is committed on its own path (LLM result or mechanical fallback); the remote artifact is merged into metadata only after both tracks committed. Non-codex providers, disabled config, model switches, aborts, and failures all leave the session on the standard local boundary. The registry entry is overwritten or cleared on every codex turn, so a stale plan can never outlive the compaction that produced it.

## Alternatives considered

- **Replace the local Markdown summary with the opaque compaction item as the session boundary for codex** — rejected: it would make codex sessions unreadable and unreplayable by any other provider, tool, or model, break the durable portable summary contract, and couple session correctness to a private protocol.
- **Reconstruct the replacement history from `MessageV2` objects on each replay instead of persisting item snapshots** — rejected: the wire shape is SDK-serialization-owned; reconstructing it later invites silent drift. Persisting the exact items the compaction request sent keeps the replay splice faithful.
- **Run the remote compaction inline (awaited) before the local summary** — rejected: it would add a second network round-trip to the compaction critical path and make the portable summary dependent on the private endpoint.
- **Always-on (no config gate) for codex sessions** — rejected: the endpoint is a private protocol that may change or fail, costs an extra request per compaction, and the feature is new; default-off keeps blast radius zero until validated.
- **Match the summary region by message count/offset rather than stored text** — rejected: compaction boundaries and pruning shift indices; matching on the exact committed summary text (whitespace-tolerant) is the only stable anchor, and it falls back cleanly when absent.

## Consequences

Long codex sessions can now cross compaction with backend-side state and cache value retained, while every other path keeps the exact behavior it had: the feature is off by default, gated to the codex provider, strictly best-effort (never blocks, never throws outside its try/catch), and the local Markdown summary remains the durable, portable boundary for all providers. The costs are deliberate: one extra streaming request per compaction when enabled, persisted metadata growth from the retained message snapshot (bounded, replaced at the next compaction), and a splice that depends on SDK serialization shape — guarded by structural checks and a no-op fallback so drift degrades to today's behavior rather than to errors. The replay registry is worker-local and session-sticky for the duration of a turn, so multi-turn, multi-session workers cannot cross-contaminate plans.
