# Decision Record: Safe managed worktree archive

Status: implemented

## Problem

Finishing isolated work needs an explicit reclamation request that an Agent can issue from its own running turn or for another idle checkout. Leaving a worktree, archiving a conversation, unloading idle execution and deleting checkout files are different operations. Treating them as one operation can stop the caller before it reports completion or destroy files whose recoverability has not been established. Registry bindings and navigation indexes also omit valid historical, child and archived Session references, so they cannot alone authorize physical retirement.

## Decision

Workbench exposes `worktree_archive` as an optional-target tool with operation-specific permission admission before mutation. Local Runtime owns the implementation through its existing Worktree lifecycle and native retirement coordinator; Harness owns canonical Session references and the Workspace catalog retirement state. The [product reference](../../../product/workspaces-and-sessions.md#finishing-isolated-work) defines caller-visible outcomes; [safe worktree archive](../../../architecture/workspace-and-files.md#safe-worktree-archive) owns the detailed invariants.

The operation separates caller departure, reclamation candidacy and confirmed deletion. An omitted target selects the current worktree or returns `noop` when none is selected. An approved caller leaves its target for its original checkout without setting conversation archive state or stopping its loop. The registry becomes `gc_candidate`; safe reclamation is attempted immediately and maintenance retries blocked candidates even below the cap. Archive and its deferred retries retain the branch, use no force option and make no automatic snapshot-restore promise. Safety requires positive evidence for clean files, absent ignored files, remote commit reachability, absent locks and idle resources; unknown evidence is not permission to delete.

Reclamation enumerates canonical Sessions rather than trusting a registry or navigation projection, and checks host-qualified Workspace authority across the entire Storage namespace. Another Scope or a registered child-directory Workspace conservatively prevents deletion rather than being implicitly migrated. Exact target records enter a revision-checked transactional `active` → `deleting` fence before removal; the same transaction excludes other descendant or physical-alias authority, and every native authority publication entry rejects overlapping deleting directories. Existing active ancestors remain valid destinations for idle reference migration. The fence rejects new create, fork, bind and run admission while preserving ordinary metadata and history reads. Explicit archive migrates idle references before removal. Native exclusion then protects a fresh check of the same physical identity, catalog revisions and eligibility immediately before Git removal. Confirmed deletion permits `deleted`; an unconfirmed outcome keeps the fence unless the same retained directory can be safely verified and returned to `active`. Committed caller departure and completed reference migrations are not rolled back after a later failure.

Canonical path census discovers references, not migration authority. Caller departure and idle migration require a verified bound target record, with Session selection and catalog revisions re-read under the Session binding lock. Imported unbound and foreign-host history remain unavailable even when their stored path matches the local checkout. Automatic cap cleanup keeps its existing post-delete reference migration and recency preservation, as documented in [Worktree ownership](../../../architecture/workspace-and-files.md#worktree-ownership) and the [recency decision](../bug-fix/2026-09-21-preserve-recency-during-worktree-cleanup.md). The fence and canonical enumeration strengthen that path without adopting explicit archive's pre-delete migration order. The existing [cap janitor](../bug-fix/2026-09-20-managed-worktree-cap-janitor.md) and [retirement admission order](../bug-fix/2026-09-23-workspace-retirement-admission-order.md) remain applicable.

### External provenance and local adaptation

The [Codex worktree cleanup documentation](https://learn.chatgpt.com/docs/environments/git-worktrees#worktree-cleanup) describes a default cap retaining the most recent 15 managed worktrees, cleanup on associated-chat archival or capacity pressure, protection for pinned or in-progress chats and permanent worktrees, and a snapshot before deletion with a restore offer. It does not establish complete coverage of every file. These are Codex product behaviors, not Synergy defaults or restoration guarantees.

The [Codex App Server archive documentation](https://learn.chatgpt.com/docs/app-server#archive-a-thread) distinguishes `thread/archive`, which moves persisted conversation logs to archived storage, from deletion and from idle unloading: a thread with no subscribers and no activity unloads after 30 minutes. At pinned commit `0e1520605f67969b58e53762be4d675c036a981d`, the [TUI dynamic tool implementation](https://github.com/openai/codex/blob/0e1520605f67969b58e53762be4d675c036a981d/codex-rs/tui/src/dynamic_tools.rs#L753-L760) exposes `set_thread_archived` but rejects archiving the calling task. Neither its description nor the desktop cleanup documentation establishes a safe running-Agent self-archive guarantee.

Synergy adopts an explicit candidate lifecycle and guarded reclamation, not Codex conversation archival or unverified self-stop behavior. Its safety policy retains unique or unverifiable files instead of treating a pre-delete snapshot as proof of complete recovery. Worktree archive is independent of conversation archive and idle execution unloading.

## Alternatives considered

**Archive the conversation and stop its loop as part of worktree cleanup.** This conflates durable history with physical checkout ownership and prevents a running caller from reliably returning its result. The researched Codex interfaces do not supply a self-archive guarantee to adopt.

**Force-delete after a snapshot and promise restoration.** Synergy's snapshot policy has capture limits and omissions; a snapshot cannot prove preservation of ignored files or all local-only work. Retaining the checkout is safer than inventing a complete restore guarantee.

**Only leave, or wait for capacity pressure.** Leaving does not express reclamation intent, and a candidate below the cap could remain indefinitely. Immediate safe reclamation plus below-cap candidate retries gives explicit archive a distinct effect without weakening the safety checks.

**Trust registry bindings, Scope-local scans or an in-process removal gate.** Historical and child references may be absent from the registry, another Scope can hold independent authority for the same directory, and a registration can publish after a preflight scan. Canonical enumeration plus namespace-wide transactional subtree admission and native exclusion protects durable references and the actual directory. Automatically fencing or migrating foreign and child-directory records would grant retirement authority the caller does not own.

## Consequences

A running owner can finish isolated work and continue in its original checkout while the conversation remains available. Results distinguish permission denial, no target, accepted candidacy, confirmed deletion and uncertain removal rather than reporting every archive request as successful file removal. Retained candidates can occupy disk indefinitely when their safety blockers persist; this is intentional data preservation, not a strict storage-cap guarantee.

Explicit archive may leave idle Sessions migrated even when physical removal fails, because committed Workspace changes are not an atomic transaction with Git deletion. Automatic maintenance retains its post-delete migration order and does not promote old conversations in navigation. A durable `deleting` record may require safe reconciliation after an uncertain failure; historical reads stay available, but executing against a replaced or unverified directory does not. Non-NotFound Session read failures retain the recovery fence and registry; early registry failures report unknown unless the retained directory and active authority are verified. Creation skips retained catalog locations instead of reactivating a tombstoned identity. Namespace census adds a complete indexed catalog walk to missing registration and retirement; it does not cover dormant logical references in a separate Storage namespace.

Behavioral evidence lives in the [Workbench tool tests](../../../../packages/workbench/test/project/worktree-archive.test.ts), [native archive tests](../../../../packages/local-runtime/test/workspace/worktree-archive.test.ts), [catalog retirement tests](../../../../packages/harness/test/workspace/catalog-retirement.test.ts), [Session retirement tests](../../../../packages/harness/test/workspace/session-retirement.test.ts) and [full Runtime model-loop regression](../../../../packages/presets/test/tool/worktree-archive-model-loop.test.ts). They exercise caller continuation, permission and cancellation, canonical references, retained blockers, below-cap retries and admission fencing. The model-loop fixture uses a deterministic local HTTP provider and the existing in-process SDK stream seam; it does not prove independent worker, paid-model, UI, cross-platform or snapshot-restoration behavior.
