# Runtime 实例与无 Workspace 会话验证

本文记录 B 单元的行为验收与性能实验。设计归属见 [Runtime 与 Scope](../architecture/runtime-and-scope.md)，取舍见 [实施决策](../decisions/implemented/architecture/2026-09-21-runtime-instance-and-workspace-ownership.md)。性能数据用于比较同一机器、同一负载下的改造前后差异，不代表所有部署环境。

## 行为验收

测试通过真实临时 Home、SQLite、HTTP 和子进程观察业务结果。模型服务由本地确定性 HTTP fixture 提供，生产 Agent worker、会话循环、工具调用、存储和关闭流程正常运行；没有调用付费模型服务，也不以模型回答质量作为架构验收依据。

本地还执行了 core/full 编译二进制的完成、工具、文件、预算、超时、权限与导入导出验收，以及独立 Electron profile 和托管后端的启动测试。实际 Desktop 在 Home 创建无 Workspace 会话，使用本地 HTTP 模型 fixture 完成任务；页面显示结果，刷新后恢复历史，renderer 未产生页面错误，退出状态为零。原生 Browser 的启动、协议与 renderer 崩溃恢复测试另行通过。

Product Runtime 最终全量分片运行通过 1,490 项测试。其余包运行全量测试；发现问题后重跑受影响的拥有者。测试数量只用于说明执行范围，完成判定以上表中的可观察行为为准。跨平台结果以对应 PR 当前提交的 CI 为准。

首轮跨平台 CI 另外暴露了编译摘要启用时的导入期 Home 访问、Linux sandbox 状态测试与长流 opt-in 测试缺少 Runtime fixture，以及 benchmark 准备入口依赖进程全局工具缓存的问题。修复将摘要保持为静态产物身份，将工具查找与缓存归属到 Host，并让这些入口显式创建上下文。新增回归验证无 Runtime 导入、helper 内容篡改拒绝、两个实例各自的工具路径与 Home/PATH 准备分支；已有三十 MiB 长流取消场景验证完整数据、摘要、计量和归档。Plugin Kit 的纯网络与问候模板也显式声明无需 Workspace，并通过实际打包、宿主加载与浏览器调用验收。

修复后的本地 Docker 验收通过全部六项测试：core、full、core-library 的八次任务覆盖同容器与独立 verifier 环境，全部正常完成、奖励为 1，证据有效；重复恢复不新增 attempt。随后长输出、断流、超时、主动取消和容器强制退出场景分别验证规定的终态、证据完整性与清理，不把故障导致的不完整证据当成成功结果。该次运行耗时约十四分钟。当前源码的 Home／项目真实 worker 会话以及多实例 HTTP/WebSocket 与关闭回收另行复测通过。

附加验证覆盖父进程退出、OOM 和恢复时的文件所有权交接。ARM 主机上的 amd64 交接曾因未指定平台而选错镜像架构；交接容器改用冻结实验计划的平台后，四个实际 Docker 恢复场景通过，包括运行中与已停止容器，且保留原始文件内容、权限与验证结果。

## 性能方法

基线为 `7a5f1f606`，实现包含 `8b2528b7f` 以及本次资源关闭修复。两者使用同一 macOS arm64 主机、Bun 1.3.14、同一 HTTP fixture、独立 Home 和端口。每种条件运行五次，交替先运行基线与实现，使用中位数比较。分别测量 Product HTTP Runtime 的 `oneshot` 与常驻 `server` 模式；关闭外部模型目录刷新、默认 MCP、文件 watcher、Holos、Marketplace 预取和 Library 自主任务，并设置一个 Agent worker、空闲预热数量零。测量期间不并发运行本任务的构建或测试。

新安装条件使用空 Home；历史条件复制同一份 SQLite 种子，其中包含通过 Session API 创建的 1,000 条真实消息及文本 Part。另外加入 1,000 万条 SQL 合成行，令 `kind`、Scope 和 Session 索引列形成 157 个合成 rollout owner，以施加大表 owner 聚合负载。这些合成行不构成 1,000 万条有效业务轨迹，因此该实验不能证明全量轨迹迁移、逐条恢复或生产数据修复的性能。

启动时间包含模块导入至 Runtime 和 HTTP transport 就绪；首次任务包含真实 worker 启动、流式 HTTP 响应和会话持久化；历史分页读取 50 条消息并验证总数仍为 1,000；owner 查询直接调用 Storage 的 `evidenceOwners()`。内存以每 100 ms 采样整个子进程树的 RSS 峰值比较；关闭计时等待 Runtime.close 完成。RSS 包含分配器保留页，不能直接用来判定对象仍被引用。

| 新安装首次任务          |  1,162.47 |  1,198.94 |  +3.14% |
| 新安装关闭              |  5,034.50 |  5,046.27 |  +0.23% |
| 新安装进程树 RSS 峰值   |  1,180.96 |  1,211.38 |  +2.58% |
| 历史数据启动            |    642.51 |    666.82 |  +3.78% |
| 历史数据首次任务        |  1,341.08 |  1,366.13 |  +1.87% |
| 历史分页                |     62.32 |     62.48 |  +0.26% |

## 常驻服务结果

`server` 模式同时运行完整产品的常驻服务与 Policy worker 预热，使用相同条件和五次中位数。首个任务后仍保留服务，测量历史查询后再关闭。

| 条件与指标                    |      基线 |      实现 |    变化 |
| ----------------------------- | --------: | --------: | ------: |
| 新安装启动（ms）              |    956.70 |    949.99 |  −0.70% |
| 新安装首次任务（ms）          |  1,040.15 |  1,056.54 |  +1.58% |
| 新安装关闭（ms）              |  5,036.58 |  5,043.48 |  +0.14% |
| 新安装进程树 RSS 峰值（MB）   |  1,378.76 |  1,410.92 |  +2.33% |
| 历史数据启动（ms）            |    810.80 |    710.38 | −12.39% |
| 历史数据首次任务（ms）        |  1,178.86 |  1,210.10 |  +2.65% |
| 历史分页（ms）                |     59.42 |     65.30 |  +9.90% |
| 大表 owner 聚合（ms）         | 19,374.61 | 19,343.58 |  −0.16% |
| 历史数据关闭（ms）            |     23.94 |     32.87 | +37.29% |
| 历史数据进程树 RSS 峰值（MB） |  1,481.98 |  1,521.11 |  +2.64% |

关闭增加 8.93 ms，其余测量项的中位数退化均低于 15%。样本量与宿主配置限定了结论；未测量真实远程模型延迟，也没有以单机采样宣称生产部署的绝对性能保证。

补齐嵌套 Scope/观测上下文的关闭后，针对最终实现再次进行每种模式五对历史数据测量，任务和分页后立即关闭，省略大表 owner 聚合的约十九秒间隔。单次任务宿主关闭为 28.81 → 34.62 ms（+5.81 ms，+20.16%），常驻服务为 32.52 → 38.07 ms（+5.56 ms，+17.08%）；对应启动变化分别为 +0.85% / −10.91%，首次任务为 +1.75% / +2.91%。这组关闭时机不同，独立报告，不混入前两表的中位数。

## 重复打开与关闭

八轮同进程完整 HTTP Runtime 循环均执行真实 worker 任务后关闭，复用隔离 Home 和端口。关闭后八个 Runtime 上下文全部可回收，进程监听器数量保持不变；第二至第八轮 JavaScript heapTotal 约为 149.6 MB，没有逐轮增长。进程 RSS 约为 700–711 MB；该数值包含 native 分配器和共享模块，不能解释为每次关闭都向操作系统归还全部内存。

该实验曾稳定发现 Library checkpoint 定时器未释放及 Bun 停止 HTTP 服务后保留 handler 创建上下文的问题。修复分别位于连接拥有者与 transport 关闭处；HTTP 的最终 handler 替换发生在请求排空后，且脱离 Runtime、Scope 和观测上下文。对应测试验证两个数据库互不影响，以及在嵌套 Scope/观测上下文内部关闭的连续三个 HTTP Runtime 配置与拥有者均可回收，避免以清空全局状态掩盖生命周期问题。
