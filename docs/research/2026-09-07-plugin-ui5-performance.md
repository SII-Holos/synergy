# UI API 5 前端性能验收

## 问题与范围

本记录验证默认界面抽取为公共契约消费者后，是否增加持续性的首屏、会话切换和消息呈现开销。基线为 `81d568a8b4a0378d8b52cb4f4c8eee2ac17baab3`，比较对象为 UI API 5 的生产 App 构建。测量日期为 2026-09-07；环境为 macOS arm64、Bun 1.3.14、Chromium 149.0.7827.55，同机顺序执行，每个版本三个独立浏览器 Context，各自启动隔离宿主。这组对照完成于后续 `dev` 的 Solid 1.9.15 生命周期修复合入之前，用于评估公共接口抽取；后续独立改动的效果不计入下表。

## 方法与结果

[基准脚本](../../test/plugin-ui5/benchmark.ts)为两个版本分别通过各自 Plugin Kit 构建相同的导航插件，经正常授权加载。每个宿主导入两个各含 160 轮的合成会话；会话、消息和分部使用独立身份。每次试验测量首屏到原生编辑器可用、一次未缓存会话切换、三次已缓存切换、60 次追加文本的消息分部更新，以及首次打开插件页面。页面可用后等待两个动画帧，避免只测路由字符串变更。

| 指标（中位数）                   |            基线 |        UI API 5 |
| -------------------------------- | --------------: | --------------: |
| 首屏可用                         |       516.54 ms |       507.79 ms |
| 首屏 JS/CSS 传输正文             | 1,053,112 bytes | 1,081,145 bytes |
| 首屏 JS/CSS 文件数               |              17 |              20 |
| 未缓存会话切换                   |       191.55 ms |       183.06 ms |
| 已缓存会话切换                   |        58.08 ms |        58.81 ms |
| 60 次文本追加至最终呈现          |       155.96 ms |       139.98 ms |
| 首次打开插件页面                 |        48.15 ms |        24.39 ms |
| 160 轮会话的已挂载消息根节点     |              20 |              20 |
| 文本追加期间浏览器发起的会话 GET |               0 |               0 |
| 同一插件 UI JS 请求数            |               3 |               1 |

首屏新增 28,033 bytes（约 2.66%）和三个轻量文件；[生产构建检查](../../packages/app/test/app-build-css-contract.test.ts)独立验证重型可选资源保持按需加载。已缓存切换的中位数相差 0.73 ms，在这组帧粒度测量中没有观察到持续性回退。插件模块请求由三次减少为一次；新加载器使用同一 URL 的完整性预加载和模块缓存，不按组件重复抓取 bundle。

## 解释与限制

这组试验是可复现的本地回归证据，不能代表所有机器、网络和真实模型工作负载。首个试验包含服务冷启动和文件缓存差异，因此保留三个试验并报告中位数，不将单次冷启动差异解释为稳定提速。追加测试通过公开分部更新接口进入现有事件连接，验证的是同步和呈现路径，并非模型 token 生成速度。历史分页、恢复、输入提交及 Shell 切换另由行为测试覆盖；它们不能由本表替代。

[当前架构](../architecture/frontend-plugin-platform.md)和[实施决策](../decisions/implemented/architecture/2026-09-07-plugin-ui-api-5-domain-owned-presentation.md)定义长期约束，本记录保留此次测量方法与结果。原始输出仅含环境和数值，运行时地址、临时 home 和会话身份不进入维护文档。
