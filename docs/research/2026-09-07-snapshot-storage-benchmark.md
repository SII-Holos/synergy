# 文件快照共享存储基准

本报告记录 macOS、Bun 1.3.14、Apple Git 2.50.1 上的一次隔离目录实验。运行 `bun script/benchmark-snapshots.ts --sessions 10 --files 200 --rounds 3`，两个后端均使用本次实现的捕获与租约流程；因此耗时不能解释为新旧二进制对比。旧后端预建独立仓库，新后端首次捕获包含共享仓库初始化和持久化配置。

## 数据与结果

每个会话先捕获相同的 200 个文本文件，随后三轮仅修改一个文件，每轮并发捕获十个会话。恢复阶段逐字节验证最初文件内容。对象占用不包含索引和其他仓库元数据；三项可以相加。

| 指标               | 会话独立仓库 | Scope 共享仓库 |
| ------------------ | -----------: | -------------: |
| 相同基线对象数     |        2,010 |            201 |
| 三轮修改后对象数   |        2,070 |            207 |
| 最终对象逻辑字节   |      281,950 |         28,195 |
| 最终对象分配字节   |    8,642,560 |        864,256 |
| 索引逻辑字节       |      160,649 |        160,649 |
| 索引分配字节       |      163,840 |        163,840 |
| 其他元数据逻辑字节 |      263,623 |         28,595 |
| 其他元数据分配字节 |      864,256 |        294,912 |
| 首次捕获耗时       |       149 ms |       1,254 ms |
| 十次初始捕获 P95   |       180 ms |       1,254 ms |
| 后续并发捕获 P95   |       292 ms |         365 ms |
| 单文件恢复耗时     |       123 ms |          28 ms |

此夹具的对象存储随独立会话重复十份，共享方案只保存一份；每轮修改新增两个对象，在共享库也只增加一次。索引仍随会话数量增长，这是隔离可变状态的必要成本。共享初始化与持久引用增加写入开销，这次实验的热捕获 P95 也高于独立后端，不能宣传为全面性能加速。

## 适用范围

结果仅证明完整文件去重和历史可读性，不代表真实全库节省比例、全库迁移耗时、跨平台延迟或断电耐久性。样本较小，恢复时间受调度和文件缓存影响；应在目标文件规模和硬件上重复运行。同一工具始终使用独立临时 home，不迁移或清理正在运行的实例。

设计来源与取舍见[共享文件快照存储决策](../decisions/implemented/architecture/2026-09-07-shared-file-snapshot-storage.md)。
