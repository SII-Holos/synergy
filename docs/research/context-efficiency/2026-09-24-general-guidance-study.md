# 通用等待提示与工具说明去重：两题最终结果

本轮 CompCert、Mailman 各执行一次，均获得原生 reward 1，真实功能测试均为 3/3。两题合计 45 次请求、1,626,731 input + output token；相比[上一轮等待候选](2026-09-24-process-waiting-study.md)的 92 次请求和 4,284,248 token，总 token 减少 62.03%。两项并行批次从启动到退出共 32.400 分钟，CompCert 解题从 57.272 降至 29.216 分钟，Mailman 从 11.789 降至 8.813 分钟。

相较历史基线，两题总 token 少 54.04%，但未缓存输入为 724,873，对比基线 730,579 仅少 0.78%。因此，本轮支持保留这两个任务上的定向改动，不能把总 token 降幅写成金额节省，也不能据此宣称整个 local-24 已改善。两个任务、单次采样，以及共同变化的等待提示和工具说明不能分离各自的因果贡献。

[完整最终 JSON](2026-09-24-general-guidance-study.json) 与[十行 CSV](2026-09-24-general-guidance-study.csv) 保留六项历史已评分观察、两项历史模型前启动失败和本次两项结果。JSON 另包含本次全部 45 次请求和 36 次工具调用的脱敏指标、真实测试、阶段时间、人工审查、归档与费用。全部十行均为终态；历史记录逐项原样复制，原始证据没有改写。两项旧启动失败继续保留缺失评分和零模型请求。前次完整逐请求、逐工具数据仍在上一轮 JSON 中，不以新的快照代替。

CompCert 仍有普通解题修复：第一次 configure 缺少 Menhir，安装后通过；第一次构建成功，但功能检查找不到配置前缀下的 runtime library，随后调整前缀、第二次构建并安装，最终编译运行验证通过。两次构建的命令字符串不同，因此“逐字重复为零”不意味着没有重复构建。它也仍把安装与构建日志重定向到文件；本轮成功不能证明所有静默任务都能及时诊断。

Mailman 的 19 次工具调用全部是 Bash。它在命令选项位置、创建列表的方法签名、owner roster、subscription utility、settings 属性和 enum 类型上经历错误与修复，随后提供的迭代验证和原生三项测试均通过。它在上一轮也没有 process 调用，故本轮用量下降不能解释为“减少 process 轮询”。少了哪些实际工作、说明长度变化和单次模型决策共同影响结果。

通用退出状态提示也没有完全消除问题：Mailman 的两次 Python 失败后跟随成功诊断命令，最终 shell exit 为 0；CompCert 一次不支持的诊断参数报错后，后续命令也让 shell exit 为 0。安装和构建命令显式打印主操作状态，但不都将它作为最终退出码。现有日志允许识别这些情况；本轮没有加入运行时猜测或强制改写命令。更短的轨迹不是所有执行错误已经修复的证据。
