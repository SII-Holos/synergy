# 八题双臂契约验证与评测证据：最终结果

在派发前固定的八题双臂诊断中，实施前 `dev` 基线通过 **4/8**，新候选通过 **5/8**：fd 从失败变为通过，其余七题没有原生评分从通过退化为失败。因此候选满足预设的原生评分门槛，但这只是一轮随机样本，不能证明提示词或 Bash 退出状态单独造成 fd 改善，也不能推广为整个 local-24 的质量提升。SuperJSON、SQLFmt 与 KaTeX 虽然两臂均未通过，候选的真实失败断言分别更多。

[完整脱敏 JSON](2026-09-28-quality-contract-diagnostic-study.json) 保留全部 16 项、逐请求用量与时延、阶段队列、资源、证据和人工测试审查；[16 行 CSV](2026-09-28-quality-contract-diagnostic-study.csv) 提供逐项评分、测试、已知用量下界与未知请求数。两份均是运行结束后的最终派生数据。原始证据没有覆盖，首次准备失败也单独保留。

## 证据可信度与交付边界

冻结 evaluator 和任务选择匹配；16 项均有原生 reward，1,489 次请求中 1,485 次完成、4 次中断且用量未知。逐请求条件无偏差；10,130 个证据文件哈希核对无不符。16 个 ZIP 均可读取，其中 15 项有原始归档验证收据且原始证据 `valid=true`；Doom 候选 ZIP 成功导出，却在独立的 300 秒验证期限内超时，原始记录仍为 `valid=false` 且没有原始收据。runner 因失败项/证据问题以状态码 1 退出，但全部 16 项已终态、评分和清理完成。

对 Doom 候选仅作一次不调用模型的**同 ZIP 续验**：原始证据哈希、338,674,092 字节 ZIP 的哈希/大小和冻结验证器身份均核对一致；派生收据给出 `valid=true`、68,437 个文件、1,425 个 artifact、135 次调用，模型请求 0，独立恢复容器也已清理。该结果只说明保留 ZIP 可验证；录制仍为 `partial`、`integrity.complete=false`，不把原始证据或评分改写成完整录制。[评测器决策记录](../../decisions/implemented/testing/2026-09-28-separate-archive-validation-and-diagnostic-grading.md)定义了这个界限。此前路径追踪的同 ZIP 免费续验也不属于本批 16 个付费 cell；原 reward 1 保留，录制同样是 partial。

本批满足**预先约定的原生评分门槛**，但 15/16 项原始归档证据有效、1 项仅有独立续验，且多项双方未通过题的候选实际断言更差。提示与 Bash 模型可见退出状态同时变化，模型采样每臂仅一次，队列及资源条件不同；因此这些结果支持继续审查该候选，不构成单项机制的因果证明，也不支持宣称全量 local-24 或 token 效率提升。[旧批次失效原因](2026-09-24-local24-candidate-study.md)与这轮统一 evaluator 的诊断结果不能混为一批。
