# 编码工具输出优化：实现与小样本验证

日期：2026-09-21。研究对象是 Synergy 的 API harness。本文记录固定输入的工具测量、真实模型的小任务对照，以及未通过效率验证而撤回的改动。它不构成完整 benchmark 成绩或 GLM Coding Plan 积分收益证明。

## 结论

文件读取、检索和编辑反馈的实现已完成，并有确定性的输出体积收益。最终候选在长文件修改和搜索定位两题上分别减少总 token 44.3% 和 22.5%，同时缩短耗时。但委派审阅题总 token 增加 122.1%，耗时增加 105.6%。三题合计总 token 增加 2.8%，耗时增加 14.5%。因此，本轮只能确认局部工具优化有效，尚未证明整体任务成本下降。

初版还移除了 synergy-max 系统提示中的重复专长目录。组合方案在委派题的两次对照中均退化，因此最终实现恢复原目录。恢复后该题仍然更慢，说明不能把退化归因于目录去重，也不能声称恢复目录解决了全部问题。保留原目录是控制未经验证的行为变化；进一步目录优化需要独立实验。

## 实现范围与取舍

| 范围                    | 最终行为                                                        | 验证重点                                           |
| ----------------------- | --------------------------------------------------------------- | -------------------------------------------------- |
| read 普通文本与文档分支 | 尊重显式小 limit；默认仍为 2000 行；完整 UTF-8 行受输出预算约束 | 不再强制扩到 120 行；零行、超长行、精确续读        |
| view_file               | 多区间共享 50 KiB 代码正文预算及行预算，重复行只显示一次        | 不给半行创建编辑证据；隐藏行不能直接编辑           |
| scan_files              | 增加可选 context，匹配或整文件模式共享预算                      | 已显示完整区域可以直接 anchored edit，无须机械补读 |
| parse_code              | 返回完整多行 AST 匹配和所需上下文                               | 不再只显示匹配首行；超大 context 使用有界迭代      |
| grep、file_search       | 限制展示体积；搜索路径、内容和符号轮流获得展示位置              | 路径候选不再耗尽内容／符号的全部名额               |
| revise_file             | 新 tag、实际增删计数、紧凑修改预览、诊断；完整 UI diff 保留     | 连续编辑、格式化漂移、跨 hunk 行号和部分失败       |
| 已见行追踪              | 已知且未变的行、模型提交且格式化后未变的行可延续                | 未显示的旧内容不会因为新 tag 自动成为已见内容      |
| 恢复提示                | 精确续读或有界 shell 检查；截断不强制委派                       | 超快照上限文件不再承诺缩小范围即可获得 tag         |
| 本地处理                | 获取 tag 时不再先构造完整显示块；二进制探测只读前 4096 字节     | 避免无必要格式化与全文件二次读取                   |
| 专长目录                | 最终恢复原系统目录和 task 目录                                  | 去重版本保存于实验提交，未作为最终默认行为         |

120 行机制原本用于减少模型读不全导致的重复调用。本次只取消显式小请求的扩大，没有把默认窗口机械地缩小。文件内容的 50 KiB 预算与路径标题、恢复说明、诊断等控制信息分开；完整工具字符串可能略大于 50 KiB。

不涉及历史消息改写、reasoning 裁剪、供应商思考连续性、缓存内部机制、默认模型预算或新增压缩模型。也没有引入完整 Aider 仓库地图；本轮只借鉴预算化选择，修复现有搜索入口中有明确证据的问题。实现来源和取舍见对应决策记录。

## 固定输入的工具测量

相同的 1200 行文本文件、相同的读取区间和单行替换；通过实际 Tool.execute 包装测量返回字符串的 UTF-8 字节。表中不是 tokenizer 估计，也不是任务可节省额度。

| 操作                      | 基线字节 | 最终工具字节 |  减少 |
| ------------------------- | -------: | -----------: | ----: |
| read，明确请求 2 行       |    11605 |          257 | 97.8% |
| view_file，明确请求 2 行  |    11057 |          244 | 97.8% |
| revise_file，修改 1 行    |    51500 |          424 | 99.2% |
| view_file，3 个不相交区间 |   110608 |        51342 | 53.6% |
| scan_files，整文件显示    |   110531 |        51394 | 53.5% |

两版的单行修改均通过实际文件内容检查。后两项会省略超预算内容并提供恢复入口；不能把省略的全部字节认定为无用信息。小文件、跨区域依赖和补读成本仍需任务级验证。

可复用探针位于 `packages/runtime-local/test/tools/coding-observation-probe.test.ts`。从 runtime-local 包运行该测试，把 `SYNERGY_OBSERVATION_REPORT` 设为新的绝对 JSON 路径即可输出版本化结果；既有报告不会被覆盖。探针不调用模型，复测时应固定探针和被测源码的身份。

## 真实模型对照设置

固定官方 `deepseek-flash`，显式 `thinking.type=disabled`。主代理为 synergy-max；title、summary、审阅子代理也使用同一模型设置。所有请求经过只负责转发和记录的本地代理，实际执行使用产品 CLI；没有另写代理循环。

源代码从提交归档冻结：基线 `60dd12d6209b6b2f5b7bff726379cd48990aeef0`，目录去重组合版 `593885494ad6cddd88f7620787a883dfbb807753`，最终工具版 `031a937fff3e71ea09be4128b5aae6918423281d`。归档下所有已有 tracked 文件逐字节与相应 git archive 核对，无差异。测量脚本和新增探针单独记录身份。依赖复用安装环境，源码 workspace 链接映射到各自归档，未重新解析依赖版本。

每个任务使用独立临时 Git 仓库和独立 SYNERGY_HOME，模型时限 600 秒，最终有效组严格串行。保留沙箱，关闭 LSP、formatter、默认插件、内置 MCP、watcher、Library memory/experience 等可选服务；这是一组本地编码 fixture 评测，不等于完整生产配置或 local-24。

三个任务为：① 1300 个 marker 导出之外，修复数量计算和单复数标签；② 在 45 个误导性文件名中找到费用实现，修复阈值与非法输入；③ 修复姓名规范化与首字母函数，执行恰好一次专长审阅并整合发现。任务 3 明确审阅同一工作目录的未提交修改。

固定功能校验之外，额外复核全部 1300 个 marker、45 个无关文件、负值／非整数／非有限值、空白输入，以及审阅次数。结果全部通过。额外复核不修改历史评分，也不替代更广泛的 benchmark。

## 最终工具版与基线逐题结果

Token 来自供应商完整终态 usage：总 token 为输入加输出，输入包含缓存命中 token。所有辅助和子代理调用均计入；不把标题／摘要视为免费工作。墙钟从启动产品 CLI 到进程结束及本地校验，包含启动与工具执行。

| 任务         | API 调用 基线→最终 | 输入 token 基线→最终 | 输出 token 基线→最终 | 总 token 变化 | 耗时秒 基线→最终 |
| ------------ | ------------------ | -------------------- | -------------------- | ------------- | ---------------- |
| 长文件修改   | 17→11              | 653469→363171        | 3533→2786            | -44.3%        | 28.237→18.841    |
| 搜索定位     | 12→10              | 344794→267233        | 2323→1687            | -22.5%        | 19.071→14.740    |
| 一次专长审阅 | 14→27              | 330060→732261        | 2848→7077            | +122.1%       | 22.636→46.539    |
| 三题合计     | 43→48              | 1328323→1362665      | 8704→11550           | +2.8%         | 69.944→80.120    |

长文件主代理调用 14→8，搜索题 9→7；每题都还有 title 和 summary 调用。最终审阅题为主代理 16、maintainability-reviewer 6、title 3、summary 2 次调用，合计 27 次。对照基线为 8、2、3、1，合计 14 次。把主代理调用数当作全部开销会漏记相当部分成本。

主代理直接工具反馈字节三题合计 55922→49813，减少约 10.9%，但这并没有阻止总 token 上升：更多往返会重复携带已有上下文，并增加输出。该指标只计算每个结果首次返回的字节，不等于请求中的累计历史暴露量。

## 退化轨迹与回退依据

目录去重组合版三题合计 57 次请求、1476863 输入和 14860 输出 token、98.344 秒；相对基线没有达到整体目标。审阅题首次为 34 次请求、59.973 秒，基线为 14 次、22.636 秒。额外一组同条件复跑为组合版 26 次、37.111 秒，基线 14 次、26.290 秒。两次负面样本均保留，没有挑选较优运行替换初次结果。

组合版的长审阅轨迹包括错误测试导入路径、严格索引类型检查失败、Unicode 修改与类型检查之间反复切换，以及审阅前后重复读取。复跑中又出现审阅与主修改并发、审阅边界过宽的问题。它们是实测执行行为，尚不能由单一提示变更建立因果关系。

最终工具版恢复原目录后，审阅仍涉及 Unicode 反例复现和修复。事后诊断发现，两次基线和两次组合版都未正确处理非 BMP 首字符；最终工具版对 Deseret 字母和 emoji 两个诊断例通过。这个检查是在阅读审阅发现后新增的，属于事后诊断，不能追溯改变预先定义的通过分数，也不能把更多耗时全部认定为冗余。质量提升与额外成本需要一起看。

因此不继续靠微调提示追逐单题好成绩。文件工具的行为修复保留，目录去重暂缓；下一步应预先固定审阅验收范围和多次重复设计，区分必要审查、无效反复与随机差异。

## 排除的实验与全部开销

本轮共有 19 次有模型调用的运行、353 个 API 请求。供应商已知输入合计 11932615、输出 79816，总计 12012431 token；全部终态 usage 已取得。数字包含失败配置、环境诊断、重复对照和最终候选，不能只报最终六次的实验成本。

| 分组                       | 运行数 | 处理                                                           |
| -------------------------- | -----: | -------------------------------------------------------------- |
| 初始配置探测               |      2 | 全局 allow 让 classic read/write 进入 max 工具集，排除配对比较 |
| 受保护路径下的基线与组合版 |      6 | Node/Bun 受沙箱祖先路径规则影响，排除正常环境效率比较          |
| 修正目录后的基线与组合版   |      6 | 原始小样本对照，保留全部结果                                   |
| 审阅题复跑                 |      2 | 验证退化是否重复，独立保存                                     |
| 最终工具版                 |      3 | 恢复目录后的候选验证，与同任务基线比较                         |

受保护路径组还存在约 1.4 秒的两个运行重叠；该组已整体排除，未混入最终串行耗时。环境修正对两版一致生效，没有通过关闭安全边界来获得更好成绩。

每个运行的 wire 调用数量、输入／输出／缓存 usage 多重集与原生 call records 相符；原生汇总也与 wire 总量一致。原生 run 的 recording 状态仍为 partial，不能称整个 rollout 已完整归档。用量记录完整与完整执行记录是两个不同结论。归档嵌套目录的自动 Git provenance 会看到外层 checkout，源码身份因此以经过逐文件验证的归档 receipt 为准。

缓存命中只按供应商返回的命中输入量独立记录：基线三题 1188224 / 1328323，最终三题 1208192 / 1362665。没有高峰权重、时间权重或积分换算。当前模型和实验不是 GLM Coding Plan，没有可归因的该套餐额度变化，额度收益未知。

## 验证、限制与后续

完成 391 项不同的定向测试用例，覆盖 read／view／search、hashline、恢复、文档提取接口、紧凑 diff 和提示构造；17 项本地质量门禁全部通过。测试包括 UTF-8 长行、多区间重叠、空已见集合、格式化后失效、多文件中途失败、已写入但后续校验失败和超大 AST context。完整 CI 矩阵不在本地重复运行；本报告不把本地门禁称为远端 CI 全绿。

样本很小、没有完整 local-24、没有统计显著性、没有独立 holdout、没有随机化运行顺序；最终候选还利用了初轮结果作选择。因此只能报告实际轨迹及局部效果，不应将百分比外推到其他模型、仓库、长任务或用户套餐。

当前最确定的下一步抓手是减少审阅任务的无效扩张和反复，先建立包含 Unicode／类型检查等明确质量条件的配对任务，再研究可观测的调度与反馈改动。历史裁剪、完整仓库地图、命令语义压缩和更大架构变化仍需独立设计，不能借本轮局部输出收益宣称已经验证。
