# CompCert 与 Mailman 等待提示实验：最终结果

本报告记录 2026-09-24 已完成的两项新候选执行。两题均获得原生 reward 1，真实功能测试均为 3/3。相较旧候选，两题合计请求数从 460 降至 92，输入加输出 token 从 34,001,863 降至 4,284,248，减少 87.40%。相较历史基线的 3,539,569 token，新候选仍多用 21.04%。这支持保留本次等待提示的定向观察，但不能证明整个 local-24 的性能或费用改善，也不能把全部降幅归因于提示。

CompCert 的请求数下降，同时解题耗时从 48.478 分钟增至 57.272 分钟；Mailman 从 62.399 分钟降至 11.789 分钟。两项并行批次从启动到退出共 59.360 分钟。这是两项的周转时间，不是 48 项全量实验的一小时验证。

[完整最终 JSON](2026-09-24-process-waiting-study.json) 保存八项来源明确的观察、全部 92 次新请求的用量与时间、83 次原生工具调用的脱敏指标、测试、阶段时间、审计和费用汇总。[八行 CSV](2026-09-24-process-waiting-study.csv) 包含四项历史参考、两项首次启动失败和两项完成的新候选。文件中没有运行中的样本；未执行的评分和未知用量保持缺失。历史完整研究保留在[原报告](2026-09-23-local24-glm-fault-repair-study.md)，本报告不替换其 24 对结果。

## 等待行为与实际工作

| 新候选轨迹指标                  |               CompCert | Mailman |
| ------------------------------- | ---------------------: | ------: |
| 原生工具调用                    |                     49 |      34 |
| Bash                            |                     35 |      34 |
| 阻塞 process poll               |                     11 |       0 |
| 非阻塞 process poll / log       |                  0 / 0 |   0 / 0 |
| process write / kill            |                  2 / 1 |   0 / 0 |
| Agenda 调用                     |                      0 |       0 |
| 阻塞窗口                        | 9 × 300 秒、2 × 120 秒 |      无 |
| 实际阻塞等待合计                |           2,533.298 秒 |    0 秒 |

| 完整 Bash 命令逐字重跑          |                      0 |       0 |
| Bash 非零 exit 记录             |                      8 |      13 |

这些是本次轨迹中的观察数，不是从历史请求总数反推的轮询数量。历史 process 次数没有原始证据可重新核验，保持缺失。完整命令字符串不同也可能是在重跑同一构建；shell 末尾的成功命令还可能掩盖中途失败，所以最后两行不能代替语义审查。

CompCert 实际采用了阻塞等待，但最初安装命令没有设置非交互式包管理选项，并把安装输出重定向到文件。它连续等待四个 300 秒窗口后才查看日志，发现 tzdata 正在询问地理区域。输入之后又遇到时区选择。该命令从发起到模型终止共 1,965.826 秒，即 32.764 分钟；其中阻塞查询占 1,742.047 秒。之后的非交互修复命令包含广泛的进程匹配，输出为空、无退出码，不能声称这次修复已成功。

模型随后完成了 Coq 工具链和 CompCert，但仍经历了错误的 opam switch 名称、依赖检查失败、遗漏 `make depend` 和遗漏 runtime library 构建。它进行了三次语义上的 `make … ccomp` 尝试、重新解压源文件以及两次安装尝试；这是同一解题过程中的诊断恢复，不是 evaluator 补跑。最终构建后的阻塞等待约 186 秒就因进程退出而返回，证明 300 秒窗口不会强制睡满。本次未出现非阻塞 process 轮询，请求数也较旧候选下降；但历史轨迹缺失，无法量化轮询减少对降幅的贡献。阻塞等待还可能长时间停在一个需要输入的命令上。

Mailman 没有调用 process。其 34 次 Bash 调用围绕配置、API 用法、目录权限、缺失 alias map 和收发邮件验证展开。模型的自定义断言一度把 Mailman 加前缀的已送达主题当作未送达，随后核对邮箱内容并完成验证。17 个 CompCert、10 个 Mailman 的 shell 状态/日志关键词命中主要包含检查与故障诊断，不能直接计作冗余轮询。两题的当前原生测试全部通过，节省并非来自提前放弃任务；但 Mailman 的成本变化也不能单独归因于 process 提示。

## 请求等待、资源与记录完整性

| 新候选   | 所有请求区间并集秒 | 首数据之前的区间并集秒 | 首数据延迟中位数 / p95 秒 | 内存观测峰值 |
| -------- | -----------------: | ---------------------: | ------------------------: | -----------: |
| CompCert |            512.022 |                265.842 |            4.501 / 10.336 |    4.000 GiB |
| Mailman  |            444.805 |                187.930 |             4.455 / 7.775 |    1.957 GiB |

请求区间包括流式生成，不能整体称为等待首字节；首数据可能是推理数据，也不等同于可见答案首 token。并行区间按并集计算，不将嵌套跨度或重复采样相加。资源按每秒采样，峰值可能漏掉瞬时尖峰；CompCert 达到 4 GiB 观测值不代表已发生 OOM，所属容器事件流没有记录 OOM。

最终审计核对新执行的 650 份文件和 sidecar 哈希，全部一致；冻结 evaluator 身份匹配，两项都只有一次派发，实际顺序为 CompCert、Mailman，两题 agent 执行重叠。92 次 provider 请求均完成，模型参数和工具目录一致，与原生请求身份、正文和已知 input/output/cache/reasoning 用量全部逐请求匹配。新用量为 input 4,262,907、output 21,341、cache read 2,785,152、reasoning 9,572；后两项分别是前两项的子集。

两个归档结构与 CRC 均有效。CompCert 原生 recording 为 complete；Mailman 保留 partial 标记，来自启动和重启邮件服务命令对应的两个 interrupted process-stream artifact，分别保留 397 和 1,543 字节。其工具调用均完成、exit 0，归档未声明缺失文件，39 次请求和主用量仍完整核对。不能因此把所有进程输出也称为完整记录。两项清理均完成，独立按所属 compose project 查询确认没有残留容器、网络或卷。

## 首次启动失败与所有成本

本轮还保留两个评分缺失的正式启动失败：共享 Docker 配置不是有效 JSON，Docker 的警告被 Pier 合并进 `id -u` 输出，严格的数字 UID 校验在模型启动前拒绝。两个实际题目镜像上的四次免费对照显示，继承配置会产生警告，任务独立的有效配置返回纯数字。共享配置未修改。用户明确授权后才创建本次新运行；原失败记录没有覆盖，也未自动重试。更早的 CLI 依赖索引失败发生在正式 run 创建前，亦保留。

## 结论与后续边界

本轮达到“两题质量保持、相较旧候选请求与 token 下降”的观察目标；没有达到“相较基线同样或更低总 token”，也没有让 CompCert 更快。建议保留当前窄范围改动。若后续继续调整，首先应研究非交互式安装和长期无进展时的诊断提示，让等待区分运行、等待输入与失败；这只是基于本次证据的方向，本报告没有实施新行为，也没有新增付费试验。

实施前通过 47 项相关免费测试：process 5、提示时间单位 3、Agenda 39；17 项本地质量检查通过，工具参考已生成。相关测试和正常 pre-push 在隔离的 Bun 1.3.14 下通过。正式执行与审计没有修改测量中的源码，没有因报告或文档重新运行题目。PR 保持 Draft，CI 和 merge 不作为本地研究结果交付的等待条件。
