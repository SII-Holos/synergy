# Boa 基线保留补丁的依赖补齐重判

本次重判已经完成：24 个原生测试实际运行，22 通过、2 失败，reward 仍为 0。没有重新调用模型，也没有修改模型补丁或原生测试。完整结果及内容摘要见[JSON](2026-09-23-boa-dependency-regrade.json)。

## 原因与条件

[原 GLM 研究](2026-09-23-local24-glm-paired-study.md)中，Boa 基线在判题准备阶段失败，24 条 CTRF failed 都是缺失结果占位，不能解释为 24 个测试实际失败。进一步检查发现，基线补丁把 `Cargo.lock` 中的 `husky-rs` 从 0.3.2 升为 0.3.3；原生 verifier 禁止联网，而镜像只缓存了旧包。因此，原 DNS 错误与模型修改依赖及离线缓存不匹配有关，不能仅归因为随机网络故障。

这次在一次性原生 verifier 中使用完全相同的保留补丁、测试、镜像配方和资源限制，仍然禁止联网，只增加公开的 `husky-rs-0.3.3.crate` 缓存。包的 SHA-256 与模型保留 lockfile 的 checksum 一致。原记录、原始 0 分和原费用保持不变；这是另有依赖条件的重判结果。
