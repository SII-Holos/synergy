# Complete cloud handoff crossed owner lifetimes

## Executive summary

Real enrolled Native-to-Hosted round trips exposed three integration failures after ordinary background execution completed: a mounted source could not reach its save owner, a public file receipt exposed physical mount identity, and an accepted target callback expired with its short admission plan. A fourth failure compared equivalent native selections by JSON property order. Each failure was reproduced before its owning correction.

## Summary

The complete scenarios execute native background work, independently continue after paused activation, change cloud files through another Runtime, then return either with cloud execution retained or with an explicit private native copy. Primitive and metadata checks had not exercised these owners together.

## Timeline

The first complete run reached an active source mount after native completion. Connecting original source drainage exposed the public checkpoint identity mismatch; fixing its logical projection reached the Service source save gate. The actual target subsequently finished receiving files after its finite entry plan expired. The explicit native return then exposed a property-order mismatch in prepared selection validation. Both complete scenarios passed after these corrections; temporary internal diagnostic interception was removed from the final tests.

## Root cause

Source inspection required a dormant catalog before the original physical owner had an opportunity to save and detach its active view. Public operation results mixed native receipt identity with the logical Workspace reference consumed by the remote adapter. Environment mapping reapplied entry expiry throughout an already accepted private invocation. Stable-sorted prepared metadata was compared with an unnormalized schema object.

## Guardrails

Per-member source drainage precedes portability owner freezing and uses the original mount save/detach owner with exact target, epoch, occupancy and commit checks. The Service invokes that owner only for its original signed pre-freeze source action. Public file results project logical identity from their already bound reference while native operation receipts remain unchanged. Finite plans still gate entry; accepted callbacks retain their original Runtime, Store, signer, connection and lifetime guards. Native selections pass the original strict codec before exact comparison.

The real Main tests cover both round trips and independent Continue. Existing paged mount acceptance retains actual checkpoint and object-loss behavior. Product CLI tests verify the advertised handoff capability through actual enrolled child processes; embedded Runtime composition remains explicit.

## Lessons

Validate integrated owner lifetimes through the product entrypoints. An observer deadline, logical resource identifier and physical operation receipt each serve a distinct purpose; none can substitute for the original execution or storage owner.
