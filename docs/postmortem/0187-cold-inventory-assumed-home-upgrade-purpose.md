# Cold inventory assumed Home upgrade purpose

## Executive summary

A cold Source preparation reached the original Workspace and Environment inventory owners, but those owners accepted only Home-upgrade operations. A valid frozen backup with dormant resources could not resume.

## Summary

The full resource recovery case captured two file versions, closed the source Runtime and reopened the same preparation. Its native witness and original drainage were valid. Workspace inspection rejected it before the full canonical inventory ran.

## Timeline

The real end-to-end recovery case exposed the purpose mismatch. The three inventory owners now consume one Kernel assertion for the actual original capability and exact phase. Focused cases retain original Home-upgrade recovery and reject legacy backup leases, copied capabilities, expired callbacks and Source-preparation release.

## Root cause

Domain inventory helpers duplicated a Home-upgrade-only admission check even though the Kernel also owns Source-preparation and original durable-Reference recovery capabilities.

## Guardrails

The shared assertion reads the private lease identity and current canonical operation. It retains original native witness and phase checks. Domain owners still scan complete canonical state and recheck the operation after inspection. Source-preparation authority remains insufficient for retirement or release.

## Lessons

Recovery purposes may reuse physical inventory without sharing their mutation authority.
