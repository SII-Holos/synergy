# Selected cloud Session history lacked recovery owners

## Executive summary

Organization recovery could restore original resource objects but refused a Session that selected them. Historical validation had no path from the Session contract to the existing Cloud resource owner. A second, independently reproduced refusal discarded a genuine Hosted pause receipt after all its original authority checks had passed. The correction validates the original selected references and admits only the exactly signed, reconstructible pause metadata.

## Summary

The implementation review compared the original backup requirement with current source. An owning resource-only fixture covered dormant Workspaces, idle Environments and saved versions, while native Hosted task fixtures selected no infrastructure. Those accepted subcases did not prove their combination. The missing combination was reproduced with a real enrolled Runtime, public Session creation and resource selection, actual pause, authenticated checkpoints and an independent restoration target.

## Root cause

The resource and Session recovery readers were implemented independently. The Cloud owner could prove complete original resource graphs and actual target objects, but SessionResources.historical rejected every infrastructure reference before using that owner. Separately, the Hosted command-history reader combined accepted-history classification with an allowlist sufficient for task admission. Its final branch omitted valid historical pause receipts even though they create no new task.

A generic H0/H1 hash explanation was also insufficient: Session and resource-contract records are projected current policy. Original journal adoption may install legitimate H1 changes, while native resource data retains its independent immutable comparison and target facets. Each accepted fact needs its actual owning proof; a passing resource-only or model-only subcase does not establish their complete composition.

## Lessons

Add the missing composition through existing owners and public writers before broadening a historical allowlist. Qualify the actual failing predicate and preserve all preceding checks. A valid no-op receipt can be important history; a historical control still cannot supply a task grant or physical completion. Use the original resident service and real completion event for fixture readiness, and keep setup failures separate from semantic recovery failures.
