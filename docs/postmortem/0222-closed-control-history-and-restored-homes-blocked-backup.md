# Closed control history and restored Homes blocked backup

## Executive summary

Recovery accepted only a narrow subset of ordinary control and execution history. A real restored Service could also serve normally but could not complete another backup and recovery. The failure crossed history validation, signing rotation and native Home formats; accepted subcases did not establish the original full backup requirement.

## Summary

Review against the original recovery requirement found that completed Continue, Cancel and confirmed Question records were ordinary retained data, rather than an authorized exclusion. Real Hosted fixtures exercised their public writers and the original whole-cohort restoration. A real enrolled Member then exercised two independent Service recoveries, retaining its original command records while deployments and signing identities rotated.

## Root cause

The historical readers reused task-admission restrictions as a data inventory. They conflated one logical accepted request with its transmission attempts, the latest released generation with its full history, and the current signer with every retained deployment. Native backup entry points separately assumed that every ordinary Home still had the initial fenced marker. A successful first restoration did not test that the resulting ordinary Home remained a valid future backup source. Later continuation and backup readers also assumed the original Root, enrollment registration and current driver belonged to one binding and deployment. A Native Binding described both cancelled Sources and activated Targets, so its endpoint fields alone were insufficient. The retirement marker separately spread the complete restored Source into strict outer fields that do not admit its installation identity; the required nested source still needed those fields. Knowledge history conflated a failed desired update with the validity of its prior activation, then treated a reusable negative deduplication mark as evidence of a complete update. Validation now requires fresh invocation-local proof of the full original pointer-specific selection. Live restoration inspection also briefly changed startup blocking, and workers assumed the initial Home format. A paused input exposed duplicate receipt observations that rewrote an identical command result’s timestamp, making exact H0/H1 history comparison fail. The owning Admission writer now preserves that timestamp while retaining all original validation and closure work.

## Lessons

Map requirements to ordinary user lifecycles before treating a reader refusal as an allowed limitation. Advance through each real failing owner and preserve the distinction between setup failures, format guards and signature evidence. Verify that a recovery result can itself be backed up again. Historical validation must preserve original facts while leaving fresh execution authority to the current owners.
